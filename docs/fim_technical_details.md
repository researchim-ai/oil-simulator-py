# Fully Implicit Method (FIM): техническое описание

Полностью неявный решатель: модель нефть–вода (`src/simulator/manual_assembly_solver.py`) и трёхфазный black-oil (`src/simulator/blackoil_fim.py`, раздел 9).
Неизвестные двухфазной модели: давление \(P\) и водонасыщенность \(S_w\) в каждой ячейке плюс забойное давление каждой скважины.

## 1. Дискретизация

Уравнение сохранения массы фазы \(\alpha \in \{o, w\}\) для ячейки \(i\):

$$
R_{\alpha,i} = \frac{(V_p S_\alpha \rho_\alpha)^{n+1}_i - (V_p S_\alpha \rho_\alpha)^{n}_i}{\Delta t}
+ \sum_{j} T_{ij}\, \lambda_{\alpha,ij}^{up}\, \Delta\Phi_{\alpha,ij} + q_{\alpha,i} = 0,
\qquad
\Delta\Phi_{\alpha,ij} = (P_i - P_j) - \bar\rho_{\alpha,ij}\, g\, (z_i - z_j)
$$

* \(\lambda_\alpha = k_{r\alpha}\rho_\alpha/\mu_\alpha\) — массовая подвижность, берётся по схеме upwind по потенциалу фазы (противоток возможен).
* \(V_p = V_{p,0}\,(1 + c_r (P - P_{ref}))\) — сжимаемость породы (`c_rock` в разделе `fluid`).
* Проводимость грани (TPFA, полуячейки, неравномерная сетка):
  \(T_{ij} = A_{ij} / \left(\frac{d_i}{2k_i} + \frac{d_j}{2k_j}\right)\).
* Сборка идёт по списку граней (L, R, T, Δz), поэтому добавление NNC/разломов и corner-point сводится к расширению этого списка.

Якобиан собирается аналитически в блочном формате BSR 2×2. Корректность проверяется конечными разностями (`tests/test_fim_jacobian.py`, `tests/test_fim_wells.py`, режим отладки уровня 3).

## 2. Скважины

* Перфорации: `perforations: [[i,j,k], ...]` (по умолчанию одна ячейка `i,j,k`).
* Индекс скважины по Писмену для анизотропной ячейки:
  \(WI = \frac{2\pi\sqrt{k_x k_y}\,h}{\ln(r_0/r_w) + s}\),
  \(r_0 = 0.28\frac{\sqrt{\sqrt{k_y/k_x}\,\Delta x^2 + \sqrt{k_x/k_y}\,\Delta y^2}}{(k_y/k_x)^{1/4} + (k_x/k_y)^{1/4}}\);
  `skin`, ручной `well_index` (м³).
* Забойное давление \(p_{bh}\) на глубине верхней перфорации — отдельная неизвестная; давление в стволе у перфорации \(p_{bh} + \rho_{wb} g \Delta z\) (плотность смеси в стволе берётся явно на начало шага).
* Режимы: `rate` (поверхностный дебит; для добывающих `surface_phase` = `liquid` | `oil` | `water`, для нагнетательных — вода) и `bhp`.
* Ограничения: `bhp_min` (добывающие, по умолчанию 1 атм), `bhp_max` (нагнетательные). При нарушении скважина автоматически переходит на BHP-ограничение и возвращается на дебит, когда пласт снова способен его обеспечить. Режим сохраняется между шагами.
* Уравнения скважин исключаются через дополнение Шура \(J - C D^{-1} B\) прямо в операторе FGMRES; вклад каждой перфорации в собственный диагональный блок учитывается и в предобуславливателе.
* `ramp_days` — опциональный плавный выход на режим (по умолчанию выключен).

## 3. Метод Ньютона и критерии сходимости

Критерии — как в Eclipse/OPM:

| Критерий | Формула | Параметр (по умолчанию) |
|---|---|---|
| CNV (локальный) | \(\Delta t \max_i \lvert R_{\alpha,i}\rvert / (\rho_{\alpha,ref} V_{p,i})\) | `newton_tol_cnv` (1e-3) |
| MB (глобальный баланс) | \(\Delta t \lvert\sum_i R_{\alpha,i}\rvert / (\rho_{\alpha,ref} \sum_i V_{p,i})\) | `newton_tol_mb` (1e-7) |
| Дебит скважины | \(\lvert Q - Q^*\rvert / \lvert Q^*\rvert\) | `newton_tol_well_rate` (1e-5) |
| Забойное давление | \(\lvert p_{bh} - p^*\rvert\), Па | `newton_tol_well_bhp` (10) |

Параметры `newton_tol_mass` и `newton_tolerance` устарели и игнорируются.

Поправки ограничиваются по каждой ячейке (Appleyard): \(|\delta S_w| \le\) `newton_ds_max` (0.2),
\(|\delta P| \le \max(\) `newton_dp_max_rel`·P, `newton_dp_max_abs_mpa`\()\), \(|\delta p_{bh}| \le\) `newton_dbhp_max_rel`·\(p_{bh}\).

## 4. Линейный решатель

* FGMRES (`src/solver/fgmres.py`) на GPU, строки масштабируются по диагональным блокам: на |J_ii|, а если
  диагональ вырождена относительно строки блока (уравнение нефти в ячейке без нефти: ∂M_o/∂p = 0,
  ∂M_o/∂Sw ≠ 0) — на максимум строки блока. Деление на ноль давало масштаб 1e300 и NaN в FGMRES, как только в
  таких строках появлялась невязка округления.
* CPR (`src/simulator/cpr_gpu.py`): давление выделяется по квази-IMPES (веса \(w_i = D_{ii}^{-T} e_p\)), решается одним V-циклом Classical AMG; затем блочный Якоби для полной системы (`cpr_smoother_sweeps`).
* Иерархия AMG строится на первой итерации шага и дальше только обновляется (`amg_rebuild`: `step` | `iteration`).
* Допуск — неточный Ньютон: \(\eta = \mathrm{clip}(0.1\cdot \text{CNV}/\text{CNV}_0,\ \) `linear_tol_min`, `linear_tol_max`\()\).
  Допуск задан по норме всей системы, а CNV — максимум по ячейкам: локальная невязка (водоносная ячейка у
  границы регионов в Norne) может не уменьшаться при «решённой» СЛАУ. Если нормированная невязка
  max(CNV/tol_cnv, MB/tol_mb) за итерацию не упала вдвое, допуск следующих СЛАУ шага ужесточается в 100 раз.
* Если фактическая невязка СЛАУ выше `linear_accept_rel_res` (0.1), итерация считается отказом и шаг по времени дробится.

## 5. Шаг по времени

`Simulator.run_step(dt)` продвигает решение ровно на отчётный интервал подшагами:

* рост шага: \(f = \min(\) `dt_increase_factor`, `newton_target_iter`/итерации, `dt_target_dsw`/max ΔSw\()\);
* `dt_control: "opm"` (умолчание для deck Eclipse) — PIDAndIterationCount из OPM Flow: ошибка
  \(e = \sqrt{\sum(\Delta p^2 + \Delta s^2) / \sum(p^2 + s^2)}\), при \(e > 0.1\) шаг \(\cdot 0.1/e\), иначе PID Турека
  (\(k_P = 0.075, k_I = 0.175, k_D = 0.01\)); минимум с оценкой по итерациям (цель 8, рост 3.2, спад 1.0);
  рост ≤ 3×, после дробления ≤ 2×, дробление ×0.33;
* при несходимости — деление на `dt_reduction_factor`, не ниже `min_time_step_days`, не более `max_time_step_attempts` дроблений подряд;
* `max_time_step_days`, `initial_time_step_days`; подобранный шаг переносится на следующий интервал.

## 8. Ограничения

* Гистерезис ОФП — только Карлсон (EHYSTR модель 0, KR); гистерезис Pc и ENDSCALE DIRECT не поддерживаются.
* Жирный газ без VAPPARS VAP2, DRVDT.
* VFPINJ и THP нагнетательных, трассеры (TRACER, WTRACER), WECON, поверхностная сеть, многосегментные
  скважины — не поддерживаются.
* В простом JSON-режиме FIM дебиты только поверхностные (`rate_type: "reservoir"` не поддерживается); в deck
  исторический RESV поддержан.

## 9. Трёхфазный black-oil (`src/simulator/blackoil_fim.py`)

Включается `simulation.fim_model: "blackoil"` или автоматически (`"auto"`): PVT-таблица, начальная `s_g > 0`, газовые скважины.

**Компоненты и уравнения** (кг/с, \(b = 1/B\)):

$$
\begin{aligned}
R_o &= \tfrac{\Delta}{\Delta t}\big(V_p S_o b_o \rho_o^{sc}\big) + \textstyle\sum_j T_{ij}\,\rho_o^{sc}\big(\tfrac{k_{ro} b_o}{\mu_o}\big)^{up}\Delta\Phi_o + q_o\\
R_w &= \tfrac{\Delta}{\Delta t}\big(V_p S_w b_w \rho_w^{sc}\big) + \textstyle\sum_j T_{ij}\,\rho_w^{sc}\big(\tfrac{k_{rw} b_w}{\mu_w}\big)^{up}\Delta\Phi_w + q_w\\
R_g &= \tfrac{\Delta}{\Delta t}\big(V_p (S_g b_g + S_o b_o R_s) \rho_g^{sc}\big) + \textstyle\sum_j T_{ij}\,\rho_g^{sc}\Big[\big(\tfrac{k_{rg} b_g}{\mu_g}\big)^{up}\Delta\Phi_g + \big(\tfrac{R_s k_{ro} b_o}{\mu_o}\big)^{up}\Delta\Phi_o\Big] + q_g
\end{aligned}
$$

Давления фаз \(P_w = P - P_{cow}\), \(P_g = P + P_{cog}\); upwind и гравитация — по потенциалу каждой фазы отдельно.

**Переключение переменных** (как в OPM Flow). Неизвестные ячейки: \((P, S_w, X)\).

| Состояние | \(X\) | Прочее | Переход |
|---|---|---|---|
| насыщенное (есть газ) | \(S_g\) | \(R_s = R_s^{sat}(P)\) | \(S_g < 0\) → недонасыщенное, \(R_s = R_s^{sat}(P)\) |
| недонасыщенное | \(R_s\) | \(S_g = 0\) | \(R_s > R_s^{sat}(P)\) → насыщенное, \(S_g = 0\) |

Переключение выполняется после каждой поправки Ньютона; состояние фиксируется только на сошедшемся шаге. Rs хранится в `fluid.rs`.

**PVT.** Насыщенная ветвь — линейная интерполяция таблицы по P (`Bo, Bw, Bg, μ, Rs`). Недонасыщенная нефть:
\(B_o = B_o^{sat}(P_b)\,e^{-c_o (P - P_b)}\), \(\mu_o = \mu_o^{sat}(P_b)\,e^{c_\mu (P - P_b)}\), \(P_b = (R_s^{sat})^{-1}(R_s)\);
\(c_o, c_\mu\) оцениваются по участку таблицы выше давления насыщения (где Rs уже постоянен), иначе берётся `c_oil`.
Без PVT-таблицы — мёртвая нефть и несмешивающийся газ, \(b_\alpha = 1 + c_\alpha (P - 1\,атм)\); при \(S_g = 0\) модель в точности совпадает с двухфазной.

**ОФП** — Stone II:
\(k_{ro} = k_{rocw}\big[(k_{row}/k_{rocw} + k_{rw})(k_{rog}/k_{rocw} + k_{rg}) - k_{rw} - k_{rg}\big]_+\),
двухфазные кривые — Corey по `fluid.relative_permeability` (`nw, now, ng, nog, sw_cr, so_r, sg_cr, krw_end, krg_end, ko_end_w, ko_end_g`) или таблицы SWOF/SGOF. Капиллярные давления — таблицы или степенная модель `Fluid`.

**Производные.** Свойства ячейки (17 величин: массы, давления и плотности фаз, подвижности, \(b\)) вычисляются одной функцией, а их производные по \((P, S_w, X)\) — прямым режимом AD (`torch.func.jvp`, три прохода). Потоки по граням и перфорациям собираются вручную по цепному правилу в блоки 3×3. CPR, FGMRES, AMG и дополнение Шура для скважин — общие с двухфазным решателем.

**Скважины.** Нагнетание воды или газа (`injected_phase`); закачиваемая фаза входит с суммарной подвижностью ячейки. Для добывающих `surface_phase`: `liquid` | `oil` | `water` | `gas` (газ — свободный + растворённый). Начальное \(p_{bh}\) для режима по дебиту находится точно из линейной зависимости дебита от \(p_{bh}\) при замороженной ячейке.

**Критерии.** CNV и MB считаются в поверхностных объёмах, приведённых к пластовым средним \(\bar B_\alpha\) (как в OPM):
\(\text{CNV}_\alpha = \Delta t\,\bar B_\alpha \max_i |R_{\alpha,i}| / (\rho_\alpha^{sc} V_{p,i})\).

**Ограничение поправок.** Изменения \(S_w, S_g, S_o\) в ячейке масштабируются одним множителем до `newton_ds_max`; \(|\delta R_s| \le\) `newton_drs_max_rel`·\(R_s^{max}\).

**Верификация** (`tests/test_blackoil_fim.py`):

| Проверка | Результат |
|---|---|
| Якобиан 3×3 против конечных разностей: смешанное состояние, гравитация, Pcow и Pcog, все ячейки | rel. err ~1e-9 по P и Sw, ~2e-6 по X (округление) |
| Блоки скважин C, B, D против конечных разностей | rel. err < 1e-5 |
| Black-oil без газа против двухфазного FIM, 10×10, 10 сут | ΔP < 2 кПа, ΔSw < 1e-4 |
| Закачка газа, 6×5×3, PVT, 6 сут: баланс компонентов | ошибка < 1e-6 от массы в пласте |
| Истощение ниже давления насыщения | газ выделяется, Rs ≤ Rs_sat, в насыщенных ячейках Rs = Rs_sat |
| `gas_injection_3phase.json`, 20 сут, шаг 1 / 0.25 / 0.0625 сут | 2.0–2.5 итерации на шаг; ошибка по шагу ~4× при уменьшении шага в 4× (первый порядок) |
| То же с PVT, 22 → 12 МПа на забое (переход через Pb) + закачка газа, 30 сут | 2.0–2.2 итерации на шаг, без дроблений |
| 100×100×100, PVT, 65 скважин с пределами BHP, RTX 3090 | 2.7–9 с на 0.5 сут, без дроблений; пиковая память 10 ГБ |

Сравнение с трёхфазным IMPES пока некорректно: IMPES использует старый индекс скважины (`Well.well_index`, зашитые 1 м и 100 мД — фактически бесконечная продуктивность) и при модели `corey` не учитывает влияние газа на \(k_{ro}\).

### Corner-point сетка (`simulator/corner_point.py`)

COORD/ZCORN/ACTNUM → углы ячеек → объём (24 тетраэдра), глубина центра (среднее 8 углов), DX/DY (горизонтальные
расстояния между центрами граней) и DZ для Писмена. Полупроводимость как в Eclipse NEWTRAN:
\(T_i = k_{dir}\,|A\cdot d| / |d|^2\), где \(k_{dir}\) — проницаемость по направлению грани (не тензорная
проекция: на крутом падении \(k_x A_x d_x\) в Z-грани даёт ошибку до 10⁴ раз), \(d\) — от центра ячейки до центра
её полной грани; \(T = 1/(1/T_L + 1/T_R)\); NTG умножает PV и kx, ky. Решатель и скважины берут из `Reservoir`
переопределения `cell_depth`, `cell_dims`, `face_trans`. Неактивные ячейки изолированы (T = 0, минимальный PV).

**Разломы и NNC** (`CornerPointGrid.connections`): для каждой пары соседних столбцов перебираются все сдвиги по k;
перекрытие граней считается точно в координатах (s, z) столба (кусочно-линейные кровля/подошва, разбиение в
точках пересечения). Площадь связи — доля перекрытия от полной грани каждой из ячеек. По k — связь со следующей
активной ячейкой колонки по правилам PINCH (толщина < порога → неактивна; GAP/NOGAP, макс. зазор).
`EclipseCase.static_model()` собирает активность (ACTNUM, MINPV, PINCH), PV (NTG·MULTPV) и множители:
MULTX/Y/Z и MULTX-/Y-/Z-, FAULTS + MULTFLT (с шаблонами имён), MULTREGT (FLUXNUM/MULTNUM, направления, NNC/NONNC).
`EclipseCase(path, grid_only=True)` читает только RUNSPEC/GRID/EDIT — для статической проверки больших моделей.

На SPE9 геометрия совпадает с `SPE9_CP.INIT` Eclipse поячеечно: DEPTH и PORV — 1e-7, TRANX/Y/Z — 1.03e-4
(во всех ячейках одинаково: округлённая константа Дарси 0.001127 в Eclipse).

Norne (46×112×22, 61 разлом, MULTREGT, PINCH, MINPV; `scripts/validate_grid.py` против Eclipse 2014.2), 4 с:

| величина | совпадение |
|---|---|
| активные ячейки | 44431 = 44431, расхождений 0 |
| PORV | медиана 2e-8 |
| TRANX / TRANY / TRANZ | медиана 2.3e-6; > 0.1% — 1% / 0.6% / 0.5% связей |
| NNC | 13455 пар Eclipse найдены все, лишних с T > 0 нет; медиана 2.4e-4, 95% < 0.9%, сумма T 1.00006 |

Остаток по NNC — способ вычисления площади перекрытия в 3D (у нас — масштабирование вектора площади полной грани).
Решатель получает связи списком `Reservoir.connections = (L, R, T)`; блочная CSR строится по ним векторизованно
(`SparseMatrixBuilder(pairs=...)`, 500 тыс. ячеек — 0.13 с), позиции блоков — `builder.position(rows, cols)`.
Для декартовых моделей по-прежнему используется 7-точечный шаблон.

### Расписание и исторический режим

START + DATES и/или TSTEP; режимы WCONPROD, WCONINJE, WCONHIST (ORAT/WRAT/GRAT/LRAT/RESV/BHP), WCONINJH
(RATE/BHP); статусы OPEN/SHUT/STOP в записях режимов и WELOPEN на уровне скважины (маски имён). Скважина без
режима или со статусом SHUT/STOP закрыта: соединения отключены (`conn_open = 0`), уравнение скважины фиксирует
p_bh. STOP трактуется как SHUT (без перетока по стволу). Скважины могут открываться позже начала расчёта; смена
фазы контроля пересчитывает веса уравнения дебита.

RESV (как в Eclipse/OPM, `RateConverter`): уравнение скважины — пластовый объём
\(\sum_c (a_O q_O + a_W q_W + a_G q_G)\) с коэффициентами при средних по углеводородному поровому объёму пласта
давлении \(\bar p\), \(\bar R_s\), \(\bar R_v\) (PVT-регион соединения), \(D = 1 - \bar R_s \bar R_v\):
\(a_O = (1/b_o - \bar R_s/b_g)/(\rho_o^{sc} D)\), \(a_W = 1/(\rho_w^{sc} b_w)\),
\(a_G = (1/b_g - \bar R_v/b_o)/(\rho_g^{sc} D)\). Для WCONHIST цель — пластовый объём исторических Qo, Qw, Qg при
\(\bar p\) с \(R_s = \min(Q_g/Q_o, \bar R_s)\), \(R_v = \min(Q_o/Q_g, \bar R_v)\). Средние — на начало подшага.
Веса по состоянию ячеек соединений (как было раньше) занижали добычу Norne на 2–3% к 230 сут; с весами по средним —
дебиты скважин в пределах 0.1–0.8% от Eclipse. В истории ограничение BHP — 1 атм.

Тип скважины (добыча ↔ закачка) и фаза закачки могут меняться по расписанию: начальный тип — по первому режиму
с ненулевым управлением, при смене пересчитываются веса уравнения дебита и маска закачки, p_bh
инициализируется заново. Накопленные объёмы ведутся раздельно за периоды добычи и закачки (W*PT / W*IT).

### Соединения скважин (COMPDAT, WELOPEN)

Скважина хранит объединение всех соединений за расписание; на каждом отчётном шаге — маска открытых
(`conn_sched`). COMPDAT: состояние OPEN/SHUT, CF (тогда WI = CF), иначе Писмен по направлению X/Y/Z с Kh и Ro
из записи (диаметр по умолчанию 1 фут), скин; повтор соединения заменяет его. WELOPEN с I/J/K (0 — любое)
действует на соединения, без них — на скважину. Скважина без открытых соединений закрыта. Гидростатика ствола —
только по открытым соединениям. Не поддерживаются: SATNUM соединения, D-фактор, номера заканчиваний.

### Закрытие скважин симулятором и WTEST (`eclipse_run.WellTestState`)

Как в Eclipse: открытая скважина на контроле BHP, которая за отчётный шаг ничего не отобрала (нагнетательная —
не закачала), закрывается с причиной P. WTEST (интервал, причины P/E/G/D/C, число проверок, 0 — без
ограничения) открывает её на пробу раз в интервал; не заработала — снова закрыта. Закрытие снимает только явный
WELOPEN OPEN; повтор WCONHIST/WCONPROD — нет (как в OPM). События — `info["well_events"]`. Проверка — по концу
отчётного шага (Eclipse — по концу шага по времени). WECON (причина E) пока не поддерживается.

### Пороговые давления (EQLOPTS THPRES, THPRES)

Поток через границу регионов EQLNUM — только сверх порога: \(\Delta\Phi_{eff} = \mathrm{sign}(\Delta\Phi)
\max(|\Delta\Phi| - \theta, 0)\), производная ниже порога — 0; при θ = 0 результат побитово совпадает с расчётом
без порога. Пары без записи THPRES — порог 0. Порог по умолчанию — максимальная по подвижным фазам
|ΔΦ| через границу в начальном состоянии. IRREVERS — пороги по направлению. Без EQLOPTS THPRES — ошибка.

### VFPPROD и ограничение THP

Таблица задаёт BHP на своей опорной глубине как функцию FLO (OIL/LIQ/GAS), THP, WFR (WOR/WCT/WGR), GFR
(GOR/GLR/OGR) и ALQ; интерполяция многолинейная, вне осей — линейная экстраполяция (как в OPM). На опорную глубину
скважины BHP переносится гидростатикой ствола \(\rho_{wb} g\,(z_{ref} - z_{VFP})\). В режиме THP уравнение скважины
\(r = p_{bh} - BHP_{VFP}(Q_o, Q_w, Q_g, THP) - \rho_{wb} g \Delta z\), \(Q_m = \sum q_m/\rho_{sc,m}\); производные
\(\partial r/\partial p_{bh} = 1 - \sum_m g_m\,\partial Q_m/\partial p_{bh}\), \(\partial r/\partial x = -\sum_m g_m\,\partial Q_m/\partial x\),
\(g_m = \partial BHP_{VFP}/\partial Q_m\) (autograd по таблице). Работает самое жёсткое из ограничений: при дебите
забой ниже \(\max(BHP_{min}, BHP_{VFP})\) — переход на соответствующее ограничение; обратно — когда дебит превысил
уставку или BHP-ограничение стало жёстче THP. WTHP — обратная интерполяция таблицы по THP.
Проверка: `test_vfpprod_thp_control_matches_opm` (SPE1CASE1_METRIC_VFP1 из opm-tests, переход на THP через 2 года).

### VAPPARS

\(R_v^{eff} = R_{v,sat}(P)\,(\max(S_o, 10^{-3})/S_o^{max})^{VAP1}\) при \(S_o < S_o^{max}\) и \(S_o^{max} > 0.01\)
(как saturatedVaporizationFactor в OPM); \(S_o^{max}\) обновляется после каждого принятого шага. Газ при VAPPARS
считается по недонасыщенной формуле PVTG (ветви непрерывны). VAP2 ≠ 0 (снижение Rs) не поддерживается.

Проверка (`tests/test_history_mode.py`, SPE1): дебиты прогноза, поданные как WCONHIST ORAT + WCONINJH, воспроизводят
прогноз с точностью 1e-6; в режиме RESV — 2% (цель пересчитана при среднем давлении); WELOPEN SHUT обнуляет отбор.

### Групповые контроли (`simulator/groups.py`)

GRUPTREE (дерево; без родителя — FIELD), группа скважины из WELSPECS, GCONPROD (ORAT/WRAT/GRAT/LRAT/RESV),
GCONINJE (RATE, REIN — доля добычи фазы поддерева, VREP — доля пластового объёма добычи), режим скважины GRUP.
Цели распределяются явно в начале каждого шага по времени: guide rate = потенциал скважины (дебит при
предельном BHP по замороженному состоянию ячеек); доля не превышает потенциал и собственную цель скважины,
недобор перераспределяется. Под управление группы переводятся скважины в режиме GRUP и все скважины поддерева,
если без этого цель группы нарушается; иначе скважины остаются на своих режимах. Ограничения подгрупп
обрабатываются раньше родительских (родитель только уменьшает доли). Сводка: GOPR/GWPR/GGPR/GWIR/GGIR и *T.

Пока нет: guide rate из GCONPROD/WGRUPCON (используется потенциал), действия при превышении вторичных
ограничений (item 7, 11–13), GCONINJE RESV, GEFAC, сетей (NETBALAN).
Проверка: `tests/test_groups.py` — распределение и иерархия; SPE9 с FIELD ORAT 20000 и закачкой 500: цели
выполняются с точностью 1e-4, доли скважин различаются по потенциалам.

### Регионы (`simulator/regions.py`)

SATNUM — свои SWOF/SGOF (ОФП и Pc), PVTNUM — свои PVTO/PVDO, PVDG, PVTW и ROCK (сжимаемость породы — по
ячейкам), EQLNUM — свои EQUIL и RSVD. Обёртки `RegionPVT` / `RegionRelPerm` повторяют интерфейс таблиц:
значения считаются по всем регионам и выбираются по номеру региона ячейки (дифференцируемо для jvp);
для соединений скважин — `pvt.at(ячейки)`. При одном регионе обёртки не создаются (без накладных расходов).
Равновесие — для каждого EQLNUM: профили фаз по PVT преобладающего в регионе PVTNUM, обращение Pc — по
таблицам SATNUM каждой ячейки. FIPNUM читается (для отчётности). DENSITY должна совпадать по регионам.
Проверка (`tests/test_regions.py`): два одинаковых региона воспроизводят однорегиональный расчёт SPE1 до 1e-9;
свой ВНК во втором EQLNUM меняет насыщенности только в нём; несоответствие числа таблиц числу регионов — ошибка.

### Равновесие EQUIL

Давление нефти интегрируется от опорной глубины, воды — от ВНК, газа — от ГНК (RK2, шаг 0.25 м); насыщенности —
обращением Pcow(Sw) = po − pw и Pcog(Sg) = pg − po в центре ячейки (EQUIL item 9 = 0); при нулевых Pc — резкие контакты.
Rs — по RSVD с ограничением Rs ≤ Rs_sat(p).
Опорная глубина может лежать в водяной (газовой) зоне: тогда профиль воды (газа) строится от опорной глубины,
а профиль нефти — от контакта.

### Масштабирование концевых точек (ENDSCALE, `simulator/endpoint_scaling.py`)

Двух- и трёхточечное (SCALECRS) кусочно-линейное отображение насыщенности ячейки в насыщенность таблицы по
SWL/SWCR/SWU/SGL/SGCR/SGU/SOWCR/SOGCR и вертикальное — KRW/KRO/KRG/PCW/PCG. При совпадении концевых точек
отображение — точное тождество (наклон ровно 1), результаты побитово совпадают с расчётом без ENDSCALE.
SWATINIT: Sw = SWATINIT, PCW ячейки пересчитывается так, чтобы Pcow(SWATINIT) = po − pw; где po − pw ≤ 0 или
Pc(SWATINIT) ≤ 0 — Sw из равновесия.

### Гистерезис ОФП (SATOPTS HYSTER, `simulator/hysteresis.py`)

Модель Карлсона (EHYSTR 0, KR): кривые пропитки — таблицы IMBNUM с концевыми точками I*; кривая сканирования
krn(S) = krn_imb(S + ΔS), сдвиг ΔS — из условия непрерывности в точке разворота (sw_min, sg_max), которые
фиксируются после каждого принятого шага.

### Жирный газ (VAPOIL, PVTG)

Три состояния ячейки: недонасыщенная нефть (X = Rs), насыщенная (X = Sg), газ без нефти (X = Rv, Sg = 1 − Sw).
Масса нефти — So·bo + Sg·bg·Rv, газа — So·bo·Rs + Sg·bg; дополнительный поток нефти в газовой фазе.
Переключение состояния сохраняет массу компонента, по которому оно произошло (обращение той же функции свойств
ячейки). Ветви PVT обязаны совпадать на линии насыщения точно: PVTO — насыщенная нефть берётся из той же
2D-интерполяции в точке (Rs_sat(P), P), что и недонасыщенная (как в OPM); PVTG — недонасыщенный газ =
насыщенный(P) + приращение 2D-таблицы от Rv_sat(P) до Rv. Расхождение ветвей (в SPE1 было 0.06% по Bo и 0.25% по μo)
давало скачки массы ~1e-5 при каждом переключении и зацикливание Ньютона (шаг падал до 1e-3 сут).
Детектор колебаний Ньютона работает по нормированной невязке max(CNV/tol_cnv, MB/tol_mb).

Ячейки без нефти и защита от дребезга переменных:
- `SO_EMPTY = 1e-6`: ячейка с So ≤ SO_EMPTY ведётся по Sg, а не по Rs (как в OPM), в том числе с начала расчёта.
  При So = 0 масса газа So·bo·Rs не зависит от Rs, и газ, закачанный в водоносную ячейку, не мог появиться
  (Norne, C-4H, ~541 сут).
- `SO_FILLED = 1e-4`: обратный переход Sg → Rs — только при So > SO_FILLED. Это гистерезис: с одним порогом
  водоносные ячейки (Sw ≈ 1, Sg ≈ 0) переключались туда-обратно на каждой итерации, и Norne замедлялся в ~4 раза.
- `MAX_CELL_SWITCHES = 3`: ячейка, сменившая состояние столько раз за шаг, до конца шага не переключается
  (переменная остаётся на границе своего состояния). Без этого Ньютон зацикливался на паре ячеек с одинаковой
  невязкой на каждой итерации.
- Переток через перфорацию нагнетательной скважины (давление в ячейке выше, чем в стволе) несёт флюиды ячейки
  по фазовым подвижностям, как у добывающей. Раньше он считался закачиваемой фазой с полной подвижностью: из
  водяной ячейки у газовой C-4H (Norne) «уходил» газ, которого в ней нет, и Ньютон требовал Sg < 0.
- Смешение в стволе нагнетательной (`BlackOilWells.wellbore_mixing`, по умолчанию включено, см. ниже): вошедшие
  в ствол компоненты не выходят на поверхность, а закачиваются обратно в пласт.
- Ослабленный CNV (как в OPM): после `newton_max_strict_iter` = 8 итераций, если ячейки с CNV > tol_cnv занимают
  ≤ `newton_relaxed_max_pv_fraction` = 3% порового объёма, CNV проверяется с допуском `newton_tol_cnv_relaxed` = 1,
  MB — с `newton_tol_mb_relaxed` = 1e-6; скважины — строго. Случай Norne: водонасыщенная ячейка (12,35,20) у C-4H при смене закачки газа на воду —
  Ньютон требует Sw > 1 и Sg < 0, обрезка возвращает их на границу, CNV ~4e-3 не убывает, шаг падал до 0.05 сут.

### Смешение в стволе нагнетательной скважины (`BlackOilWells._wellbore_mixing`)

Перфорации нагнетательной делятся на закачивающие c (давление в стволе выше, чем в ячейке) и перфорации
обратного потока b. Поток \(B = \sum_b q_b\) (массы компонентов), вошедший в ствол, закачивается обратно через
закачивающие перфорации в долях \(f_c = t_c / S\), где \(t_c\) — масса закачки по Дарси (закачиваемая фаза,
полная подвижность), \(S = \sum_c t_c < 0\):

\[ q_c = t_c\,e_{inj} - f_c\,B', \qquad B' = B - \Big(\sum_k B_k\Big) e_{inj}. \]

Масса через перфорацию c остаётся равной расходу Дарси \(t_c\), переток меняет только её состав. Нетто-закачка
скважины с поверхности (уравнение дебита) — \(S + \sum_k B_k\): масса перетока вычитается из закачки. Она монотонна
и непрерывна по p_bh, включая нулевую уставку — тогда ствол закрыт сверху, а жидкость перетекает между
перфорациями (как STOP с перетоком в Eclipse). Без закачивающих перфораций (S = 0) смешение не действует, и обратный
поток выходит на поверхность.

Якобиан точный: смешение связывает ячейки всех перфораций одной скважины, эти пары добавлены в разреженную
структуру (`SparseMatrixBuilder(extra_pairs=...)`), блоки — \(\partial q_c/\partial x_b = -f_c(\partial q_b/\partial x_b
- e_{inj}\otimes\mathbf 1^T\partial q_b/\partial x_b)\) и \(\partial q_c/\partial x_d = -B'\otimes(\delta_{cd}\,\partial t_c
- f_c\,\partial t_d)/S\); производные по p_bh — в `dq/dp_bh`. Для перфораций обратного потока строка Шура уравнения
дебита — \((a\cdot e_{inj})\,\mathbf 1^T\partial q_b/\partial x_b\). Проверка: `tests/test_injector_crossflow.py`
(сохранение массы, нетто-закачка, блоки и dq/dp_bh против центральных конечных разностей).

Прежняя формула \(q_c = t_c - f_c B\) (через перфорацию уходила масса \(t_c - f_c\sum B\)) давала разрыв дебита при
S → 0: на Norne водяная C-3H с уставкой 0 и перетоком в ствол зацикливала Ньютон на 3068 сут при любом шаге.

### Полный прогон Norne

Постановка, результаты против Eclipse 2014.2 и OPM Flow, рисунки и порядок воспроизведения — на странице
[Norne](NORNE.md). Скрипт прогона — `scripts/run_norne.py`.

Чекпоинты: `run_deck(..., checkpoint=path, checkpoint_every=n)` сохраняет полное состояние (симулятор, скважины,
сводку, WTEST, счётчики) после каждых n отчётных шагов (запись через временный файл), `run_deck(..., resume=path)`
продолжает расчёт с него; результат продолжения совпадает со сквозным расчётом побитово (SPE1).

### Пошаговый прогон deck и среда для агентов (`iter_deck`, `src/deck_env.py`)

`iter_deck(...)` — генератор: отдаёт `(n, t, summary)` после каждого отчётного шага, по окончании возвращает
`(summary, info)` (через `StopIteration.value`); `run_deck` — обёртка над ним. `control_hook(n, t, wm, solver)`
вызывается перед каждым отчётным шагом после расписания и WTEST — в нём можно менять уставки скважин;
`context` получает ссылки на `case/sim/wm/solver/fluid`, `yield_start=True` отдаёт начальное состояние.

`DeckEnv(deck, start=ckpt, ...)` — среда gymnasium поверх `iter_deck`: шаг = отчётный шаг deck, действие —
множитель 0…2 к уставке каждой скважины под контролем дебита/RESV (скважины на BHP, закрытые и групповые не
трогаются), наблюдение — дебиты нефти/воды/газа (м³/сут) и забой (МПа) каждой скважины, среднее давление и
доля прошедшего времени. Награда — `(oil_price·ΔQo − water_cost·ΔQw − inj_cost·ΔWi − gas_inj_cost·ΔGi)/reward_scale`
по приращениям накопленных объёмов (м³); расхождение Ньютона даёт `fail_penalty` и конец эпизода. `start` —
чекпоинт `run_deck`, эпизод начинается с него (например, Norne с середины истории). Действие из единиц
воспроизводит `run_deck` (тест `tests/test_deck_env.py`).

### Линейная система только по связанным ячейкам

Ячейки, у которых в строке Якобиана нет соседей (изолированные активные ячейки после MINPV/PINCH и т.п.) и нет
перфораций, решаются отдельно — прямым решением блока 3×3. FGMRES и CPR-AMG строятся на оставшейся подсистеме
(индексы кэшируются, `linear_drop_isolated`, по умолчанию true). На Norne это заметно улучшает сходимость
линейного решателя: 125 суток после 3068 сут — 25.7 с вместо 55.7 с, 58 итераций Ньютона вместо 93.

### Воспроизводимость

Включён `torch.use_deterministic_algorithms` (параметр `deterministic`, по умолчанию true): ядра с накоплением
(index_add/scatter, разреженное умножение в AMG) иначе дают расхождения ~1e-14, которые Ньютон усиливает до ~1e-5
в результатах. Стоимость — около 14% времени. Огрубление AMG использует генератор с фиксированным зерном.

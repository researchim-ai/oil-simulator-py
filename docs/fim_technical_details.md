# Fully Implicit Method (FIM): техническое описание

Полностью неявный решатель: модель нефть–вода (`src/simulator/manual_assembly_solver.py`) и трёхфазный black-oil (`src/simulator/blackoil_fim.py`, раздел 9).
Неизвестные двухфазной модели: давление \(P\) и водонасыщенность \(S_w\) в каждой ячейке плюс забойное давление каждой скважины.

## 1. Дискретизация

Уравнение сохранения массы фазы \(\alpha \in \{o, w\}\) для ячейки \(i\):

$$
R_{\alpha,i} = \frac{(V_p S_\alpha \rho_\alpha)^{n+1}_i - (V_p S_\alpha \rho_\alpha)^{n}_i}{\Delta t}
+ \sum_{j} T_{ij}\, \lambda_{\alpha,ij}^{up}\, \Delta\Phi_{\alpha,ij} + q_{\alpha,i} = 0,
\qquad
\Delta\Phi_{\alpha,ij} = (P_i - P_j) - \bar\rho_{\alpha,ij}\, g\, (z_i - z_j)
$$

* \(\lambda_\alpha = k_{r\alpha}\rho_\alpha/\mu_\alpha\) — массовая подвижность, берётся по схеме upwind по потенциалу фазы (противоток возможен).
* \(V_p = V_{p,0}\,(1 + c_r (P - P_{ref}))\) — сжимаемость породы (`c_rock` в разделе `fluid`).
* Проводимость грани (TPFA, полуячейки, неравномерная сетка):
  \(T_{ij} = A_{ij} / \left(\frac{d_i}{2k_i} + \frac{d_j}{2k_j}\right)\).
* Сборка идёт по списку граней (L, R, T, Δz), поэтому добавление NNC/разломов и corner-point сводится к расширению этого списка.

Якобиан собирается аналитически в блочном формате BSR 2×2. Корректность проверяется конечными разностями (`tests/test_fim_jacobian.py`, `tests/test_fim_wells.py`, режим отладки уровня 3).

## 2. Скважины

* Перфорации: `perforations: [[i,j,k], ...]` (по умолчанию одна ячейка `i,j,k`).
* Индекс скважины по Писмену для анизотропной ячейки:
  \(WI = \frac{2\pi\sqrt{k_x k_y}\,h}{\ln(r_0/r_w) + s}\),
  \(r_0 = 0.28\frac{\sqrt{\sqrt{k_y/k_x}\,\Delta x^2 + \sqrt{k_x/k_y}\,\Delta y^2}}{(k_y/k_x)^{1/4} + (k_x/k_y)^{1/4}}\);
  `skin`, ручной `well_index` (м³).
* Забойное давление \(p_{bh}\) на глубине верхней перфорации — отдельная неизвестная; давление в стволе у перфорации \(p_{bh} + \rho_{wb} g \Delta z\) (плотность смеси в стволе берётся явно на начало шага).
* Режимы: `rate` (поверхностный дебит; для добывающих `surface_phase` = `liquid` | `oil` | `water`, для нагнетательных — вода) и `bhp`.
* Ограничения: `bhp_min` (добывающие, по умолчанию 1 атм), `bhp_max` (нагнетательные). При нарушении скважина автоматически переходит на BHP-ограничение и возвращается на дебит, когда пласт снова способен его обеспечить. Режим сохраняется между шагами.
* Уравнения скважин исключаются через дополнение Шура \(J - C D^{-1} B\) прямо в операторе FGMRES; вклад каждой перфорации в собственный диагональный блок учитывается и в предобуславливателе.
* `ramp_days` — опциональный плавный выход на режим (по умолчанию выключен).

## 3. Метод Ньютона и критерии сходимости

Критерии — как в Eclipse/OPM:

| Критерий | Формула | Параметр (по умолчанию) |
|---|---|---|
| CNV (локальный) | \(\Delta t \max_i \lvert R_{\alpha,i}\rvert / (\rho_{\alpha,ref} V_{p,i})\) | `newton_tol_cnv` (1e-3) |
| MB (глобальный баланс) | \(\Delta t \lvert\sum_i R_{\alpha,i}\rvert / (\rho_{\alpha,ref} \sum_i V_{p,i})\) | `newton_tol_mb` (1e-7) |
| Дебит скважины | \(\lvert Q - Q^*\rvert / \lvert Q^*\rvert\) | `newton_tol_well_rate` (1e-5) |
| Забойное давление | \(\lvert p_{bh} - p^*\rvert\), Па | `newton_tol_well_bhp` (10) |

Параметры `newton_tol_mass` и `newton_tolerance` устарели и игнорируются.

Поправки ограничиваются по каждой ячейке (Appleyard): \(|\delta S_w| \le\) `newton_ds_max` (0.2),
\(|\delta P| \le \max(\) `newton_dp_max_rel`·P, `newton_dp_max_abs_mpa`\()\), \(|\delta p_{bh}| \le\) `newton_dbhp_max_rel`·\(p_{bh}\).

## 4. Линейный решатель

* FGMRES (`src/solver/fgmres.py`) на GPU, строки масштабируются по диагональным блокам.
* CPR (`src/simulator/cpr_gpu.py`): давление выделяется по квази-IMPES (веса \(w_i = D_{ii}^{-T} e_p\)), решается одним V-циклом Classical AMG; затем блочный Якоби для полной системы (`cpr_smoother_sweeps`).
* Иерархия AMG строится на первой итерации шага и дальше только обновляется (`amg_rebuild`: `step` | `iteration`).
* Допуск — неточный Ньютон: \(\eta = \mathrm{clip}(0.1\cdot \text{CNV}/\text{CNV}_0,\ \) `linear_tol_min`, `linear_tol_max`\()\).
* Если фактическая невязка СЛАУ выше `linear_accept_rel_res` (0.1), итерация считается отказом и шаг по времени дробится.

## 5. Шаг по времени

`Simulator.run_step(dt)` продвигает решение ровно на отчётный интервал подшагами:

* рост шага: \(f = \min(\) `dt_increase_factor`, `newton_target_iter`/итерации, `dt_target_dsw`/max ΔSw\()\);
* при несходимости — деление на `dt_reduction_factor`, не ниже `min_time_step_days`, не более `max_time_step_attempts` дроблений подряд;
* `max_time_step_days`, `initial_time_step_days`; подобранный шаг переносится на следующий интервал.

## 6. Режим отладки

`--debug-solver [1|2|3]` или `simulation.debug` в конфиге. Журнал `results/solver_debug/<run>/events.jsonl`:

1. CNV/MB по фазам, худшие ячейки, итерации и фактическая невязка СЛАУ, AMG, поправки и число ограниченных ячеек, переключения скважин, время по стадиям; снимок системы при сбое.
2. + истории FGMRES, дебиты/режимы/забойные давления скважин, диагностика Якобиана, лог построения AMG.
3. + проверка Якобиана конечными разностями и снимки на каждой итерации.

## 8. Ограничения (план работ)

* Corner-point только согласованная (без разломов, NNC, MULTX/MULTFLT, PINCH, MINPV).
* Нет испаряющейся нефти (Rv), гистерезиса ОФП, регионов (SATNUM/PVTNUM/EQLNUM), групповых ограничений скважин,
  DATES/WCONHIST/WELOPEN.
* Дебиты только поверхностные (`rate_type: "reservoir"` в FIM не поддерживается).

## 9. Трёхфазный black-oil (`src/simulator/blackoil_fim.py`)

Включается `simulation.fim_model: "blackoil"` или автоматически (`"auto"`): PVT-таблица, начальная `s_g > 0`, газовые скважины.

**Компоненты и уравнения** (кг/с, \(b = 1/B\)):

$$
\begin{aligned}
R_o &= \tfrac{\Delta}{\Delta t}\big(V_p S_o b_o \rho_o^{sc}\big) + \textstyle\sum_j T_{ij}\,\rho_o^{sc}\big(\tfrac{k_{ro} b_o}{\mu_o}\big)^{up}\Delta\Phi_o + q_o\\
R_w &= \tfrac{\Delta}{\Delta t}\big(V_p S_w b_w \rho_w^{sc}\big) + \textstyle\sum_j T_{ij}\,\rho_w^{sc}\big(\tfrac{k_{rw} b_w}{\mu_w}\big)^{up}\Delta\Phi_w + q_w\\
R_g &= \tfrac{\Delta}{\Delta t}\big(V_p (S_g b_g + S_o b_o R_s) \rho_g^{sc}\big) + \textstyle\sum_j T_{ij}\,\rho_g^{sc}\Big[\big(\tfrac{k_{rg} b_g}{\mu_g}\big)^{up}\Delta\Phi_g + \big(\tfrac{R_s k_{ro} b_o}{\mu_o}\big)^{up}\Delta\Phi_o\Big] + q_g
\end{aligned}
$$

Давления фаз \(P_w = P - P_{cow}\), \(P_g = P + P_{cog}\); upwind и гравитация — по потенциалу каждой фазы отдельно.

**Переключение переменных** (как в OPM Flow). Неизвестные ячейки: \((P, S_w, X)\).

| Состояние | \(X\) | Прочее | Переход |
|---|---|---|---|
| насыщенное (есть газ) | \(S_g\) | \(R_s = R_s^{sat}(P)\) | \(S_g < 0\) → недонасыщенное, \(R_s = R_s^{sat}(P)\) |
| недонасыщенное | \(R_s\) | \(S_g = 0\) | \(R_s > R_s^{sat}(P)\) → насыщенное, \(S_g = 0\) |

Переключение выполняется после каждой поправки Ньютона; состояние фиксируется только на сошедшемся шаге. Rs хранится в `fluid.rs`.

**PVT.** Насыщенная ветвь — линейная интерполяция таблицы по P (`Bo, Bw, Bg, μ, Rs`). Недонасыщенная нефть:
\(B_o = B_o^{sat}(P_b)\,e^{-c_o (P - P_b)}\), \(\mu_o = \mu_o^{sat}(P_b)\,e^{c_\mu (P - P_b)}\), \(P_b = (R_s^{sat})^{-1}(R_s)\);
\(c_o, c_\mu\) оцениваются по участку таблицы выше давления насыщения (где Rs уже постоянен), иначе берётся `c_oil`.
Без PVT-таблицы — мёртвая нефть и несмешивающийся газ, \(b_\alpha = 1 + c_\alpha (P - 1\,атм)\); при \(S_g = 0\) модель в точности совпадает с двухфазной.

**ОФП** — Stone II:
\(k_{ro} = k_{rocw}\big[(k_{row}/k_{rocw} + k_{rw})(k_{rog}/k_{rocw} + k_{rg}) - k_{rw} - k_{rg}\big]_+\),
двухфазные кривые — Corey по `fluid.relative_permeability` (`nw, now, ng, nog, sw_cr, so_r, sg_cr, krw_end, krg_end, ko_end_w, ko_end_g`) или таблицы SWOF/SGOF. Капиллярные давления — таблицы или степенная модель `Fluid`.

**Производные.** Свойства ячейки (17 величин: массы, давления и плотности фаз, подвижности, \(b\)) вычисляются одной функцией, а их производные по \((P, S_w, X)\) — прямым режимом AD (`torch.func.jvp`, три прохода). Потоки по граням и перфорациям собираются вручную по цепному правилу в блоки 3×3. CPR, FGMRES, AMG и дополнение Шура для скважин — общие с двухфазным решателем.

**Скважины.** Нагнетание воды или газа (`injected_phase`); закачиваемая фаза входит с суммарной подвижностью ячейки. Для добывающих `surface_phase`: `liquid` | `oil` | `water` | `gas` (газ — свободный + растворённый). Начальное \(p_{bh}\) для режима по дебиту находится точно из линейной зависимости дебита от \(p_{bh}\) при замороженной ячейке.

**Критерии.** CNV и MB считаются в поверхностных объёмах, приведённых к пластовым средним \(\bar B_\alpha\) (как в OPM):
\(\text{CNV}_\alpha = \Delta t\,\bar B_\alpha \max_i |R_{\alpha,i}| / (\rho_\alpha^{sc} V_{p,i})\).

**Ограничение поправок.** Изменения \(S_w, S_g, S_o\) в ячейке масштабируются одним множителем до `newton_ds_max`; \(|\delta R_s| \le\) `newton_drs_max_rel`·\(R_s^{max}\).

**Верификация** (`tests/test_blackoil_fim.py`):

| Проверка | Результат |
|---|---|
| Якобиан 3×3 против конечных разностей: смешанное состояние, гравитация, Pcow и Pcog, все ячейки | rel. err ~1e-9 по P и Sw, ~2e-6 по X (округление) |
| Блоки скважин C, B, D против конечных разностей | rel. err < 1e-5 |
| Black-oil без газа против двухфазного FIM, 10×10, 10 сут | ΔP < 2 кПа, ΔSw < 1e-4 |
| Закачка газа, 6×5×3, PVT, 6 сут: баланс компонентов | ошибка < 1e-6 от массы в пласте |
| Истощение ниже давления насыщения | газ выделяется, Rs ≤ Rs_sat, в насыщенных ячейках Rs = Rs_sat |
| `gas_injection_3phase.json`, 20 сут, шаг 1 / 0.25 / 0.0625 сут | 2.0–2.5 итерации на шаг; ошибка по шагу ~4× при уменьшении шага в 4× (первый порядок) |
| То же с PVT, 22 → 12 МПа на забое (переход через Pb) + закачка газа, 30 сут | 2.0–2.2 итерации на шаг, без дроблений |
| 100×100×100, PVT, 65 скважин с пределами BHP, RTX 3090 | 2.7–9 с на 0.5 сут, без дроблений; пиковая память 10 ГБ |

Сравнение с трёхфазным IMPES пока некорректно: IMPES использует старый индекс скважины (`Well.well_index`, зашитые 1 м и 100 мД — фактически бесконечная продуктивность) и при модели `corey` не учитывает влияние газа на \(k_{ro}\).

### Corner-point сетка (`simulator/corner_point.py`)

COORD/ZCORN/ACTNUM → углы ячеек → объём (24 тетраэдра), глубина центра (среднее 8 углов), DX/DY (горизонтальные
расстояния между центрами граней) и DZ для Писмена. Полупроводимость как в Eclipse NEWTRAN:
\(T_i = k_{dir}\,|A\cdot d| / |d|^2\), где \(k_{dir}\) — проницаемость по направлению грани (не тензорная
проекция: на крутом падении \(k_x A_x d_x\) в Z-грани даёт ошибку до 10⁴ раз), \(d\) — от центра ячейки до центра
её полной грани; \(T = 1/(1/T_L + 1/T_R)\); NTG умножает PV и kx, ky. Решатель и скважины берут из `Reservoir`
переопределения `cell_depth`, `cell_dims`, `face_trans`. Неактивные ячейки изолированы (T = 0, минимальный PV).

**Разломы и NNC** (`CornerPointGrid.connections`): для каждой пары соседних столбцов перебираются все сдвиги по k;
перекрытие граней считается точно в координатах (s, z) столба (кусочно-линейные кровля/подошва, разбиение в
точках пересечения). Площадь связи — доля перекрытия от полной грани каждой из ячеек. По k — связь со следующей
активной ячейкой колонки по правилам PINCH (толщина < порога → неактивна; GAP/NOGAP, макс. зазор).
`EclipseCase.static_model()` собирает активность (ACTNUM, MINPV, PINCH), PV (NTG·MULTPV) и множители:
MULTX/Y/Z и MULTX-/Y-/Z-, FAULTS + MULTFLT (с шаблонами имён), MULTREGT (FLUXNUM/MULTNUM, направления, NNC/NONNC).
`EclipseCase(path, grid_only=True)` читает только RUNSPEC/GRID/EDIT — для статической проверки больших моделей.

На SPE9 геометрия совпадает с `SPE9_CP.INIT` Eclipse поячеечно: DEPTH и PORV — 1e-7, TRANX/Y/Z — 1.03e-4
(во всех ячейках одинаково: округлённая константа Дарси 0.001127 в Eclipse).

Norne (46×112×22, 61 разлом, MULTREGT, PINCH, MINPV; `scripts/validate_grid.py` против Eclipse 2014.2), 4 с:

| величина | совпадение |
|---|---|
| активные ячейки | 44431 = 44431, расхождений 0 |
| PORV | медиана 2e-8 |
| TRANX / TRANY / TRANZ | медиана 2.3e-6; > 0.1% — 1% / 0.6% / 0.5% связей |
| NNC | 13455 пар Eclipse найдены все, лишних с T > 0 нет; медиана 2.4e-4, 95% < 0.9%, сумма T 1.00006 |

Остаток по NNC — способ вычисления площади перекрытия в 3D (у нас — масштабирование вектора площади полной грани).
Решатель получает связи списком `Reservoir.connections = (L, R, T)`; блочная CSR строится по ним векторизованно
(`SparseMatrixBuilder(pairs=...)`, 500 тыс. ячеек — 0.13 с), позиции блоков — `builder.position(rows, cols)`.
Для декартовых моделей по-прежнему используется 7-точечный шаблон.

### Расписание и исторический режим

START + DATES и/или TSTEP; режимы WCONPROD, WCONINJE, WCONHIST (ORAT/WRAT/GRAT/LRAT/RESV/BHP), WCONINJH
(RATE/BHP); статусы OPEN/SHUT/STOP в записях режимов и WELOPEN на уровне скважины (маски имён). Скважина без
режима или со статусом SHUT/STOP закрыта: соединения отключены (`conn_open = 0`), уравнение скважины фиксирует
p_bh. STOP трактуется как SHUT (без перетока по стволу). Скважины могут открываться позже начала расчёта; смена
фазы контроля пересчитывает веса уравнения дебита.

RESV: уравнение скважины — пластовый объём \(\sum_c (a_O q_O + a_W q_W + a_G q_G)\) с весами по состоянию ячеек
на начало шага (\(a_O = 1/(\rho_o^{sc} b_o) - R_s/(\rho_o^{sc} b_g)\), \(a_W = 1/(\rho_w^{sc} b_w)\),
\(a_G = 1/(\rho_g^{sc} b_g)\)); для WCONHIST цель — пластовый объём исторических Qo, Qw, Qg при среднем
(по углеводородному PV) давлении пласта, как в Eclipse. В истории ограничение BHP — 1 атм.

Проверка (`tests/test_history_mode.py`, SPE1): дебиты прогноза, поданные как WCONHIST ORAT + WCONINJH, воспроизводят
прогноз с точностью 1e-6; в режиме RESV — 2% (цель пересчитана при среднем давлении); WELOPEN SHUT обнуляет отбор.

### Групповые контроли (`simulator/groups.py`)

GRUPTREE (дерево; без родителя — FIELD), группа скважины из WELSPECS, GCONPROD (ORAT/WRAT/GRAT/LRAT/RESV),
GCONINJE (RATE, REIN — доля добычи фазы поддерева, VREP — доля пластового объёма добычи), режим скважины GRUP.
Цели распределяются явно в начале каждого шага по времени: guide rate = потенциал скважины (дебит при
предельном BHP по замороженному состоянию ячеек); доля не превышает потенциал и собственную цель скважины,
недобор перераспределяется. Под управление группы переводятся скважины в режиме GRUP и все скважины поддерева,
если без этого цель группы нарушается; иначе скважины остаются на своих режимах. Ограничения подгрупп
обрабатываются раньше родительских (родитель только уменьшает доли). Сводка: GOPR/GWPR/GGPR/GWIR/GGIR и *T.

Пока нет: guide rate из GCONPROD/WGRUPCON (используется потенциал), действия при превышении вторичных
ограничений (item 7, 11–13), GCONINJE RESV, GEFAC, сетей (NETBALAN).

### Равновесие EQUIL

Давление нефти интегрируется от опорной глубины, воды — от ВНК, газа — от ГНК (RK2, шаг 0.25 м); насыщенности —
обращением Pcow(Sw) = po − pw и Pcog(Sg) = pg − po в центре ячейки (EQUIL item 9 = 0); при нулевых Pc — резкие контакты.
Rs — по RSVD с ограничением Rs ≤ Rs_sat(p).

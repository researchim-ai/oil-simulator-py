# Связанная динамика конечных PR-сосудов

`CompositionalNetwork` объединяет [компонентные сепараторы](COMPOSITIONAL_SEPARATOR.md)
в одну неявную систему Torch float64 CPU/CUDA. Все фазовые количества,
давления, температуры и температуры стенок решаются совместно. Это
не последовательная передача заранее вычисленных потоков между сосудами.
Межсосудные производные входят в общий якобиан, включая состав и энергию.

Исторический `VesselNetwork` на NumPy/SciPy остаётся отдельной моделью.
Он не вызывается новым решателем и не служит скрытым CPU fallback.

## Соединения и сохраняемые величины

`CompositionalConnection` задаёт имена источника и приёмника, объёмную
проводимость, открытие, возможность обратного течения и выбор фаз с
каждой стороны. Для текущего донора используется:

`Vdot_phase = G × opening × max(Pdonor − Preceiver, 0) × Vphase / Vvessel`.

Это прежний режим без геометрического патрубка. Необязательная
[PR-геометрия](PR_PHASE_GEOMETRY.md) заменяет `Vphase/Vvessel`
долей площади круглого отверстия и добавляет неявный `level_control`.
Такое замыкание сейчас требует `g=0` и не рассчитывает гидростатический профиль.

Молярный расход фазы равен `Vdot_phase / vm_phase`. Компонентные расходы,
энтальпия и энтропия берутся из **конечного состояния фактического донора**.
При обратном течении используется противоположный сосуд и его правило
выбора фаз. Результат хранится со знаком относительно `source → target`.
`donor_volume_rate_m3_s` — объёмный расход при условиях донора со знаком;
он не является объёмным расходом в условиях приёмника.

Один вычисленный поток вносится с противоположными знаками в оба сосуда.
Поэтому внутренние соединения сокращаются в глобальных балансах
компонентов и полной энергии. У каждого сосуда дополнительно проверяются
собственные компонентный, энергетический, объёмный и энтропийный балансы.
В общий энергетический запас входят стенки. Наружные питание, экспорт,
нагрев и теплообмен со средой отражаются в отдельном внешнем журнале.

Возможные режимы выбора: `bulk`, `densest`, `lightest`, `component_rich`.
Для последнего задаётся компонент и порог его молярной доли.
Это идеальное селективное извлечение, а не модель капельного уноса или
расположения патрубков. На границах смены донора/фазы закон негладкий.
`allow_reverse=false` блокирует обратный поток без внешнего подпитывания.

Ограничение `maximum_pressure_drop_fraction` проверяет объявленную область
проводимости, а не автоматически калибрует её. За пределами области
начальное состояние отклоняется до Ньютона; выход за пределы на пробном
шаге требует уменьшения шага либо изменения модели/режима. Расход не
подрезается молча до произвольного предела. Закрытое соединение не течёт.

## Общая термодинамика и новые компоненты

Все сосуды обязаны иметь одинаковые EOS, реестр компонентов, энергетические
референсы и устройство. Автоматического сведения разных PVT не происходит.
Смена фазового набора запускает повторное решение общей системы.
Старые запасы при смене ветви не меняются. Для чистого компонента
UV-предиктор служит только начальным приближением к новой ветви.

Активные компоненты расширяются по возможным направлениям транспорта,
включая цепочки соединений в пределах одного неявного шага. Закрытые
и нулевые проводимости не распространяют активный набор. Начальное
приближение логарифмических неизвестных использует малые положительные
числа; они не добавляются в правые части материального баланса.
Для потенциально достижимого компонента без фактического переноса может
остаться численный след в пределах допуска. Компонент, отсутствующий
во всём достижимом наборе запасов/питания, сохраняет точный ноль.

Постпроверка устойчивости выполняется отдельно от Ньютона. Численный
мультистарт TPD не является универсальным сертификатом глобального
минимума. Внутри общей невязки нет вложенного равновесного flash.

## Численная схема и область производительности

Backward Euler, адаптивное дробление и оценка ошибки «шаг против двух
полушагов» по компонентам, давлению, температуре и стенкам всех сосудов.
Принимаются полушаги. Сохраняется следующий предлагаемый шаг и единые
часы; отчётный интервал покрывается полностью. Неудачный интервал не
изменяет входное состояние и не публикует частичный результат.

До 128 неизвестных применяется прямое Torch-решение якобиана.
Выше — топологический шаблон блочной разреженности, окрашенный forward AD
и предобусловленный GMRES из общего Torch-ядра. Шаблон учитывает собственный
сосуд и соседей; при смене фаз/активного набора строится соответствующая
структура. Малый direct-путь и принудительный sparse-путь сверяются тестом.
Сеть из 36 сосудов проверяет фактическое пересечение порога 128 неизвестных.

Для появления компонента через несколько соединений используется
положительный предиктор переноса с замороженными начальными давлениями.
Ограниченное число Jacobi-проходов даёт начальные количества; сходимость
этого предиктора не предполагается и его баланс не принимается за ответ.
Окончательное решение обязано пройти полную связанную PR-систему и
физические проверки. Это устраняет большие логарифмические поправки
при попытке начать реальный входящий поток с машинного нуля.

Нелинейные решения остаются на выбранном устройстве. Управление ветвями,
проверки сходимости и сериализация синхронизируются с CPU. Это ещё не
GPU-resident пакетный flash, не CUDA Graph и не заявление об ускорении
малых сетей на GPU. Испытание 36 сосудов не квалифицирует тысячные сети
и не заменяет отдельный бенчмарк крупных связанных моделей.

## Конфигурация и запуск

Пример `configs/surface_compositional_network.json`: три сосуда, три
соединения (одно с запретом обратного хода), стенка, питание, нагрев,
экспорт, закрытие, смена направления одного соединения и общий останов.
Модель свойств иллюстративная, не калиброванная для реальной установки.

```bash
python scripts/run_compositional_network.py configs/surface_compositional_network.json --device cpu --output /tmp/network_cpu.json
python scripts/run_compositional_network.py configs/surface_compositional_network.json --device cuda --output /tmp/network_cuda.json
python scripts/check_compositional_network.py configs/surface_compositional_network.json /tmp/network_cpu.json /tmp/network_cuda.json --output /tmp/network_check.json
```

Разреженный квалификационный случай воспроизводится генератором:

```bash
python scripts/build_compositional_chain.py --vessels 36 --output /tmp/chain36.json
python scripts/run_compositional_network.py /tmp/chain36.json --device cpu --output /tmp/chain36_cpu.json
python scripts/run_compositional_network.py /tmp/chain36.json --device cuda --output /tmp/chain36_cuda.json
python scripts/check_compositional_network.py /tmp/chain36.json /tmp/chain36_cpu.json /tmp/chain36_cuda.json --output /tmp/chain36_check.json
```

Генерация большего числа сосудов сама по себе не подтверждает их расчёт.

Корневые поля: `system`, `initial`, `periods`.
`system.vessels` — словарь имя → полная конфигурация `CompositionalSeparator`.
`system.connections` — список соединений. Численные параметры сети задаются
на её уровне; локальные ограничения изменения запасов/температур остаются
у сосудов. `initial` содержит PT/состав и, при необходимости, температуру
стенки для каждого сосуда. Типизированный Python API также принимает
полные `CompositionalNetworkState` с запасами, включая чистое насыщение.

Период: `duration_s`, `feeds` (имя сосуда → список потоков `from_pt`/`stream`),
`heat_w`, `utility_temperature_k` (словари по сосудам),
`outlet_openings` (сосуд → выход → открытие),
`connection_openings` (соединение → открытие), `max_substeps`.
Неизвестные имена и некорректные будущие команды отвергаются до публикации.
Давление пассивного питания проверяется в фактическом состоянии периода
и на принятых конечных состояниях, не подменяется насосом.

`--stop-after N` сохраняет префикс, `--checkpoint PATH` продолжает его.
Checkpoint связан с исходниками, всей конфигурацией, расписанием,
runtime и устройством. Кроме checksum выполняется физический повтор
префикса. Между CPU и CUDA checkpoint не переносится автоматически.
CLI проверяет исходники до импорта и перед атомарной публикацией.

Проверяющий скрипт самостоятельно восстанавливает линейные потоки,
upwind-состав/энергию, фазовые объёмы, фугитивности и локальные/общие
балансы из журналов. EOS общая; это независимая проверка сборки балансов,
а не внешний промышленный термодинамический эталон.

## Оставшаяся физика

Соединения не имеют распределённых запасов, инерции, проскальзывания фаз,
тепловой стенки трубы или критического истечения. Чтобы не выдавать
перепад давления за полный гравитационный напор, эта версия требует
одинаковых геодезической отметки и g всех сосудов. Разные высоты
отклоняются явно. Кинематические уровни/патрубки при `g=0` реализованы
отдельным замыканием выше. Пространственная PR-гидростатика, подробная многофазная
труба, приводы и карты реальных агрегатов, общие защиты/регуляторы PR-сети
и неявное энергетическое сопряжение с FIM — следующие задачи.
Существующие жидкостные и газовые контуры не стали частью этой системы
автоматически. Реальные измерения для калибровки отсутствуют.

# Динамический равновесный сосуд

`DynamicVessel` — жёсткий сосуд постоянного объёма с запасами явных компонентов
PR-смеси и полной внутренней энергией. Давление и температура изменяются
в результате подачи, отбора и тепла. Это отдельный CPU reference, использующий
[термодинамику PR](THERMODYNAMICS.md); он не превращает установившуюся
[тепловую схему](THERMAL_PROCESS.md) в динамическую автоматически.

## Состояние и уравнения

`VesselState` хранит `component_moles`, `internal_energy_j`, `pressure_pa`,
`temperature_k`, `time_s`, `model_id`. P/T нужны для продолжения нелинейного
решения; произвольные P/T при заданных запасах и энергии не допускаются.
При загрузке проверяются состав, EOS, постоянный объём и энергия.

Внутри сосуда фазы мгновенно приходят к общему равновесию при P/T. Для каждой
пробы выполняется PT-flash с численной проверкой фазовой устойчивости.
Объём и энергия вычисляются по фазам:

```
V = sum_phase N_phase v_phase
U = sum_phase N_phase h_phase - P V
```

Неявный шаг backward Euler одновременно решает положительные запасы каждого
компонента, P и T:

```
n_i,new - n_i,old = dt (F_in,i - F_out,i,new)
U_new - U_old = dt (H_in - H_out,new + Q)
V_new = V_vessel
```

Вход и выход переносят **энтальпию**, запас хранит **внутреннюю энергию**.
У закрытого нагреваемого идеального газа поэтому получается Cv, а не Cp;
при заполнении учитывается работа входящего потока. Замена U на H дала бы
другую физику. Общий принцип динамических запасов и потоков энергии описан
в [IDAES 0D control volume](https://idaes-pse.readthedocs.io/en/main/reference_guides/core/control_volume_0d.html).

Нелинейные неизвестные — логарифмы компонентных запасов и давления,
температура ограничена общей областью калорической модели. Проверяются
сами невязки, а не только признак остановки оптимизатора. Разрешается
локальное продолжение решения из предыдущего состояния; глобальный поиск
всех UV-ветвей и сертификат максимума энтропии не заявляются.

## Подача, отбор и тепло

Подачи — `ThermalStream` с тем же отпечатком EOS/порядком компонентов.
Для пассивного входа давление источника не ниже давления сосуда.
Расход задан пользователем, гидравлика входной арматуры не рассчитывается.
Энтальпия входящего потока сохраняется при пассивном сбросе давления;
диссипация входа входит в общий энтропийный баланс.

Отбор задаётся молярными расходами по портам:

- `bulk`: состав всего запаса и равновесная средняя энтальпия.
- `phase_0`: состав и энтальпия первой разрешённой фазы.
- `phase_1`: состав и энтальпия второй разрешённой фазы.

В двухфазном режиме PR первая фаза — жидкость, вторая — пар. Если фаза
отсутствует, положительный отбор из её порта отклоняется. Автоматического
переключения фазового порта на bulk нет. В однофазном режиме `phase_0` —
единственная фаза, без выдуманной классификации по плотности.

Q положительна при подводе тепла. Для ненулевой Q требуется явная
`utility_temperature_k`. Проверяются направление обмена относительно
конечных температур и дискретный энтропийный баланс:

```
S_new - S_old - dt (S_in - S_out,new + Q/T_utility) >= 0
```

Это равномерная температура рабочего объёма и заданный тепловой поток от
резервуара. Нет тепловой инерции стенки, UA, пространственного профиля
температуры или конечного запаса теплоносителя.

## Ограничения и шаг по времени

`min_pressure_pa`, `max_pressure_pa`, `minimum_component_moles` ограничивают
разрешённую область. Вакуум и полное исчезновение компонента не моделируются;
запас не обрезается до нуля задним числом.

При двух разрешённых фазах возвращаются фазовые объёмы и доля жидкого объёма.
Необязательные `min_liquid_volume_fraction`/`max_liquid_volume_fraction`
ограничивают её. Для однофазного состояния эта доля неизвестна (`null`);
включённая защита требует разрешённых фаз и отклоняет неоднозначное состояние.
Объёмная доля не выдаётся за высоту уровня: для высоты нужна геометрия аппарата.
Это отказ интервала, не модель автоматического закрытия защитного клапана.

`advance` проходит заданный интервал подшагами. При нелинейном отказе,
нарушении области, границы состояния или ограничений изменения запасов/T
шаг дробится. При достижении `minimum_dt_s` весь вызов возвращает ошибку;
исходный неизменяемый объект состояния остаётся прежним.
Скрытого частичного продвижения времени нет.

`maximum_dt_s` по умолчанию равен `initial_dt_s`: после дробления шаг растёт
к этому пределу. Изменения запасов и температуры ограничиваются через
`max_fractional_inventory_change` и `max_temperature_change_k`.
Это защитные ограничения шага, не оценка локальной ошибки. Метод первого
порядка; необходима проверка сгущением временной сетки для рабочего случая.
Минимальный шаг ограничивает дробление после отказа; последний остаток
отчётного интервала может быть меньше него, если сходится.

Каждый принятый шаг сохраняет P/T, компонентные запасы, энергию, время,
выводимые фазовые доли, потоковые интегралы и невязки. Численные остатки
не компенсируются изменением состава или энергии после решения.

## Конфигурация и запуск

Пример `configs/surface_dynamic_vessel.json` содержит `fluid`, `vessel`,
`initial`, `periods`, необязательный `stepper`.

- `fluid`: массив `components` и полная матрица `binary_interactions`.
- `vessel`: `name`, `volume_m3`, `min_pressure_pa`, `max_pressure_pa`,
  необязательные ограничения состояния, описанные выше.
- `initial`: `pressure_pa`, `temperature_k`, `mole_fractions`, необязательный
  `time_s` (0). Начальные запасы/энергия выводятся из равновесия и объёма.
- Период: `duration_s`, необязательные `feeds` (имя → PT/молярная подача/состав),
  `withdrawals` (порт → mol/s), `heat_w`, `utility_temperature_k`.
- `stepper`: `initial_dt_s` (1), `maximum_dt_s` (начальный шаг),
  `minimum_dt_s` (1e-5), `max_substeps` (10000).

Периодные команды постоянны внутри интервала. Время не сбрасывается между
периодами. Несколько сосудов связываются отдельной [монолитной сетью](DYNAMIC_NETWORK.md).
Пороговое переключение по давлению/объёмной доле жидкости подключается через
[защиты сетевого режима](NETWORK_PROTECTIONS.md), в том числе для одного сосуда.

```bash
python scripts/run_dynamic_vessel.py configs/surface_dynamic_vessel.json --output /tmp/vessel.json --stop-after 1
python scripts/run_dynamic_vessel.py configs/surface_dynamic_vessel.json --checkpoint /tmp/vessel.json --output /tmp/vessel.json
```

Checkpoint хранит текущие физические запасы, время, принятые шаги и интегралы
компонентных/энтальпийных потоков и тепла. Проверяются отпечатки EOS/геометрии/
команд/реализации, контрольная сумма, хронология, накопления и общий баланс
от исходного состояния. CLI записывает результат атомарно. Повреждённый или
несовместимый checkpoint не применяется. Контрольная сумма не цифровая подпись.

## Проверка и область применимости

Независимые пределы: нагрев при постоянном объёме через Cv, адиабатическое
заполнение с работой потока и аналитическое опустошение идеального газа.
Проверяется первый порядок по времени при уменьшении шага, двухфазный
селективный отбор, компонентный/энергетический баланс, давления/фазовые порты,
границы жидкого объёма, дробление шага и точный JSON-перезапуск.

Модель использует те же постоянные Cp/kij и численные ограничения PR, что
термодинамический модуль. Нет водной фазы, проскальзывания, капельного уноса,
отдельных температур фаз, химических реакций, геометрического sizing,
пространственной гидродинамики, связи с пластовым FIM или GPU-реализации.
Это динамический контрольный объём; перенос на реальный сепаратор требует
калибровки термодинамики и проверки равновесного приближения.

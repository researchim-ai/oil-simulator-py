# Динамика приводов соединений

`ConnectionActuator` добавляет конечную скорость и апериодическое запаздывание
коэффициента соединения в динамической PR-сети. Модель связывает команду,
фактическое положение и поток: расход считается при положении нового
временного слоя. Поддерживаются линейные проводимости, однофазные PR-сопла
и двухфазные HEM-сопла. Это CPU-модель; статические насосные станции и
пластовый FIM автоматически динамическими приводами не оснащаются.

## Закон движения

Положение x и команда u лежат в [0,1]. Для постоянной команды на участке:

```
dx/dt = clip((u − x)/tau, −closing_rate, opening_rate), tau > 0
```

При `time_constant_s=0` используется движение с заданной скоростью до
достижения команды. Скорости открытия и закрытия независимы, в 1/s.
При tau > 0 сначала проходит участок ограничения скорости, затем
экспоненциальное приближение к команде. Обе части интегрируются аналитически,
без явного Эйлера, перескока за команду или искусственного мгновенного
присваивания конечного положения. При tau > 0 достижение команды
асимптотическое; отдельная модель посадки на седло не добавлена.

У каждого принятого подшага есть `actuators` с `initial_position`, `command`,
`effective_target`, `mode`, `final_position`. На этом подшаге уравнения потока
используют `final_position`. Интегрирование массы/энергии остаётся обратным
Эйлером и имеет погрешность по времени первого порядка, хотя автономная
траектория привода вычисляется точно. Это не точное интегрирование расхода
по всей траектории. Проверка с уменьшением шага необходима.

`max_position_change` (по умолчанию 0.1) ограничивает движение на подшаге.
Слишком крупный шаг дробится до вычисления EOS. Неудачная проба не меняет
положение, запасы или часы. Ограничение движения помогает разрешать переходный
режим, но не является универсальной оценкой погрешности давления.

## Конфигурация

Полный пример: `configs/surface_vessel_network_actuated.json`.

```json
{
  "actuators": {
    "transfer": {
      "opening_rate_per_s": 0.5,
      "closing_rate_per_s": 0.25,
      "time_constant_s": 0.2,
      "fail_position": 1,
      "max_position_change": 0.1
    }
  },
  "actuator_positions": {"transfer": 0}
}
```

Корневой `actuators` ссылается на существующие соединения. Для каждого привода
обязательно начальное фактическое положение в `actuator_positions`.
Оно не выводится из команды и не предполагается равным единице.
`fail_position` обязателен: выбор fail-open или fail-closed — данные оборудования,
а не решение симулятора о безопасности.

Период задаёт `connection_factors` как команды. Для связи с приводом эта команда
становится целью движения; для связи без привода коэффициент меняется сразу,
как прежде. Отсутствующая команда означает 1. Фактическое положение сохраняется
между периодами. Период также допускает:

```json
{
  "duration_s": 1,
  "connection_factors": {"transfer": 0},
  "actuator_modes": {"transfer": "fail_safe"}
}
```

Режимы:

- `normal`: привод идёт к команде с заданными скоростями и tau.
- `fail_safe`: идёт к явно заданному `fail_position`; команда записывается,
  но не определяет цель движения.
- `stuck`: сохраняет фактическое положение независимо от команды.

Режим задаётся на период; при отсутствии записи действует `normal`.
Отказ не выбирается случайно и не является вероятностной моделью надёжности.
Скорости и tau при отказе используются те же; отдельные характеристики
пружины/аккумулятора следует задавать в будущей специализированной модели.

## Защиты и повторный пуск

`NetworkTrip.close_connections` меняет команду на 0, не фактическое положение.
Во время закрытия вещество продолжает поступать, давление может продолжать
расти. При заклинивании или отказе с fail_position=1 команда закрытия не
создаёт фиктивную изоляцию. Защёлка защиты блокирует команду расписания,
но не отменяет физический отказ привода. Сброс защёлки не сбрасывает положение.

Время события ищется повторными физическими решениями из одного состояния
перед подшагом, включая одно и то же исходное положение привода. Принимается
траектория только до найденного события; остаток интервала интегрируется
с новой командой. Непринятые пробы не добавляют время движения или перенос массы.
Временное разрешение событий сохраняет ограничения основного алгоритма.

## Python, сохранение и воспроизведение

`DynamicVesselNetwork(..., actuators={name: model})` принимает модели приводов.
`advance(..., actuator_positions={name: x}, actuator_modes={name: mode})`
возвращает новые `actuator_positions`; вызывающая сторона передаёт их в
следующий вызов. Входные словари не изменяются. Для расписания задаётся
`initial_actuator_positions` один раз; далее положения сохраняются автоматически.

Checkpoint v5 хранит положения, команды/режимы и историю принятых траекторий.
Помимо checksum и отпечатка параметров/исходников, проверяются непрерывность
положений, соответствие командам с учётом защит, закон движения на каждом
подшаге и конечные положения. Старые отпечатки не принимаются молча.
Контрольная сумма не является криптографической подписью доверенного источника.

```bash
python scripts/run_vessel_network.py configs/surface_vessel_network_actuated.json \
  --output results/actuated.json
python scripts/run_vessel_network.py configs/surface_vessel_network_actuated.json \
  --stop-after 2 --output results/actuated_partial.json
python scripts/run_vessel_network.py configs/surface_vessel_network_actuated.json \
  --checkpoint results/actuated_partial.json --output results/actuated_resumed.json
```

Пример включает теплоёмкость стенок, закрытие по давлению, заклинивание,
отказ в открытом положении, восстановление и повторное срабатывание.
Это демонстрационный сценарий с явными коэффициентами, не паспортная модель.

## Ограничения

Нормированное положение управляет существующим коэффициентом проводимости
или площади сопла. Нелинейную характеристику реального клапана нельзя
заменять этой нормировкой без калибровки. Не включены статика/трение штока,
люфт, позиционер/PID, момент/инерция двигателя, потребление энергии приводом,
ограничения давления питания, задержка/шум датчика, волны давления и гидроудар.
Насосные приводы, распределённые трубные запасы и динамическое сопряжение
этой PR-сети с пластом остаются отдельными задачами. Нет SIL-сертификации.

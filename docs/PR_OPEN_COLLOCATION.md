# Открытые PR-границы и L-устойчивый Radau IIA

`PROpenTransportNetwork.advance(..., integrator="gauss4" | "radau3")`
теперь включает существующие материальные границы в общие стадии PR.
По умолчанию остаётся `backward_euler`. Термодинамика, характеристики
границ и допуски не меняются при выборе нового метода.

## Материальные границы

Повторно используются `PRTransportFeed`, `PRTransportPressurePort`,
`_BoundaryProperties` и `_OpenCoupling`. Поддержка достижимых компонентов
и положительные начальные догадки строятся прежним механизмом; догадки
не добавляются в сохраняемые запасы. Внешние PT-состояния подготавливаются
один раз на интервал, а фактические потоки вычисляются на каждой стадии.

Постоянная подача вносит заданные расходы компонентов, полную энергию и
энтропию. Проверяется допустимое давление принимающего узла. Давленческий
порт использует существующую эмпирическую характеристику `Q = C*opening*ΔP`
в заявленной области перепада не более 5%. При реверсе состав и энтальпия
берутся со стороны внешнего поддерживаемого PT-состояния; при оттоке —
из фактического состояния конечного сосуда. Для одностороннего порта
обратный расход обнуляется прежним правилом.

На каждой стадии используются эти же N/H/S-потоки. Материальные интегралы
вычисляются с весами метода, а не по последнему расходу. По ним проверяются
локальные/глобальные запасы компонентов и энергии и перенос энтропии.
Конечная точка отдельно проверяется по допустимости границы. Стеночные
запасы и обмен с окружением остаются в общем балансе.

Свойства и геометрические ограничения прежние: внешние порты подключаются
к поддерживаемым перемешиваемым сосудам. Это не осевые ghost-состояния
трубы, не конечный патрубок стратифицированного сепаратора и не модель
критического многофазного дросселя. Подача/внешний PT описывают заданные
границы, а не конечную динамическую ёмкость внешнего резервуара.

## Radau IIA: меньше нелинейных решений

Добавлен двухстадийный L-устойчивый `scheme="radau3"`:

```text
A = [[5/12, -1/12],
     [3/4,   1/4 ]]
b = [3/4, 1/4]
c = [1/3, 1]
```

Это третий порядок на гладкой ветви. Последняя строка A совпадает с b,
поэтому конечные P/T, фазовые количества, импульс и Tw берутся из последней
стадии. Отдельная нелинейная конечная проекция не нужна. Как и прежде,
сохраняемая энергия соответствует тому же интегралу потоков; дефект
равновесной энергии независимо проверяется.

На успешную попытку с оценкой полного шага против двух полушагов
приходится **три общих решения вместо шести у Gauss4**. Это не гарантирует
двукратного ускорения: размер совместной системы больше, методы имеют
разный порядок, а число шагов определяется ошибкой. `collocation_nonlinear_solves`
регистрирует реальные вызовы нового Newton, включая отброшенные попытки;
решения резервной ветви backward Euler в этот счётчик не входят.

L-устойчивость проверена на отделённой стеночной моде с `λ*dt=100`:
Radau подавляет её, тогда как Gauss сохраняет значительную амплитуду.
Это проверка численного свойства; адаптивный расчёт продолжает соблюдать
все бюджеты ошибки и физические ограничения. Четвёртый порядок Gauss4
сохранён как отдельная опция.

При отказе стадии или смене фазового состава весь кандидат отбрасывается.
Прежний поиск фаз backward Euler повторяет тот же интервал с той же
материальной границей и проверкой времени. В журнале записаны фактический
метод и причина fallback. Общий бюджет попыток/минимальный шаг сохраняются.
Высокий порядок непосредственно через фазовый переход не заявляется.

## Независимый аудит

Общий scalar-PR/HLLC-аудитор поддерживает оба метода и смешанные журналы.
Для открытого графа `check_pr_open_transport.audit` отдельно восстанавливает
потоки каждого граничного пакета на обеих стадиях и в конечной точке.
Далее проверяются стадийные N/M/E, стенки, все интегралы N/H/S и общий ledger.

Аудитор не вызывает рабочие flash, потоковый оператор или Newton.
Подменённые стадийные потоки, интегралы, идентичность модели, энергия
конечного пакета и тепловые данные отвергаются. Независимая внешняя
проверка в этом наборе охватывает одну и две равновесные PR-фазы; она не
заменяет промысловую калибровку или доказательство глобальной TPD-стабильности.

## API и воспроизведение

```python
report = open_model.advance(initial, 1e-3, integrator="radau3",
                            port_openings={"boundary": 1.0})

from surface import PRCollocation
closed_solver = PRCollocation(physical_model, scheme="radau3")
```

`run_pr_open_transport.py` принимает модель, явные начальные узлы/группы
либо физический checkpoint и последовательность периодов. Устройство
задаётся явно. Результат включает конфигурацию, runtime, хеши исходников,
материальные интегралы и полный журнал. Запись атомарная; неудачный запуск
сохраняет существующий выходной файл. Restart проверяет физическое
состояние, но не воспроизводит автоматически всё старое расписание.

```bash
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 python scripts/run_pr_open_transport.py configs/surface_pr_open_collocation.json --integrator radau3 --output /tmp/pr_open.json
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 python scripts/benchmark_pr_collocation.py --fixture walls --methods gauss4 radau3 --duration 0.02 --output /tmp/pr_radau_walls
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 python scripts/benchmark_pr_open_collocation.py configs/surface_pr_open_collocation.json --output /tmp/pr_open_timing
```

Конфигурация открытого примера содержит шесть узлов, две параллельные трубы,
две PR-фазы, подачу состава, обратный внешний поток и закрытие/открытие
порта. Это короткая численная проверка, не длительный полевой расчёт.
[Результаты и границы измерений](../benchmarks/reports/surface_pr_open_collocation/README.md).

## Следующие адаптеры

Оборудование/роторы, stagnation-трассы, гидростатические грани,
проскальзывание и капельные запасы пока остаются на прежних решателях.
Новый временной адаптер отвергает их вместо упрощения физики. Основная
математика — Torch на устройстве флюида; управляющая логика, аудиты и
экспорт журналов читают данные на CPU. Чистый GPU-бенчмарк здесь не заявлен.

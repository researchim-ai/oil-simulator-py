# Компактные производные давления сборного дерева

`BlackOilProductionNetwork.solve(sources, sensitivity_mode="operator")`
возвращает прежнее физическое решение и компактную
`pressure_linearization` вместо таблиц производных каждого узла по каждому
источнику и каждому открытию. `sensitivity_mode="dense"` остаётся
значением по умолчанию и контрольным представлением.

Размер сериализуемой линеаризации пропорционален числу узлов, источников
и управляемых ветвей. Данные можно передать через JSON и восстановить
без повторного решения PVT/гидравлики:

```python
import torch
from surface.tree_pressure_tangent import TreePressureTangent

result = network.solve(sources, sensitivity_mode="operator")
tangent = TreePressureTangent(result["pressure_linearization"], device="cpu")
dq = torch.zeros(len(tangent.source_names), 3, dtype=torch.float64)
dp = tangent.matvec(dq)
source_gradient = tangent.rmatvec(torch.ones(len(tangent.node_names), dtype=torch.float64))
```

## Уравнения и единицы

На принятом состоянии фиксируются локальные производные существующих
законов труб/арматуры. Для узла n:

- изменение компонентного массового расхода ветви — сумма изменений
  источников её поддерева;
- изменение давления — `a_n dp_parent + b_n · dm_subtree + c_n du_n`;
- давление приёмника задаётся отдельным граничным возмущением.

`a` — производная по выходному давлению; три компонента `b` соответствуют
сохранённым stock-компонентам oil/water/gas в кг/с; `c` — производная по
безразмерному открытию. Результат — Па. Производные получены прежними
локальными решателями, включая их интегрирование по PVT-областям.
Оператор не заменяет физическое замыкание и не приближает трение новым законом.

## Алгоритм без полной таблицы

Итеративный обход формирует непрерывные интервалы поддеревьев.
Их суммы считаются из непересекающихся сбалансированных сегментов.
Вычитание больших префиксных сумм не используется: малая независимая
ветвь не должна теряться рядом с источником в 1e16 раз больше.

Давление распространяется через двоичное объединение предков.
Это исключает Python-рекурсию и линейную цепочку отдельных шагов
распространения давления на глубоких деревьях. Транспонированный оператор
выполняет обратные операции и обратное суммирование сегментов, а не
строит матрицу или новый AD-Якобиан.

Сохранённые Torch-планы имеют верхнюю оценку порядка `N log N`,
а не `N × sources` или `N × valves`. Конкретное число сегментов зависит
от топологии. Промежуточные массивы действия на R правых частей также
зависят от R; не следует передавать единичную матрицу всех источников,
если нужен только один вектор.

## API действий

- `matvec(dq)`: `dq` имеет форму `(sources, 3)` либо `(sources, 3, R)`.
- `apply(dq, receiving_pressure=..., valve_openings=...)` добавляет
  граничное давление и независимые изменения открытий.
- `rmatvec(z)` возвращает градиенты источников для весов давлений
  формы `(nodes,)` либо `(nodes, R)`.
- `adjoint(z)` дополнительно возвращает градиент давления приёмника
  и градиенты открытий.
- `jacobian_rows(names)` явно извлекает выбранные строки, в том числе
  повторяющиеся. Размер выхода и давление RHS ограничены бюджетами;
  попытка неявно получить огромную полную таблицу отвергается.

Входы действий — Torch float64 на устройстве оператора. Конструктор
канонизирует устройство, в том числе `cpu:0` и неиндексированный `cuda`.
После подготовки чистые `matvec/rmatvec` не вызывают `.cpu()`, `.numpy()`
или `.item()`. GPU-производительность в текущем окружении не подтверждена.
Несколько рабочих тензоров могут существовать одновременно; бюджет RHS
не является пределом всей памяти процесса.

## Подключение к FIM

В `simulation.physical_surface_network`:

```json
{"sensitivity_backend": "tree_operator"}
```

Остальные поля существующего описания сети сохраняются. По умолчанию
используется `dense`. Новый путь извлекает только строки привязанных
скважин и повторяет колонки для скважин, соединённых с одним узлом.
При стандартном `well_block_backend=dense` далее используются прежние
B/D, активные ограничения и дополнение Шура. Отдельный opt-in
[`tree_structured`](STRUCTURED_WELL_COUPLING.md) заменяет плотные B/D
действиями по дереву.
Host-оркестрация и пакет обмена CPU/GPU сохраняются: подключение
компактной производной не означает полностью автономный GPU-промысел.

Активный `BlackOilPressureControl` с этой ветвью пока отвергается явно:
его обратная связь требует отдельной производной регулируемого открытия.
Статические открытия и их независимые чувствительности оператор поддерживает.
Обход ограничения через молчаливое исключение регулятора запрещён.

Старый checkpoint без `sensitivity_backend` использует `dense`.
Линеаризация сериализуется обычными данными; в отчёт не записывается
живой объект с графом автодифференцирования.

## Временные произведения при сборке скважинных блоков

`maximum_surface_product_entries=1048576` ограничивает порцию произведения
`wells × perforations × components × reservoir_variables`. Большой путь
собирает B по частям, не создавая дополнительно полный Brate и полное
четырёхмерное произведение. Малые задачи сохраняют прежнюю векторизацию;
опорная единичная матрица переиспользуется.

Это не предел общего расхода памяти: выходные `B_full`, `D_full`, LU,
линейные массивы перфораций и пластовые данные остаются. Производственные
ограничения **128 скважин / 10000 соединений сохраняются для `dense`**.
Отдельный `well_block_backend=tree_structured` исключает скважины по дереву
без этих плотных B/D и использует ресурсный бюджет допуска.
[Метод, проверенные размеры и ограничения](STRUCTURED_WELL_COUPLING.md).

# Поиск наземного ограничения, временной шаг и память сопряжения

## Проверяемый поиск допустимой добычи

`CoupledFacilityControl.search_method` принимает `safeguarded` (по умолчанию)
`facet_safeguarded` или `bisect` (прежний путь для контрольных сравнений).
Все методы сохраняют
исходную сетку `scan_points`, обнаружение разорванных допустимых областей
на этой сетке и исходный абсолютный `fraction_tolerance`.
По умолчанию `commit_method="replay"` повторяет расчёт выбранного
допустимого режима перед приёмкой.

Опциональный `commit_method="state_restore"` сохраняет физическое
состояние лучшей уже рассчитанной допустимой пробы текущего шага и
принимает его после завершения поиска. Все пробы по-прежнему решаются
из одного и того же начала интервала. Восстанавливаются поля и фазовые
флаги, состояния скважин, их накопления и отчёт именно выбранной пробы.
Множитель не округляется, расходы не пересчитываются масштабированием.
Это исключает один повтор Ньютона на каждый ограниченный связанный
шаг ценой одного дополнительного снимка состояния. Снимки заменяются
при улучшении допустимой границы и не переносятся в следующий шаг.

Дополнительный `search_method="facet_safeguarded"` строит секущую по
одному и тому же именованному ограничению на обеих границах скобки.
Это помогает, когда максимум общего остатка на допустимой стороне
принадлежит другому оборудованию и скрывает наклон активного ограничения.
При нескольких кандидатах выбирается ближайшее предсказанное пересечение.
Неизвестные остатки и смена активного ограничения сохраняют защитное
деление пополам. Все новые уставки требуют полного физического решения;
критерий ширины скобки и допустимость оборудования не ослаблены.
Режим опциональный; по умолчанию остаётся `safeguarded`.

В режиме `safeguarded` следующая уставка прогнозируется секущей по
безразмерным запасам до измеренных ограничений. Предыдущая принятая
уставка используется как дополнительная проба, в том числе после смены
команд. Она всегда заново рассчитывается из текущего начала шага.
Нет переноса старого принятого состояния в новую пробу или масштабирования
уже рассчитанной добычи.

`CapacityBracket` хранит рассчитанную допустимую нижнюю и недопустимую
верхнюю границы. Прогноз не является условием сходимости: требуется ширина
интервала не больше исходного допуска. Плохие/неизвестные знаковые данные
вызывают деление пополам; после двух слабых сокращений принудительно
выполняется такое деление. Проба около края интервала отстоит от него
на половину допуска, чтобы секущая не застревала на одном значении.

У газового клапана `GasValveCapacityError` дополнительно передаёт реальные
расход и пропускную способность. Давления, температура, газовые свойства
и формула критического расхода не меняются. Переполнение по-прежнему
отвергается; структурированный остаток нужен только для следующей пробы,
строка ошибки не разбирается и не превращается в физический допуск.
Остальные ошибки оборудования используют прежний безопасный путь.

В отчёте сохраняется `capacity_bracket` с обеими границами, шириной и
допуском. Независимый учётный проверяющий сверяет его с фактическим `trace`
и выбранной допустимой пробой: последней при `replay` либо указанной
в `capacity_commit.solved_trace_index` при `state_restore`.
Численный отказ, плохая PVT и несохранение
материала не становятся допустимым ограничением добычи.

Как и раньше, выбор ветви основан на конечной сетке проб. Это не
доказательство глобального оптимума произвольной немонотонной сети;
неразрешённые острова между пробами нельзя исключить только этим поиском.

## Необязательный контроль изменения дебита

Следующие поля добавляются в существующий `simulation.coupled_facility`:

```json
{
  "control": {"search_method": "safeguarded"},
  "time_control": {
    "rate_relative_tolerance": 0.01,
    "rate_absolute_tolerance_kg_s": 1e-8,
    "startup_step_days": 1.0,
    "safety_factor": 0.9,
    "maximum_growth": 2.0
  }
}
```

Поле `facility` с существующим описанием установки сохраняется.
Поле `time_control` отсутствует по умолчанию. Этот режим не добавляет
дополнительного coarse/fine-решения пласта на каждом шаге.

По фактическим принятым компонентным массовым расходам вычисляется
максимум `0.5 |q_new-q_old| / (abs_tol + rel_tol max(|q_new|,|q_old|))`.
Значение больше единицы отвергает шаг с полным откатом. По принятому
индикатору ограничивается следующий шаг, с запасом и пределом роста;
прежние ограничения FIM по Ньютону/насыщенности остаются действующими.
После изменения операторских команд история расхода сбрасывается:
скачок команды не выдаётся за гладкую временную производную.
Начальный шаг и первый шаг нового режима ограничены `startup_step_days`.

Это **эвристика изменения конечного дебита**, а не строгая оценка локальной
ошибки FIM, не доказательство точности давления/насыщенностей и не решение
акустического пуска. Точность конечных полей и накопленной добычи нужно
подтверждать отдельным уточнением времени. Независимый учётный аудит
заново считает индикатор из принятых скважинных потоков и проверяет
границы событий. Короткий отчётный хвост не обязан ограничивать рост
шага в следующем интервале: для clipped-пробы предел роста отделён
от оценки изменения расхода.

`compare_fim_facility_forecast.py --allow-numerical-policy` позволяет
сравнить один физический запрос при различии `time_control`,
`control.search_method` и `physical_surface_network.sensitivity_backend`. Физические модели, прочие настройки ограничителя,
операторское расписание и горизонт обязаны совпадать. По умолчанию
сравнение конфигураций остаётся строгим.

## Ограниченные временные блоки дополнения Шура

`FullWellSchur.maximum_rhs_entries=1048576` ограничивает объём одного
временного RHS-блока. Небольшие задачи сохраняют прежний общий solve.
Большой путь агрегирует перфорации по порциям ячеек, решает блоки тем же
LU и сохраняет только необходимые локальные члены. Несколько перфораций,
в том числе разных скважин, в одной ячейке суммируются до выбора
локального члена. Действие B на вектор также разбивается на порции.

Порядок соединений и префиксы групп кешируются только для неизменной
топологии. Внутри Krylov-действия нет новой выгрузки списка перфораций
на CPU. При float64 один блок из указанного числа значений занимает
до 8 MiB; несколько временных блоков могут существовать одновременно.
Это не предел всей памяти процесса.

Для производных давления самой сборной сети теперь есть отдельный
[компактный оператор](TREE_PRESSURE_TANGENT.md), подключаемый к FIM.
Он не заменяет исключение общего скважинного блока.

Плотные `D_full` и входной `B_full` остаются. Производственные ограничения
128 скважин / 10000 соединений не сняты. Для действительно большого
числа скважин ещё нужны разреженная либо матрично-свободная модель общего
скважинно-наземного блока и её предобусловливатель. Изменение порций не
подменяет эту архитектурную работу. Проверка на 192 скважинах относится
к синтетической алгебре исключения, не к полному физическому расчёту
такого числа скважин.

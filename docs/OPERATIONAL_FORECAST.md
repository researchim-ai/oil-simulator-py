# Эксплуатационный прогноз: пласт и установившаяся наземная сеть

Для длительного прогноза используется существующий `coupled_facility`:
black-oil FIM → скважины ↔ установившаяся сборная сеть → сепарация →
водяная сеть и газовый экспорт. Собственная акустика сантиметровых PR-ячеек
не включается в каждый шаг прогноза. Подробный PR-граф сохраняется для
отдельных быстрых переходных задач; автоматически эти модели не подменяются.

## Что действительно связано

`SurfaceCoupledBlackOilWells` включает противодавление физической сборной
сети и перекрёстные производные скважин в FIM. `FacilityCoupledFIM`
проверяет фактическую компонентную добычу на ограничениях сепараторов,
водяной сети и газового экспорта. При нарушении ограничений повторно
решается тот же пластовый шаг с общим множителем уставок добывающих.
Выбранный режим заново рассчитывается и только затем принимается;
готовая добыча не масштабируется задним числом. Неуспех возвращает
физическое состояние и накопления к началу пробного шага.

Это существующее внешнее сопряжение по общему ограничителю добычи,
а не новый монолитный Якобиан всего промысла. Первый допустимый вариант
требует одного пластового решения; ограниченный режим может потребовать
много проб. Время проб необходимо учитывать в полном измерении.

## Расписание эксплуатации

`run_fim_blackoil_surface.run_case(..., facility_schedule=[...])`
поддерживает события с `time_days` и `controls`. Время — от начала
запуска; события строго возрастают и лежат в `[0, days)`.
Ни один отчётный интервал и принятый пластовый подшаг не пересекают
момент команды. После события адаптация шага продолжается существующим
интегратором `Simulator.run_step`.

Каждое событие полностью заменяет операторские команды:

```json
[
  {"time_days": 0, "controls": {}},
  {"time_days": 10, "controls": {"gas_valve_max_opening": 0.8}},
  {"time_days": 20, "controls": {}}
]
```

Пустой словарь возвращает настройки оборудования из модели. Набор
поддержанных команд определяется `FacilityCoupledFIM.control_fields`;
произвольное масштабирование подачи запрещено. События применяются
на границе интервала; мгновенная переходная реакция оборудования
между установившимися состояниями в этом режиме не разрешается.

`report_days` задаёт максимальную длину запрашиваемого отчётного
интервала; события дополнительно разрезают его. Без явно заданного
`max_time_step_days` этот интервал также ограничивает шаг FIM согласно
существующей политике симулятора. Для точности во времени нужны
сравнение с более частыми шагами и согласованные допуски, а не только CNV/MB.

## Запуск и проверка

Из корня проекта; каталог результата должен отсутствовать:

```bash
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=src:scripts python scripts/run_fim_facility_forecast.py --schedule configs/fim_facility_forecast_schedule.json --days 30 --report-days 5 --device cpu --output /tmp/forecast_month
PYTHONPATH=src:scripts python scripts/check_fim_facility_forecast.py /tmp/forecast_month/trajectory.json.gz
```

Для CUDA требуется явно выбранный `CUDA_VISIBLE_DEVICES`. Этот драйвер
не превращает существующую CPU-арматуру и весь facility-код в GPU-код.
CPU-замеры нельзя объявлять подтверждением CUDA-производительности.

Протокол сохраняет исходные хеши, расписание и длительность. Траектория
с фактическими расходами, уставками, командами, балансами и статистикой
адаптации записывается до независимого учётного аудита. Только полный
прошедший проверку расчёт получает `summary.json` со статусом `complete`.
Незавершённая серия остаётся помеченной `incomplete`.

Проверяющий независимо суммирует материал принятых скважинных потоков,
подачу и экспорт; сверяет расписание, часы, применённые ограничения и
сквозную убыль запасов. Он не запускает решатель и не подменяет
независимую проверку физических корреляций/PVT. Массовый бюджет аудита
не меняет критерии Ньютона или интегратора.

## Область применимости существующего режима

Сборная сеть — дерево с однородной black-oil моделью без проскальзывания,
одной PVT-областью и ограничениями направления/геометрии труб.
Текущий facility-драйвер поддерживает активные добывающие скважины
с положительными уставками дебита; нагнетание и полный останов скважин
этим сценарием не квалифицированы. Газовый экспорт использует существующую
модель сухого идеального газа. Нефть учитывается в продуктах сепарации;
произвольная гидравлическая сеть её дальнейшего экспорта здесь не решается.
Это не эквивалент всей подробной PR-наземной сети.

Следующие расширения: проверка временной точности и масштабирования,
нефтяная экспортная и нагнетательная ветви, более общий состав/термодинамика
и топология, затем согласованное подключение выбранной эксплуатационной
динамики. Многолетний Norne с полной наземной инфраструктурой остаётся
отдельным приёмочным сценарием.


## Границы PVT в пробах мощности

Если при заданном пробном расходе требуемое давление конца трубы выходит
за пределы общей PVT-области, `BlackOilPipe` выдаёт отдельное
`PipePressureCoverageError`. Внешний facility-поиск отмечает только эту
пробу как недопустимую и может проверить меньшую уставку. Запасы и
накопленная добыча отвергнутой пробы откатываются. Путь отражается в
`trace` с причиной `pipe_pressure_coverage`.

Это ограничение области модели, а не доказанное физическое запирание
потока. Свойства не экстраполируются, таблица не расширяется молча.
Обычные ошибки PVT (`PropertyModelError`) по-прежнему прерывают расчёт;
исчерпание численного бюджета поиска давления относится к
`HydraulicConvergenceError`, а не к выходу за PVT-область.


## Подтверждённый сценарий и следующие расширения

Для маленького связанного пласта проверен месяц с ограничением и
восстановлением газового экспорта. Сравнение 5-суточных интервалов с
суточными дало 0,513% по накопленной компонентной добыче и 148 Па по
конечному давлению. 10-суточный вариант не прошёл заранее заданный
бюджет добычи 1%. По умолчанию драйвер запрашивает 5 суток;
это начальная настройка, требующая проверки для конкретной модели.

Отдельный месячный запуск на 32×32×1 ячеек завершён с проверкой балансов.
Это ограниченный связанный пример с двумя скважинами, не подтверждение
скорости полного Norne или произвольной сети. Измерения и полные
траектории — [в протоколе](../benchmarks/reports/surface_operational_forecast/README.md).


## Ускоренный ограничитель и опциональная адаптация времени

По умолчанию `control.search_method=safeguarded` выбирает пробы по
измеренным запасам до ограничений, с возвратом к делению пополам.
Контрольный `bisect` сохранён. Вычисленная допустимая/недопустимая
скобка и абсолютный допуск проверяются независимо по trace.

Необязательный `coupled_facility.time_control` ограничивает изменение
фактических компонентных дебитов и старт после операторского события.
Это дополнение к существующему управлению шагом FIM, не строгая оценка
его ошибки. Оно может дать меньшую погрешность ценой большего числа
шагов; отсутствие поля сохраняет обычную временную политику.
[Подробная постановка](FACILITY_SEARCH_SCALING.md).
[Актуальная серия скорости и точности](../benchmarks/reports/surface_capacity_search/README.md).


## Представление чувствительностей сборной сети

По умолчанию используется плотная таблица `sensitivity_backend=dense`.
Опция `physical_surface_network.sensitivity_backend=tree_operator`
заменяет её компактным оператором и извлекает только нужные производные
скважин. Физическая модель и интегратор не меняются; при стандартном
`well_block_backend=dense` полные B/D сохраняются. Опциональный
`well_block_backend=tree_structured` исключает их по структуре дерева
и допускает больше 128 скважин по ресурсному бюджету.
[Метод и квалификация](STRUCTURED_WELL_COUPLING.md). Активный регулятор давления требует отдельного расширения,
поэтому такой набор опций явно отвергается.
[Единицы, API и область подтверждения](TREE_PRESSURE_TANGENT.md).

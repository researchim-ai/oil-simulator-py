# Структурированное исключение скважин сборного дерева

## Включение и область модели

Для black-oil FIM задайте в `simulation.physical_surface_network`:

```json
{
  "well_block_backend": "tree_structured",
  "structured_memory_budget_bytes": 268435456
}
```

Это дополнительные поля существующей конфигурации с `network` и `well_nodes`.
`well_block_backend=dense` остаётся значением по умолчанию, включая старые
checkpoint без этого атрибута. В структурированном варианте пропущенный
`sensitivity_backend` означает `tree_operator`; явно заданный `dense` отвергается.

Меняется представление линейной системы, а не физика или допуски Ньютона.
Поддержана существующая область адаптера: активные добывающие скважины с
положительными ограничениями дебита, переходом на давление сети/предел BHP,
перфорациями на опорной отметке BHP, согласованными PVT и плотностями.
Ограничения самого `homogeneous_blackoil_tree` сохраняются: направленное
сборное дерево с одним приёмником, без реверса, нулевых расходов и разделения
потоков. Активный регулятор давления пока несовместим с `tree_operator`;
статические открытия допустимы. Этот блок не добавляет MSW, группы, кольца,
нагнетание или распределённую динамику наземных запасов.

## Линейная система

Для замороженной линеаризации каждой связи дерева:

```
dp_n = a_n dp_parent + b_n · dm_subtree
```

Потоки скважин дают `dm_w = U_w dp_w + dm_field,w`. У поверхностной строки
`dp_w - dp_node(w) = rhs_w`; у дебитной строки собственная диагональ,
у строки предела BHP — единичная. `TreeWellSystem` хранит производные
перфораций и локальные коэффициенты дерева. Действия B и D вычисляются
через агрегирование по связям, без `B_full`, `D_full` и скважинной единичной
матрицы. Пакет обратной передачи в сборку содержит четыре скаляра на скважину,
а не полную таблицу производных скважина×скважина×компонент.

Исключение поддеревьев снизу вверх использует компонентную проводимость H:

```
pivot_n = 1 - b_n · H_n
A_n = a_n / pivot_n
Y_n = H_n A_n
```

Известная часть правой части проходит вверх; давления восстанавливаются вниз.
На одном уровне узлы обрабатываются тензорным пакетом PyTorch. Хранилище
исключения линейно по числу узлов и перфораций; компактный оператор давления
дополнительно хранит стадии композиции предков. Число последовательных
проходов исключения зависит от глубины дерева: глубокая цепочка требует
больше запусков, чем широкое мелкое дерево.

Для локальной части CPR используется приближённая диагональ D и производная
собственной перфорации. Пригодность диагонали проверяется относительно
масштаба её слагаемых. Полная поправка Шура вычитает включённую локальную
часть и возвращает `-C D^-1 B`; поэтому приближение предобуславливателя
не заменяет полный оператор уравнений.

## Отказы и точность

Относительно малый/нечисловой локальный pivot не маскируется. Допускается
ограниченный матрично-свободный GMRES только после достаточного сертификата
невырожденности: строгого взвешенного диагонального преобладания по верхней
оценке модулей коэффициентов. Сертификат достаточный, не необходимый:
некоторые обратимые системы будут явно отклонены. Плотного fallback нет.
Сингулярный блок нельзя принять только потому, что его совместимая правая
часть дала малую невязку.

Каждое решение D проверяется по исходному действию D отдельно в каждой
строке: относительная граница `1e-10`, абсолютная `1e-13` для дебитной
и `1e-7` для строки давления, в единицах соответствующего уравнения.
Отказ возвращает нечисловую поправку и флаг ошибки существующему FIM;
шаг не принимается. На обычном пути используется уже существующий пакет
проверки факторизации FIM, без нового host-read внутри каждого Krylov-действия.
Это не устраняет host-оркестрацию нелинейной сборной сети.

## Ресурсные границы

Пределы **128 скважин / 10000 соединений сохраняются у `dense`**, но не
применяются к `tree_structured`. Вместо них действует положительный целый
`structured_memory_budget_bytes` (по умолчанию 256 MiB). Оценка допуска:

```
8 * (nodes * (64 + 16 * max(1, nodes.bit_length()))
     + 32 * wells + 48 * perforations)
```

Это оценка структурированной линеаризации, не строгая граница полной памяти
процесса, пласта, AMG, отчёта или нелинейного решателя сети. Не следует
обещать произвольное число скважин только по прохождению этого фильтра.
CUDA, общая GPU-память, многолетний Norne и много-GPU этим этапом не
квалифицированы: NVIDIA-драйвер текущего окружения недоступен.

## Проверка

Сравниваются Bx, D, обратное действие, полная поправка Шура, правая часть и
восстановление BHP с независимым малым плотным эталоном; проверяются
смешанные режимы, повторные привязки узлов/ячеек, restart и отказы.
Большая алгебраическая задача сравнивается с аналитическим обращением
диагонали плюс одно ранговое возмущение, без выделения плотного эталона.
Физические FIM-прогоны отдельно проверяют фактические скважинные расходы,
приёмник и интегральные балансы компонентов. Это проверка представления
уравнений и учёта массы, не экспериментальная валидация корреляций/PVT.

[Конфигурации, траектории и измерения](../benchmarks/reports/surface_structured_wells/README.md).

Пакетный нелинейный расчёт труб выбирается отдельно через
[`network.hydraulic_backend=torch_batch`](BATCHED_BLACKOIL_HYDRAULICS.md);
само структурированное исключение не меняет гидравлическую корреляцию.

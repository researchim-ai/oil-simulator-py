# Конечные тепловые контуры в общем PR-графе

`PRHeatLink(name, source, target, conductance_w_k)` связывает температуры
двух конечных объёмов. В `PREquilibriumTransportNetwork.heat_links` доступны
сосуды и трубные ячейки. В `PRGravityTransportNetwork.heat_links` — также
гравитационные колонны. Связи решаются одновременно с PR-фазами, импульсом
и энергией обеих сторон, без внешней итерации по переданному теплу.

Физическое замыкание: `Q=UA*(T_source-T_target)`.
Один и тот же Q вычитается из источника и добавляется получателю.
Компоненты и импульс через тепловую связь не проходят. Тепловая связь
не объединяет наборы активных компонентов разных материальных контуров.
Реверс тепла определяется текущей разностью температур; источник не обязан
оставаться более горячим. Несколько контактов могут образовывать тепловую сеть.

Производство энтропии на контакте равно
`UA*(T_source-T_target)^2/(T_source*T_target)` и неотрицательно.
При сопряжении колонн с трубами учтены энтропийные потоки на границах
подсистем и производство на тепловом контакте. Их сумма соответствует
изменению энтропии всей замкнутой системы. Независимый проверяющий инструмент
пересчитывает глобальную энтропию по PR-состояниям и профилям колонн.

Имена тепловых и материальных связей уникальны. `openings` изолирует обе
разновидности связей; закрытый тепловой контакт имеет строго нулевой Q.
Разреженный Якобиан содержит связь энергетических строк с переменными
обеих сторон. Checkpoint сохраняет состояния конечных контуров и идентичность
их полной модели; подставной бесконечный тепловой резервуар не требуется.

## Примеры и проверки

`configs/surface_pr_counterflow_heat_exchanger.json` содержит два отдельных
материальных контура с разными чистыми компонентами и распределёнными
противоточными тепловыми контактами. Расписание отключает теплообмен
и включает его вновь. Запуск:

`configs/surface_pr_finite_reboiler.json` отдельно задаёт тепловую связь
конечного утилитного объёма с двухфазной гравитационной колонной.

```bash
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 python scripts/run_pr_equilibrium_transport.py configs/surface_pr_counterflow_heat_exchanger.json --output results/pr_heat_links/counterflow.json
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 python scripts/check_pr_equilibrium_transport.py configs/surface_pr_counterflow_heat_exchanger.json results/pr_heat_links/counterflow.json
```

Тесты проверяют независимый предел двух конечных теплоёмкостей, отсутствие
переноса компонентов, положительную энтропию, изоляцию, restart, производные
и разреженное решение. Связанный пример конечных холодного и горячего
контуров конденсирует процессную среду из одной фазы в две и затем полностью
испаряет её без внешнего теплового источника. Колонна–сосуд и колонна–колонна
проверяются независимым расчётом свойств и балансов.

Для гравитационной колонны проверяется также последовательность двухфазное
состояние → однофазное → двухфазное при нагреве и охлаждении от конечных
контуров. Ограниченный температурный предиктор выбирает начальную фазовую
ветвь по PT/UV-пробам вне Ньютона. Его температура лежит между исходными
температурами соседних тел; он не подменяет старые N/E или решаемый тепловой
поток. На обычных малых тепловых шагах дополнительные пробы не выполняются.
Крупные шаги в тесте проверяют смену ветви и балансы, а не точность траектории
по времени; временная погрешность проверяется адаптивным интегратором.

Полная функциональная матрица:

```bash
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 python scripts/validate_pr_surface_matrix.py --device cpu --jobs 4 --timeout-s 900 --output results/pr_surface_matrix/cpu
```

Она прогоняет девятнадцать конфигураций, независимо проверяет каждый отчёт и
сохраняет хеши исходников и конфигураций. Для CUDA требуется явно выбрать
устройство через `CUDA_VISIBLE_DEVICES` и передать `--device cuda`.
Время этого запуска включает инициализацию и проверку; оно не является
показателем производительности крупной наземной сети.

## Область применимости

Контакт имеет заданную UA и нулевую собственную теплоёмкость стенки.
Конечные теплоёмкости жидкостей, газа и имеющихся стенок объёмов сохраняются.
Это замыкание для теплообмена, не расчёт конструкции аппарата: сопротивления
загрязнений, температурная зависимость UA, тепловые напряжения и теплоёмкость
разделяющей стенки требуют дополнительных данных и состояний.
Положительный энтропийный баланс не подтверждает коэффициенты теплоотдачи
реального оборудования. Унос капель и конечная скорость сепарации этим
тепловым блоком не моделируются.

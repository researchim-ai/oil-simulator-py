# Механика вращающегося привода

`RotatingDrive` — отдельный CPU-блок механики вала с инерцией. Он дополняет
существующие статические характеристики насосов, но пока не заменяет
совместное решение динамической сети, ротора и регулятора.

## Уравнение и энергия

При постоянных на интервале моментах двигателя и нагрузки:

```
J dω/dt = τ_motor − τ_load − b ω
K = J ω²/2
```

J задаётся в kg m², ω в rad/s, моменты в N m, b в N m s.
Нагрузка неотрицательна. Момент двигателя может быть положительным
(разгон) или отрицательным (рекуперативное торможение).

Траектория интегрируется аналитически. Для b>0 скорость экспоненциально
стремится к (τ_motor−τ_load)/b, для b=0 ускорение постоянно. Вычисляются
интеграл скорости (угол) и интеграл квадрата скорости. Вблизи b dt/J=0
используются устойчивые ряды, а не разность почти равных экспонент.

```
W_motor = τ_motor ∫ω dt
W_load = τ_load ∫ω dt
Q_drag = b ∫ω² dt
ΔK = W_motor − W_load − Q_drag
```

Электрическая энергия положительна при потреблении и отрицательна при
возврате в сеть. В первом случае W_electric=W_motor/η_motor, во втором
W_electric=η_regen W_motor. Потери двигателя Q_motor=W_electric−W_motor
неотрицательны. При η_regen=0 торможение полностью диссипативное;
Q_motor обозначает суммарные потери моторного/тормозного тракта.
Отдельно проверяются механический и полный балансы:

```
W_electric = ΔK + W_load + Q_drag + Q_motor
```

Вариант однонаправленный: при достижении ω=0 аналитически определяется
момент остановки, затем идеальный удерживающий упор не допускает обратного
вращения. Его импульс записывается отдельно, работа при покое нулевая.
Это явно выбранное ограничение механики, не модель свободного обратного
вращения насоса или турбинного режима.

## Ограничения привода

Требуются J, максимальная скорость, максимальные двигательный и тормозной
моменты. Дополнительно задаются вязкое сопротивление, КПД двигателя и
рекуперации, пределы электрического потребления/экспорта.

Превышение предела возвращает `EquipmentOperatingError`. Команда не
обрезается молча. Предел мощности проверяется на максимальной скорости
всей монотонной траектории, а не по средней мощности интервала. При
торможении это может быть начальная скорость, даже если конечная равна нулю.

Моторная модель идеализирована: нет тока, напряжения, тепловой динамики,
потерь холостого хода/заблокированного ротора или частотного преобразователя.
При покое работа нулевая; это не утверждение о нулевом токе реального мотора.
Паспортные данные не предоставлены; пример не является калибровкой оборудования.

## Связь с существующими насосными характеристиками

`pump_shaft_load` вычисляет пробу нагрузки по имеющемуся `Pump`:
скорость масштабируется относительно явно заданной номинальной скорости,
используются существующие напор/КПД/NPSH и ограничения мощности/расхода.
Момент нагрузки равен мощности на валу, делённой на ω.

При ω=0 допустим только нулевой расход. Обратный поток и турбинный режим
не поддерживаются этим адаптером. Исходный объект насоса не изменяется.
Возврат пробы нагрузки не означает, что давление и расход сети уже
согласованы с динамикой ротора. Изменяющуюся нагрузку нужно решать совместно
или уточнять по времени; `advance` считает её постоянной на интервале.
Тепло двигателя/трения не добавляется автоматически в энтальпию флюида.

## Запуск и перезапуск

Пример `configs/surface_rotating_drive.json`: разгон, выбег, торможение
до покоя. Это синтетический пример с явно заданными параметрами.

```bash
python scripts/run_rotating_drive.py configs/surface_rotating_drive.json --output results/drive/full.json
python scripts/run_rotating_drive.py configs/surface_rotating_drive.json --stop-after 1 --output results/drive/partial.json
python scripts/run_rotating_drive.py configs/surface_rotating_drive.json --checkpoint results/drive/partial.json --output results/drive/resumed.json
cmp results/drive/full.json results/drive/resumed.json
```

`RotorState` хранит скорость, время и идентификатор модели. Расписание
добавляет checksum, отпечаток параметров/команд/исходников и журнал работ.
При продолжении дешёвая аналитическая история воспроизводится заново:
проверяются все поля работ и конечное состояние. Изменение модели,
расписания или исходников не принимается молча. CLI записывает JSON атомарно.

## Проверки и следующий этап

Независимые проверки: постоянное ускорение/работа, экспоненциальный выбег,
интеграл потерь против квадратуры, событие остановки, рекуперация, пределы
пиковой мощности, разбиение интервала и restart, насосные законы подобия.
Протокол: `reports/validation/2026-11-02/ROTATING_DRIVE_VALIDATION.md`.

Связанный [блок насоса, вала и PID](DYNAMIC_PUMP.md) теперь реализован
отдельно для одного насоса с квазистационарной жидкостной сетью.
Для сухого идеального газа реализован отдельный [компрессорный блок](COMPRESSOR_TRAIN.md)
с картой и антипомпажным контуром. Для параллельных насосов реализована
[динамическая станция](DYNAMIC_STATION.md). Компрессорные группы, реальные карты,
PR/многофазность, связь с FIM и GPU остаются отдельными задачами.

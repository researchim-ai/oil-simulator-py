# Пространственная PR-модель с раздельным движением фаз

`PRMultifluidPipe` решает компоненты, импульс и полную энергию каждой
из двух или трёх фаз, уравнения объёмных долей и локальный межфазный обмен.
Фазы имеют собственные P/T/скорости; состав каждой фазы переносится по трубе
и может различаться между ячейками. Ранее отсутствовавший компонент может
поступить в ячейку без добавления фиктивного начального запаса.

## Реализованная область

Горизонтальная прямая труба постоянного диаметра, в том числе с
неравномерными длинами ячеек; периодические или закрытые торцы.
Все фазы присутствуют во всех ячейках в заданной области
`minimum_phase_fraction`. Нулевой фазовый запас не заменяется малой массой.
Межфазного переноса массы и рождения/исчезновения фаз пока нет.

Этот тип трубы подключён к конечным узлам через `PRMultifluidNetwork`,
включая наклонные ветви, но не заменяет профильные трубы `PRProfileGraphNetwork`.
Переменное сечение внутри инерционной ячейки, механистическая карта режимов
и пространственный перенос с изменяемым числом фаз остаются незавершёнными.
Механические корни PR задаёт
пользователь; химическое равновесие и газовая идентичность из плотности
автоматически не выводятся.

## Уравнения переноса

Каждая фаза хранит вектор молей N_k, объём V_k, импульс M_k и энергию
E_k = U_k + m_k u_k²/2. EOS связывает N_k, V_k, p_k и T_k.
Для плотностей по полному объёму ячейки:

```text
Q_k = (N_k/V, m_k u_k/V, E_k/V)
F_k = (N_k u_k/V, m_k u_k²/V + alpha_k p_k,
       (E_k/V + alpha_k p_k) u_k).
```

Фаза 0 — явно выбранная reference phase. Её скорость u_0 переносит
объёмные доли остальных фаз. Для двух фаз это выбор межфазных величин
uI = u_0, pI = p_1 в постановке Baer–Nunziato:
[Zanotti–Dumbser, описание модели и path-conservative схем](https://link.springer.com/article/10.1186/s40668-015-0014-x).
Здесь используется собственная схема первого порядка, не высокопорядковая ADER.

Для трёх фаз задано явное звёздное расширение: каждая фаза k>0 взаимодействует
с reference phase через p_k и u_0. Неконсервативные фазовые члены:

```text
B_M,k dQ = -p_k d(alpha_k),      k>0
B_E,k dQ = -p_k u_0 d(alpha_k),  k>0
B_M,0 = -sum(B_M,k), B_E,0 = -sum(B_E,k)
alpha_k,t + u_0 alpha_k,x = 0,   k>0.
```

Компоненты не имеют межфазного источника. Поэтому сохраняется глобальный
компонентный запас каждой фазы, а не только сумма по фазам. Межфазные
импульсные и энергетические члены взаимно сокращаются в суммарных балансах.
Трёхфазное расширение — определённая здесь модель; универсальная
гиперболичность всех её возможных состояний не заявляется.

## Пространственная и временная схемы

На грани используются path-conservative колебания Rusanov:

```text
Dminus = (F_R-F_L + integral(B dQ) - a (Q_R-Q_L))/2
Dplus  = (F_R-F_L + integral(B dQ) + a (Q_R-Q_L))/2.
```

Путь линеен по долям, давлениям и скоростям. Произведение p_k*u_0 вдоль
пути квадратично и интегрируется точно; произведение средних вместо среднего
произведения не используется. По времени — Backward Euler с общим
разреженным Torch-Якобианом всех ячеек. В невязке нет flash или вложенного
итерационного решателя. Энергетические строки согласованы с компонентными
строками для уменьшения зависимости численной ошибки от калорического нуля.

Это диффузионная схема первого порядка. Она сохраняет равновесные давление,
температуру и скорость при переносе чистого межфазного контакта, но размывает
сам профиль долей. Аналитический множитель дискретного Fourier-контакта и
измельчение сетки проверяются тестами. Точная фиксация неподвижной резкой
границы и высокопорядковый contact-resolving solver не реализованы.

`wave_speed_bound_m_s` должен покрывать |u_k|+c_k на выбранных механических
ветвях EOS. Проверяется область долей и исключается близкий акустический
резонанс reference-скорости с другой фазой. Эти проверки не заменяют
полный анализ гиперболичности или экспериментальную валидацию.

Жёсткие торцы используют отражённые скорости и локальные фазовые
акустические оценки. Фазовые массовые и энергетические потоки равны нулю;
опора воспринимает импульс. Неположительная расчётная тяга стенки отклоняется;
кавитационный режим этим граничным условием не моделируется.

## Сопряжение с локальными источниками

Полный шаг — композиция Lie первого порядка:
`Phi_source(dt) Phi_transport(dt)`. После пространственного переноса каждая
ячейка решает [PR-межфазную релаксацию](PR_INTERPHASE_RELAXATION.md) с теми же
фактическими компонентами, импульсами и энергиями. Состояния и обмены обоих
этапов сохраняются. Оба подоператора покрывают один dt; физические часы
продвигаются один раз. `source_inputs` явно фиксирует стартовый clock
подоператора и перенесённые запасы.

`sources` содержит модель обмена для каждой ячейки. Её коэффициенты
интегральные: при измельчении сетки их нужно масштабировать с соответствующим
контактным объёмом/площадью. Автоматические корреляции площади интерфейса,
вязкого сопротивления и смены режима не подставляются.

`advance` сравнивает полный и два половинных шага. Ошибка контролируется по
P/T/объёмам, скоростям и каждому компонентному запасу. Отказ любого источника
или пространственного решения не публикует частичный результат. Проверяются
компоненты, энергия, импульс опор и неубывание энтропии. Это проверка принятого
решения, а не доказательство entropy-stability схемы для произвольных ударных волн.

## CPU/CUDA и воспроизведение

EOS и пространственная сборка пакетные. Внутри Ньютона нет поячеечных
CPU-копирований; скаляры источников и checkpoints остаются API на стороне
host. Построение и выгрузка пространственного состояния используют целые
массивы. Большие сетки используют соседний разреженный stencil.
Масштабирование полного source-этапа на крупные сетки ещё требует измерений.

```sh
PYTHONPATH=src python scripts/run_pr_multifluid_pipe.py \
  configs/surface_pr_multifluid_counterflow.json --output /tmp/multifluid.json
PYTHONPATH=src python scripts/check_pr_multifluid_pipe.py \
  configs/surface_pr_multifluid_counterflow.json /tmp/multifluid.json
```

Дополнительные примеры: `surface_pr_multifluid_three_phase.json`,
`surface_pr_multifluid_walls.json`. Условия задаются через `initial.cells`
или полное `initial.state`. Runner фиксирует исходники.

Независимый NumPy-аудит использует скалярный PR, Gaussian-интегрирование
межфазного пути и высокоточный аудит каждого локального источника. Он проверяет
локальные фазовые компоненты/импульсы/энергии, доли, грани, стенки, обе стадии,
общие часы и restart. Тесты запрещают вызовы runtime-физики из аудита.
Это численная верификация ограниченной пространственной модели; сравнения с
промысловыми замерами и промышленными многофазными трубными пакетами пока нет.

## Конечные узлы и разветвления

`PRMultifluidNetwork` соединяет эти фазовые ячейки в замкнутый горизонтальный
граф. У каждого узла — собственный конечный объём, фазовые компоненты,
давления и температуры. Транспорт всех ветвей решается одним Ньютоном;
локальные источники сохраняют прежнюю композицию подшагов.

В `pr_multifluid_network_v1` задаются `cell_names`, `volumes_m3`, `sources`,
`supported_nodes` и `faces`. Грань содержит `source`, `target`, `area_m2` и
горизонтальный единичный вектор `direction`. Инерционная ячейка имеет один
вход и один выход с одинаковыми площадями и направлениями. Поворот или
разветвление проходит через конечный опорный узел. Его скорости равны нулю:
опоры принимают импульс, но энергия входящего потока остаётся в жидкости.
Учитываются и реакции неподвижных стенок. Поэтому импульс и его невязка
выводятся **трёхкомпонентными векторами**, а не суммой скаляров разных ветвей.
Порядок невязок: компоненты, энергия, импульс X/Y/Z.

Сборка граней в узлы использует заранее подготовленные индексы и gather/sum
на устройстве, без атомарного накопления и без переноса состояния на CPU
внутри вычисления невязки. Разреженный Якобиан следует реальным связям графа.
`PRMultifluidPipeState` сохраняет общий restart; конфигурация и топология
входят в идентификатор модели. Пример запуска:

```bash
PYTHONPATH=src python scripts/run_pr_multifluid_pipe.py \
  configs/surface_pr_multifluid_network.json --output /tmp/multifluid-network.json
```

Проверки `tests/test_surface_pr_multifluid_network.py` охватывают конечные
узлы, разветвление с поворотами, покой, полный/разреженный Якобиан,
двух-/трёхфазный адаптивный restart. Независимый NumPy-пересчёт использует
скалярную PR-EOS и квадратуру пути из `reference_pr_multifluid_network.py`.

Это отдельная неравновесная сеть: оборудование, профили сепараторов и FIM
из прежнего равновесного графа автоматически в неё не переносятся. Внешние
границы, перенос между фазами, появление/исчезновение фаз и калиброванные
режимные замыкания пока отсутствуют. Три общих физических блока проекта
целиком не закрыты.


## Гравитация и энергия наклонных ветвей

`pr_multifluid_network_v2` дополнительно задаёт `elevations_m` в порядке
`cell_names` и неотрицательное `gravity_m_s2`. Высота положительна вверх;
векторы `direction` теперь могут иметь вертикальную составляющую. Исходная
горизонтальная схема v1 и её идентификаторы сохранены.

Длина инерционной ячейки — её объём, делённый на площадь прохода. Каждая
грань находится на половине длины от центра инерционной ячейки и на отметке
центра опорного узла. Обе стороны должны задавать одну физическую отметку;
несовместимая геометрия отклоняется до расчёта. Опорный узел здесь остаётся
сосредоточенным запасом, а не распределённым гравитационным сепаратором.

В уравнение фазового импульса включён вес вдоль оси трубы. Давление
экстраполируется гидростатически к реальной отметке порта с плотностью
соответствующей фазы. Исправление давления внесено и в поток энергии.
Это устраняет ошибку силы у конечного узла, возникающую при смешении
центрового давления трубы и давления порта без учёта половины длины ячейки.

Работа тяжести в ячейке вычисляется через тот же численный поток компонентов,
что и материальный баланс, включая диффузионную часть потока Русанова:
`sum_ports sign * A * g * (z_port-z_cell) * mass_flux`. Поэтому сохраняется
сумма `U + K + sum(m*g*(z-z_origin))`, где `z_origin` — отметка первой ячейки.
Выбор нуля потенциальной энергии не влияет на динамику. Поле отчёта
`wall_impulse_kg_m_s` для v2 содержит **общий внешний импульс**: давление
стенок, реакции опор, проекцию веса и локальное сопротивление стенок.
Это не отдельно измеренная реакция опоры.

Примеры: `surface_pr_multifluid_gravity.json` и
`surface_pr_multifluid_gravity_three_phase.json`. Запуск и независимая проверка:

```bash
PYTHONPATH=src python scripts/run_pr_multifluid_pipe.py \
  configs/surface_pr_multifluid_gravity.json --output /tmp/pr-gravity.json
PYTHONPATH=src python scripts/check_pr_multifluid_pipe.py \
  configs/surface_pr_multifluid_gravity.json /tmp/pr-gravity.json
```

Проверяются направление ускорения, малый временной предел ускорения во
внутренней ячейке, сохранение полной энергии, перенос начала высот,
баланс веса и давления для постоянноплотностного PR-профиля, разреженное
решение, источники и restart. Проверяющий инструмент использует собственный
NumPy-пересчёт PR-состояний, квадратуру пути и векторные реакции; методы
динамического решателя для проверки потоков и балансов не вызываются.

**Ограничение покоя:** баланс давления и веса не означает точного сохранения
всего стратифицированного состояния. Поток Русанова продолжает размывать
температурные, компонентные и фазовые контакты. Для v1/v2 точное сохранение произвольной стратификации не обеспечивается;
проверенный изотермический профиль теперь можно сохранять в режиме v3,
описанном ниже. Это нельзя подменять утверждением о малой общей невязке энергии. Необходимость
согласованного восстановления равновесия и численного потока обсуждается
в [работе Berberich и соавторов](https://arxiv.org/abs/1807.11825);
текущая многофазная реализация не заявляется реализацией этой схемы.


## Сохранение проверенного гидростатического профиля (v3)

`hydrostatic_reference` содержит начальные спецификации фаз для каждой
ячейки, как в `initial.cells`. Для этой схемы задаётся
`model: pr_multifluid_network_v3`. Перед использованием проверяются:

- нулевые скорости и заполнение конечных объёмов;
- постоянные по высоте температура, состав и объёмная доля каждой фазы;
- постоянство удельного потенциала `(h-T*s)/molar_mass + g*z` каждой фазы;
- стационарность локальных тепловых и барических источников.

Неподходящий профиль отклоняется. Полный дискретный оператор считается
как разность текущего оператора и оператора проверенного равновесия.
Вычитаются согласованно потоки, источники и внешний импульс. Глобальные
материальные и энергетические балансы сохраняются; возмущение давления
продолжает распространяться. Профиль входит в идентификатор модели и restart.
Тензорный оператор опорного состояния вычисляется один раз при создании
модели, а не на каждой итерации Ньютона.

Примеры: `surface_pr_multifluid_hydrostatic.json` и
`surface_pr_multifluid_hydrostatic_three_phase.json`. Независимый checker
сам восстанавливает PR-запасы и проверяет термодинамический потенциал;
оператор динамического решателя для этого не вызывается.

Это сохранение объявленного класса изотермических равновесий. Оно не
добавляет произвольную температурную стратификацию, межфазные границы с
нулевым фазовым запасом или автоматический поиск профиля. Для фаз с
разными гидростатическими давлениями нельзя включать барический обмен,
который сам по себе разрушает выбранное равновесие.

## Фазовый насос в общем Ньютоне (v4)

`pr_multifluid_network_v4` содержит `pumps`. Для каждого задаются уникальное
`name`, инерционная `cell`, индекс жидкой `phase`, явный
`minimum_density_kg_m3`, `speed_rad_s` и существующая знаковая `SignedPumpMap`
в `map`. Пример: `surface_pr_multifluid_pump.json`.

Это насос отдельного жидкостного прохода: `Q = alpha*A*u`, сила
`F = rho*g*head*alpha*A`. Сила входит в фазовый импульс, полная мощность
вала — в фазовую энергию, включая диссипацию карты. Газовый проход не
получает ту же характеристику автоматически. Отчёт содержит работу
`external_work_j`; энергетическая невязка вычитает её на транспортном,
составном шаге, отчётном интервале и всём расчёте. Карта, плотность и
допустимые рабочие точки проверяются; недопустимый шаг не публикуется.
Независимый checker пересчитывает характеристику скалярно.

Скорость вала здесь предписана, обратная связь конечного ротора из старой
сети ещё не перенесена. Синтетическая карта не подтверждает поведение
реального насоса. Этот адаптер не переносит автоматически компрессоры,
сепараторы и регуляторы. Режим v4 пока не совмещается с вычитанием опорного
профиля v3: работающий привод нельзя замаскировать как равновесный источник.

## Изменение числа фаз: отдельный консервативный источник

`PRPhaseEquilibration` принимает конечные фазовые запасы и явные PR-корни.
Он сохраняет общие компоненты, объём, полный импульс и энергию. После
UV-flash остаются только активные фазы; скорости становятся общими.
Энергия относительного движения переходит во внутреннюю энергию, а не
теряется. Предписанное тепло требует температуры внешнего резервуара;
проверяется производство энтропии системы вместе с резервуаром.

Источник использует существующий Torch UV-flash. Для чистого компонента
возле насыщения исправлен предел точности вложенного PH-поиска: давление,
температура и доля пара уточняются совместно. Фаза на уровне машинного
округления удаляется только на границе активного набора с проверкой
остатков U/V. Конечные малые доли, например `1e-6`, сохраняются.

Проверки `tests/test_surface_pr_phase_equilibration.py` подтверждают цикл
одна → две → одна фаза в жёстком сосуде, три жидкие фазы, баланс кинетической
энергии, restart и крайние доли насыщения. Независимый скалярный PR-аудит
находится в `scripts/check_pr_phase_equilibration.py`.

**Граница интеграции:** это мгновенный источник гомогенного равновесия,
а не кинетика зародышеобразования. Он пока не подключён как источник
пространственной `PRMultifluidNetwork`: её текущая система неизвестных
требует присутствия всех заданных фаз. Прямое копирование результата с
изменившимся числом фаз в старые слоты было бы неверным. Полное закрытие
блока требует пространственного active-set переноса и сопряжения остальных
типов оборудования; наличие этого источника не означает их завершения.

## Пространственное изменение числа фаз: HEM Euler

`PREquilibriumEulerPipe` переносит первичные запасы компонентов, импульса
и полной энергии конечными объёмами. UV-восстановление определяет активные
фазы каждой ячейки после переноса: возможны появление и исчезновение фаз
без фиктивного остаточного запаса. Это отдельное гомогенное равновесное
замыкание с общими P/T/u; конечное проскальзывание старой multifluid-модели
с ним пока не объединено.

Схема первого порядка, явный поток Русанова, ограничение CFL. Поддержаны
горизонтальная труба постоянного сечения, периодичность, закрытые концы,
заданный теплообмен с резервуаром, restart и адаптивное дробление при отказе
UV-восстановления. Компоненты и энергия учитываются по первичным запасам,
поэтому погрешность восстановления фаз не накапливается в балансе.
Операции реализованы в Torch; последовательное UV-восстановление ячеек и
управление шагом пока требуют CPU/GPU-синхронизаций. Высокая пропускная
способность больших сетей этим блоком ещё не подтверждена.

Конфиги `surface_pr_equilibrium_euler_{cycle,transport,walls,three_phase}.json`
запускаются через `scripts/run_pr_multifluid_pipe.py`; независимый скалярный
PR-аудит — через `scripts/check_pr_multifluid_pipe.py`.

## Сопряжение пространственных труб с оборудованием

`PREquilibriumEulerPlant` соединяет HEM-трубы с конечными перемешиваемыми
сосудами `PREquilibriumTransportNetwork`. Один граничный поток компонентов
и энергии применяется с противоположными знаками к трубе и сосуду.
Поддерживаются существующие насосные соединения, конечные роторы и
компрессоры графа; при отказе оборудования весь сопряжённый шаг откатывается.

Это IMEX-сопряжение первого порядка: явная граница трубы и неявный шаг
оборудования с известной нагрузкой. Ограничения текущего адаптера:
нулевая гравитация графа, горизонтальные трубы, конечные vessel-узлы;
подключение непосредственно к разрешённому профилю патрубка сепаратора
отвергается. Переход через перемешиваемый пленум нельзя выдавать за
разрешение межфазной границы внутри патрубка.

`scripts/check_pr_equilibrium_euler_plant.py` независимо восстанавливает
граничные потоки по скалярному PR, проверяет пространственный перенос и
использует отдельный аудит оборудования с противоположными потоками.
Все три исходных физических блока пока нельзя считать полностью закрытыми:
остаётся объединение переменного числа фаз с неравновесным проскальзыванием,
разрешёнными патрубками и общей геометрией сети.

## Общая неявная ветвь с изменением фаз и drift-flux

Для связки с гравитационными сепараторами основной путь теперь доступен
через `build_pr_surface_network`, а не только через явную Euler-трубу.
Компилятор использует существующие `PREquilibriumTransportNetwork` и
`PRGravityTransportNetwork`: фазовые запасы, P/T, импульс, энергия, профили
сосудов и оборудование остаются в общем Newton. Это локально равновесная
PR-модель с алгебраическим drift-flux, не произвольная неравновесная BN-модель.

`PRTerrainPipe.drift_flux` больше не принудительно равен `None`. Заданное
замыкание переносится во все ячейки рельефа с их собственным наклоном.
Проверки области применимости остаются обязательными: например, вертикальное
RELAP-замыкание нельзя применять к горизонтальному участку. Поддержанные
законы включают gas/liquid и явное маркерное gas/oil/water замыкание;
корректность искусственных трёхфазных EOS не подтверждает реальные свойства
пластовой воды или рассола.

`PRColumnTerminal(name, column, height_m)` задаёт геометрическое место
присоединения. Компилятор занимает соответствующий торец первой/последней
реальной ячейки трубы конечным `PRColumnPort`. У терминала нет запаса,
объёма или заданного давления. Площадь патрубка интегрируется по текущим
фазовым слоям гравитационного профиля; тепловое движение границы меняет
площади и фазовые расходы в том же неявном шаге. Возможны несколько труб
на одном сосуде и прямая труба между двумя сосудами без промежуточного
смесителя. Осевые `PRResolvedSeparator` и боковые `PRLateralNozzle` также
включаются в общую транспортную сеть через аргументы компилятора.

Инициализация: `initialize_pr_surface_network` принимает сгруппированные
поля труб и начальные данные/состояния колонн. Сохранение использует
существующую схему `pr_gravity_transport_v1` и единый checkpoint. Все
поддержанные насосы, компрессоры, роторы и ограничения передаются в общий
транспортный граф; отдельного перезаписывания давлений после шага нет.

Конфиги `surface_pr_native_{surveyed_slip,column_reverse,column_parallel}.json`
используют `scripts/run_pr_gravity_transport.py` и независимую проверку
`scripts/check_pr_gravity_transport.py`. Это малые функциональные случаи,
а не масштабный скоростной или промысловый эталон. Неравновесная BN-ветвь
по-прежнему ограничена фиксированным числом фаз; эмпирические замыкания
нельзя переносить за заявленные диапазоны без отдельной валидации.

## Пространственный перенос с действительно отсутствующими фазами

`PRActiveMultifluidPipe` — новая версия неравновесной горизонтальной трубы.
Каждая присутствующая фаза хранит собственные компоненты, V/M/E и P/T/u;
отсутствующая не записывается в checkpoint. Служебные примитивы на грани
копируются из соседнего донора, но никогда не получают N/V/M/E. Для них
не вызывается EOS. Входящий поток может создать фазу в пустой ячейке;
термохимический источник может добавить новую ветвь или удалить её в
мгновенном пределе. Минимального фазового запаса или доли не задаётся.

Это отдельное попарное BN-подобное замыкание, а не незаметная смена
уравнений прежнего `PRMultifluidPipe`. Для пары i,j используются
`gamma_ij = alpha_j*dalpha_i-alpha_i*dalpha_j`,
`Uij = (alpha_i*ui+alpha_j*uj)/(alpha_i+alpha_j)` и
`Pij = (alpha_j*pi/Ti+alpha_i*pj/Tj)/(alpha_j/Ti+alpha_i/Tj)`.
Вклады `Pij*gamma_ij`, `Pij*Uij*gamma_ij` и `Uij*gamma_ij`
попарно антисимметричны. Непрерывный межфазный вклад в суммарную энтропию
обнуляется этой связкой давления и скорости; дискретный перенос дополнительно
проверяется по энтропии до применения химического источника. Источник не
может скрыть потерю энтропии транспортным оператором.

В интеграле пути используется восьмиточечная квадратура Гаусса. На
материальном контакте применяется аналитический перенос по направлению
скорости: это сохраняет неподвижный слой и предотвращает появление
округлительной энергии у фазы с нулевой массой. Распознавание контакта
учитывает обусловленность EOS через акустический модуль сжатия и калорический
масштаб float64. Проверка отдельной малой волны давления подтверждает,
что разрешимые акустические возмущения не подавляются этим критерием.

Каталог `phase_slots` содержит 1..6 имён и механических селекторов корня.
Для нескольких жидких фаз можно задать компонентные маркеры с явной областью
применимости. Имена слотов не заменяют термодинамическую классификацию
единственного сверхкритического корня. Состояние содержит только реально
присутствующие популяции. Перестановка слотов после источника не меняет
первичные запасы. Синтетический gas/oil/water пример проверяет три разные
скорости, но не подтверждает реальные PVT-свойства воды/рассола.

Текущая схема — первый порядок, явная по времени, с CFL <= 0.25,
замкнутыми или периодическими концами и постоянным сечением. Отказы EOS,
положительности, энтропии или баланса приводят к дроблению интервала;
неподдержанный каталог фаз отклоняется явно. Все принятые подшаги входят
в отчётный интервал; restart сохраняет полный активный набор и запасы.

Проверки включают неподвижные/движущиеся границы, сохранение профиля
удержания на последовательности шагов, появление газа в одной ячейке
и последующий перенос в соседние, конденсацию до полного удаления газа
в мгновенном пределе, трёхфазный противоток и однофазный предел против
отдельного HEM Euler-решателя. Независимый скалярный аудитор использует
64-точечную квадратуру и отдельный PR-код.

Запуск: `scripts/run_pr_active_multifluid_pipe.py`; проверка:
`scripts/check_pr_active_multifluid_pipe.py`. Конфиги:
`surface_pr_active_multifluid_{static,contact,birth,gow}.json`.

**Оставшиеся границы этой новой ветви:** не реализованы её наклонная
геометрия, сопряжение с сосудами/оборудованием общего графа, независимые
пространственные эталоны с измерениями и проверка больших моделей.
Существующая связанная равновесная ветвь поддерживает собственные
гравитационные сосуды и оборудование; её возможности нельзя автоматически
приписывать новой неравновесной трубе. Малые CUDA-прогоны подтверждают
функциональность, а не промышленную скорость явной схемы.

# Несколько профильных труб в общем PR-графе

`PRProfileGraphNetwork` подключает несколько именованных
`PRLayeredTransportNetwork` к конечным сосудам одного
`PREquilibriumTransportNetwork`. Параллельные пути, разветвления, слияния,
кольца и изолируемые ветви решаются одним Torch-Ньютоном. Обычный граф
вычисляется один раз на невязку; каждая профильная ветвь — также один раз.
Последовательных подстановок давлений и искусственных буферов нет.

## Состояние и геометрия

Модель `pr_profile_graph_v2` содержит `transport`, словарь `profiles` и
`maximum_head_fraction`. Для каждой ветви задаются `pipe` и два
`boundary_nodes`: имена действительных конечных сосудов либо `null`.
Имена ветвей сортируются для воспроизводимого порядка неизвестных и checkpoint.
Узел может принимать любое число ветвей; диаметры и наклоны разных ветвей
могут отличаться при соблюдении условий их индивидуальных торцевых мостов.

Каждая ветвь сохраняет область применимости [профильного компонента](PR_LAYERED_TRANSPORT.md):
прямая невертикальная труба постоянного диаметра, общие скорость и температура
фаз, поперечное гравитационное и химическое равновесие. Отметка сосуда должна
совпадать с центром подключённого диска. Ограничение поперечного напора,
HEM-состояние сосуда и фиксированный активный компонентный реестр сохраняются.
Разные наклоны не дают автоматически глобальных пространственных координат
или азимутов труб. Прямые профильные соединения без конечного сосуда,
боковые патрубки и проскальзывание этой моделью не вводятся.

`ProfileGraphState` содержит обычное состояние, именованные состояния всех
ветвей, `profile_openings` и общий ID модели. Часы всех подсистем должны совпадать.
Неизвестные и пропавшие ветви checkpoint отклоняются. Старые модели
`pr_layered_plant_v1` и их форматы продолжают работать отдельно.

## Потоки, импульс и энергия

Торцевые HLLC-потоки каждой трубы входят в её баланс и в баланс сосуда
с противоположными знаками. Все обмены одного узла суммируются до сборки
его накопления. Энергия приводится к общей отметке и включает внутренний,
гравитационный и кинетический запасы, стенки и роторы обычного графа.
В разреженный Якобиан входят связи каждого торца с общим узлом.

`vessel_support_force_n` — словарь по ветвям со списками реакций по узлам.
Каждая реакция задана вдоль оси своей трубы. Реакции разных осей не суммируются
в вымышленную общую скалярную силу: для пространственной результирующей нужны
дополнительные азимуты. Независимый аудит проверяет импульс каждой ветви.

Активные компоненты распространяются по всему связанному графу до неподвижной
точки, включая пути через другие профильные ветви. Если достижимый вход
содержит компонент вне фиксированного реестра трубы, расчёт отклоняется.
Число неизвестных ограничено обычным и всеми профильными численными бюджетами.

## Команды и перезапуск

`step` принимает обычные команды тепла, открытий, сопротивлений и моментов.
Дополнительные словари индексируются именами профильных ветвей:

- `profile_openings`: два булевых флага торцов; по умолчанию оба открыты,
  если геометрическая привязка существует. Закрытие использует отражённый
  поток, сохраняет запасы ветви и допускает повторное открытие.
- `profile_heat_w`: тепло по ячейкам ветви или единая мощность на ячейку.
- `profile_utility_temperature_k`: температуры источников по ячейкам при
  ненулевом тепле; проверяются направление теплообмена и энтропия.

В версии 2 изоляция сохраняется между интервалами и в checkpoint.
Закрытый торец открывается только явной командой. В `openings` доступны
переключатели `profile:<ветвь>:left` и `profile:<ветвь>:right` геометрически
подключённых торцов. Противоречащие команды через `openings` и
`profile_openings` отклоняются. `null` в модели всегда остаётся закрытым торцом.
Это идеальное закрытие без динамики затвора или конечного объёма клапана.

Существующий `pr_profile_graph_v1` сохраняет прежние ID, checkpoint и
команды одного интервала: без повторной команды торцы возвращаются к
привязкам модели. Сохраняемая изоляция и переключатели с префиксом `profile:`
доступны в версии 2. Старый checkpoint не становится состоянием версии 2
без явной повторной инициализации.

`PRControlledSurface` поддерживает профильный граф:
[общие PI, приводы, защиты и датчик уровня ячейки](PR_PROFILE_CONTROLS.md).

`advance` сравнивает полный шаг с двумя половинными для всех ветвей,
принимает единый шаг и сохраняет одинаковые часы и следующий шаг.
Отказ шага не изменяет переданное состояние. Фазовые повторы ограничены;
невозможность найти допустимую топологию остаётся явным отказом.

## Воспроизведение и независимая проверка

```sh
PYTHONPATH=src python scripts/run_pr_profile_graph.py \
  configs/surface_pr_profile_graph.json --output /tmp/profile-graph.json
PYTHONPATH=src python scripts/check_pr_profile_graph.py \
  configs/surface_pr_profile_graph.json /tmp/profile-graph.json
```

Начальное состояние задаётся `initial.transport` и `initial.profiles`
(равновесные P/T/состав каждой ветви), либо точным `initial.state` для restart.
Пример закрывает одну параллельную ветвь, затем вновь подключает её.
Runner фиксирует исходники. Независимые NumPy/SciPy-модели восстанавливают
фазовые профили и торцевые обмены всех ветвей, проверяют локальные N/E,
импульс, тепло и энтропию, затем проверяют обычный граф с суммарными обменами.
Проверяются также начальные условия, изоляция и согласованность опубликованных
состояний с принятыми решениями.

Численные проверки включают параллельные трубы, кольцо с реверсом отдельных
ветвей, изоляцию и повторное открытие, dense/sparse, производные связей,
перезапуск и повреждение отчётов. Эти проверки не подтверждают универсальную
карту режимов или экспериментальную точность многофазных замыканий.

# Критические PR-соединения

`PRHEMRestriction` включается в `restrictions` общего
`PREquilibriumTransportNetwork`. Это квазистационарное горло между конечными
объёмами на одинаковой отметке. Запасы находятся в объёмах, а не в арматуре.
Источник определяется направлением перепада давления. Обратное течение
разрешается явно через `allow_reverse`; `open=false` изолирует соединение.

## Физические уравнения

В том же Ньютоне решаются давление, температура, скорость и распределение
компонентов между фазами горла. Состав сохраняется, химические потенциалы
совпадают, энтропия равна входной. Энтальпия торможения удовлетворяет
`h + MW*u²/2 = h_in`. В приёмник переносится полная входная энтальпия:
кинетическая энергия струи не исчезает из баланса при торможении.

Подкритическая ветвь имеет давление приёмника. На внутреннем максимуме
потока выполняется `1 + 2*(h_in-h)*(dVm/dP)|S / Vm² = 0`.
Комплементарность выбирает ветвь без искусственного ограничения по идеальному
газу или замороженному паросодержанию. Производная вычисляется неявным
дифференцированием равновесных уравнений. Вторая производная корней PR
учитывается при сборке Якобиана критического условия.

При рождении фазы максимум может находиться на изломе зависимости потока
от давления. Для него используется отдельная параметризация с нулевой
долей новой фазы и двумя односторонними термодинамическими касательными.
Стабильность проверяется TPD по решённому составу; малая новая фаза не
должна исчезать из-за повторного холодного запуска PS-flash.

## Параметры и управление

Обязательны `name`, `source`, `target`, `throat_area_m2`,
`maximum_molar_rate_mol_s`, `minimum_pressure_pa`.
`discharge_coefficient` и `opening` лежат в (0,1] и [0,1] соответственно.
Предельный расход и `maximum_throat_velocity_m_s` задают область приёмки,
а не молча обрезают физический ответ.

Команда `restriction_openings` меняет площадь. `PRThroatControlValve`
(`model="hem_throat_area"`) связывает её с приводом и характеристикой
открытия. Две команды одной площади одновременно запрещены.
PI с `measurement="level"` и `sensor` равным имени гравитационной колонны
может регулировать удалённый клапан через конечные трубы и объёмы.
Состояния привода и регулятора сохраняются в общем checkpoint.

## Воспроизводимые примеры

- `configs/surface_pr_hem_gas.json`: газовая смесь.
- `configs/surface_pr_hem_two_phase.json`: двухфазная смесь.
- `configs/surface_pr_hem_flashing.json`: вскипание жидкости на горле.
- `configs/surface_pr_hem_phase_boundary.json`: максимум при рождении третьей фазы.
- `configs/surface_pr_hem_three_phase.json`: газ, углеводородная и водная фазы.
- `configs/surface_pr_controlled_hem_throat.json`: привод и регулирование.
- `configs/surface_pr_column_controlled_hem.json`: колонна, конечный патрубок,
  труба, критический клапан и удалённое регулирование уровня.

Пример запуска и независимой проверки:

```bash
python scripts/run_pr_equilibrium_transport.py configs/surface_pr_hem_three_phase.json --device cpu --output results/hem_three_phase.json
python scripts/check_pr_equilibrium_transport.py configs/surface_pr_hem_three_phase.json results/hem_three_phase.json
```
Для управляемой схемы используются соответствующие `*_pr_controlled_surface.py`.
`reference_pr_restrictions.py` пересчитывает PR-свойства, PS-условия,
термодинамическую касательную и балансы отдельным NumPy/SciPy-кодом.
Это численная верификация, не экспериментальная калибровка.

## Границы применимости

HEM предполагает локальное тепловое, механическое и химическое равновесие.
Модель не описывает задержку нуклеации, метастабильное течение,
неравновесную кавитационную эрозию, раздельные скорости в горле или
сертифицированную пропускную способность конкретного клапана.
Параметры PR для воды в учебных примерах не заменяют водно-ассоциативную EOS.

## Повторение проверки CPU/CUDA

Функциональная матрица запускается через
`scripts/validate_pr_surface_matrix.py --device cpu --output RESULTS_CPU`.
Для CUDA предварительно явно выбирается свободная карта через
`CUDA_VISIBLE_DEVICES`, затем используется `--device cuda` и отдельный каталог.
`--case` позволяет выбрать отдельные сценарии; CUDA-запуски выполняются
последовательно. Время этих малых примеров включает инициализацию и аудит
и не является оценкой ускорения большого промысла.

`scripts/check_pr_surface_device_parity.py RESULTS_CPU RESULTS_CUDA --output PARITY.json`
проверяет контрольные суммы исходников/конфигураций, принятые независимые
аудиты, совпадение запросов и конечных checkpoint каждого интервала.
Сравниваются физические координаты, включая фазовые запасы, стенки,
популяции, интеграторы и положения приводов; допуски сравнения устройств
не подменяют допуски физических балансов. Изменённые исходники или
несопоставимые наборы сценариев отвергаются.

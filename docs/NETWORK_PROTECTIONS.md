# События и блокировки динамической сети

Этот модуль добавляет пороговые события к [монолитной динамической сети](DYNAMIC_NETWORK.md).
Событие локализуется по физическому состоянию, затем применяются явно заданные
действия. Расчёт с реакцией защиты продолжает оставшийся интервал и сохраняет
компонентные/энергетические балансы. Исходный строгий режим без событий остаётся:
нарушение жёсткой области модели возвращает отказ, без обрезания состояния.

## Порог и область

`NetworkTrip` содержит `name`, `vessel`, `metric`, `direction`, `threshold`,
`value_tolerance` и списки действий. Метрики:

- `pressure_pa` — абсолютное давление, Pa.
- `temperature_k` — температура, K.
- `wall_temperature_k` — температура явно заданной стенки, K.
- `liquid_volume_fraction` — доля объёма жидкости, безразмерная.
- `liquid_level_m` — высота жидкости при явно заданной геометрии, m.
- `total_moles` — суммарный компонентный запас, mol.

`direction="above"` срабатывает при достижении верхнего порога,
`"below"` — нижнего. Порог и его численный допуск должны лежать строго
внутри жёстких границ соответствующей метрики. Это позволяет остановить
процесс до выхода из допустимого давления/температуры/запаса.
Порог одной метрики сам по себе не гарантирует соблюдение остальных границ.

`value_tolerance` обязателен и задаётся в единицах метрики. Это численная
точность локализации, не характеристика датчика. `event_time_tolerance_s`
(по умолчанию 1e-7 s) отдельно задаёт точность поиска времени события.
Если обе точности не выполняются, интервал дробится или отклоняется.
Состояние не заменяется присваиванием давления/уровня пороговому значению.

Объёмная доля жидкости определена только при разрешённых жидкой/паровой
фазах. Если фазовая классификация не позволяет определить её, расчёт
возвращает ошибку. Угадывания «всё жидкость»/«всё газ» по плотности нет.
Метрика не является высотой уровня без заданной геометрии аппарата.

## Действия

Поля действий — списки существующих имён:

- `close_connections`: запросить коэффициент площади/проводимости 0.
  При наличии [привода](CONNECTION_ACTUATORS.md) закрытие требует времени;
  заклинивание или fail-open могут помешать закрытию.
- `stop_feed_vessels`: прекратить все внешние подачи в указанные сосуды.
- `stop_withdrawal_vessels`: прекратить все внешние отборы из сосудов.
- `stop_heat_vessels`: отключить заданный тепловой поток любого знака.
- `stop_heating_vessels`: запретить только положительный Q, сохранив охлаждение.
- `stop_cooling_vessels`: запретить только отрицательный Q, сохранив нагрев.

Для автоматической реакции требуется хотя бы одно действие. Списки
нормализуются и проверяются до расчёта, включая неработающие периоды.
Неподходящее действие не считается успешной защитой: например, отключение
подачи при продолжающемся перегреве может привести к последующему нарушению
жёсткого предела. В этом случае весь вызов отклоняется, без частичного результата.

## Локализация без потери запасов

Проверяются начала и концы принятых подшагов. Если найдено пересечение,
пробное время события получает **новое неявное решение из одного и того же
состояния перед подшагом**. Не интерполируются отдельно P/T/энергия/состав.
Пробные решения не попадают в накопленную продукцию или интегралы потоков.
Принимается только шаг до найденного события, затем изменяются команды.

При нескольких найденных пересечениях выбирается раннее. События,
неразличимые в пределах временного и собственных метрических допусков,
обрабатываются в детерминированном порядке имён. Все действия — закрытие/
отключение, поэтому они объединяются без конфликтующих команд открытия.

События могут менять поведение внутри отчётного интервала: остаток времени
интегрируется с уже изменёнными командами. Внешние потоки и тепло до события
и после него входят в баланс со своими реальными длительностями.
Неисполненная подача учитывается отдельно в `blocked_feed_component_moles`:

```
requested_feed = actual_boundary_feed + blocked_feed
```

Заблокированное вещество не поступало в аппарат и не считается продукцией.
Это не возвращает массу в пластовый FIM: внешние источники данной модели
ещё не связаны с пластовыми неизвестными.

Метод имеет конечное временное разрешение. Несколько пересечений одного
порога между двумя проверяемыми концами подшага могут остаться невыявленными.
Нужно выбирать `maximum_dt_s` и проверять сгущение для рабочего сценария.
Такое ограничение обнаружения пересечений по концам шага описано и в
[документации событий SciPy](https://docs.scipy.org/doc/scipy/reference/generated/scipy.integrate.solve_ivp.html).
Жёсткие пределы не снимаются ради поиска события: слишком узкий запас между
порогом и жёсткой границей или неразрешимый корень дают отказ, не обещание
автоматического спасения расчёта при любых настройках.

## Защёлка и ручной сброс

Сработавшее имя попадает в `latched_trips`. Его действия имеют приоритет
над последующими командами расписания: новый `connection_factors=1` не
снимает закрытие. Возврат сигнала ниже порога сам не открывает аппарат.
Это устраняет повторное переключение на каждом шаге около порога.

Периодное `reset_trips` явно снимает перечисленные блокировки в начале
периода. Если условие всё ещё нарушено, защита срабатывает снова до подачи
потока. При безопасном состоянии оборудование может возобновить работу
по обычным командам периода. Списки неизвестных/повторных имён отклоняются.

Начальное активное условие применяется до проверки потоков, которые оно
отключает. Например, блокировка подачи не требует сперва пропустить поток
из источника с недостаточным давлением. Сами запасы и область EOS обязаны
быть допустимы: защита не исправляет повреждённое начальное состояние.

## API наблюдения и API реакции

`network.advance(..., stop_conditions=[trip])` — низкоуровневый режим
наблюдения. Он останавливается на первом найденном событии и возвращает
фактически пройденный `duration_s`, исходный `requested_duration_s`, состояние
и `events`. Он не обещает прохождение оставшегося интервала и не применяет
действия самостоятельно. Команды и модель проверяются до расчёта.

`advance_protected_network(..., rules, latched=...)` применяет действия и
проходит весь запрошенный интервал. Число принятых подшагов ограничено на
весь вызов, а не заново для каждого участка между событиями. Защёлки
ограничивают число переключений, нулевое время допустимо только для нового
срабатывания. Отказ не меняет объекты состояния/защёлок вызывающей стороны.

## Расписание, конфигурация и перезапуск

В `scripts/run_vessel_network.py` добавлены необязательные корневые
`protections` и `event_time_tolerance_s`. Период поддерживает `reset_trips`.
Пример правила:

```json
{
  "name": "receiver-high-pressure",
  "vessel": "receiver",
  "metric": "pressure_pa",
  "direction": "above",
  "threshold": 1050000,
  "value_tolerance": 0.1,
  "close_connections": ["transfer"]
}
```

Полный пример `configs/surface_vessel_network_protected.json`: повышение
давления приёмника, закрытие связи, внешний отбор, ручной сброс и повторное
срабатывание. Это сценарий симулятора с демонстрационными свойствами/характеристикой,
не настройка реального оборудования.

```bash
python scripts/run_vessel_network.py configs/surface_vessel_network_protected.json --output /tmp/protected.json --stop-after 1
python scripts/run_vessel_network.py configs/surface_vessel_network_protected.json --checkpoint /tmp/protected.json --output /tmp/protected.json
```

Checkpoint сохраняет запасы, часы, принятые шаги, журнал событий, защёлки и
заблокированную подачу. Проверяются checksum, отпечаток правил/команд/реализации,
время/порог событий, соответствие защёлок истории, накопления и баланс
запрошенной/принятой/заблокированной подачи. Текущая схема checkpoint v5 не
принимает старую реализацию молча. Контрольная сумма — проверка целостности,
не цифровая подпись. CLI сохраняет файл атомарно после успешного вызова.

## Проверка и ограничения

Проверены независимое идеальногазовое время нагрева до порога, дробление
интервала в точке события, сохранение энергии/компонентов при закрытии связи,
двухфазный жидкий объём, низкий запас, раздельные тепловые отключения,
одновременные события, начальное срабатывание, безопасный/небезопасный сброс,
приоритет защёлки над расписанием, заблокированная подача, JSON-продолжение
и отклонение неэффективной защиты при достижении жёсткой границы.

CPU/offline модель пороговых действий. Нет SIL/надёжностной сертификации,
задержек/шума датчиков, полной механики приводов, геометрического sizing предохранительного
клапана, волновой гидравлики, воды или связи с реальным оборудованием.
Физические ограничения PR/HEM, теплоёмкости стенок и пластового FIM остаются
прежними. Защитные правила требуют инженерного выбора порогов и проверки
временного разрешения; тесты кода не заменяют валидацию промышленной системы.

# Управление жидкостно-тепловым Gauss4

`CollocationThermalStation` добавляет дискретные термостаты и температурные
защиты к `ThermalLiquidCollocation`. Давления, расходы, скорости валов,
запасы жидкости, температуры и стенки проходят совместный физический шаг.
Команды контроллера удерживаются между отсчётами.

Переиспользованы `PIDController`, `PIDState`, `LiquidThermostat`,
`LiquidTemperatureTrip` и `LiquidTripMemory`. Правила температурной
выдержки и распределения мощности выделены в `thermal_control.py` и
используются также существующей `ThermalLiquidStation`.
Каскад давления/скорости, dispatch, рецикл и движущиеся исполнительные
механизмы прежней станции этим классом не заменяются.

## Часы и смысл событий

Сетка контроллера вычисляется как `clock_origin_s + next_tick * interval`.
Счётчик целочисленный, сохраняется в состоянии и не обнуляется на границе
отчёта. Численно непредставимый следующий отсчёт отвергается.

Окно отчёта полуоткрыто для опроса: отсчёт точно на его правой границе
выполняется при следующем вызове. Поэтому короткий или частичный отчёт
не создаёт лишнего PID-обновления. Периоды команд могут заканчиваться
между отсчётами; интегратор достигает этой границы до смены команды.

Термостаты в режимах `auto`, `manual`, `off` изменяют выход на очередном
отсчёте. Их заданные температуры и режимы — команды текущего окна.
Напротив, заданные непосредственно моменты двигателей, граничные условия
и внешние тепловые нагрузки применяются на границе вызова/периода.
Неуказанные моменты равны нулю. Неуказанные уставки/режимы термостатов
возвращаются к настройкам модели/`auto` на следующем отсчёте.

Температурные защиты также **дискретные**. Выдержка отсчитывается от
первого отсчёта с нарушением; после срабатывания защита защёлкивается.
Это не непрерывный поиск корня и не гарантия обнаружения выброса
между отсчётами. Тест с коротким тепловым импульсом прямо подтверждает:
редкий опрос может пропустить нарушение, более частый — обнаружить.

## Действия защит и мощности

Команда остановки снимает момент соответствующего двигателя, но не
обнуляет его скорость, расход, массу или энергию. Выбег рассчитывается
из сохранённого физического состояния. Геометрия сети автоматически
не изолируется. Действия зарегистрированы в `events`, фактически поданные
команды — внутри каждого физического сегмента.

- `mode="off"` снимает моменты на текущее окно без защёлки.
- `mode="trip"` устанавливает операторскую защёлку; она сохраняется
  при следующих вызовах до `reset_trip=True`.
- `unavailable` сохраняет внешнюю маску отключённых приводов; явный
  пустой список снимает её.
- `reset_temperature_trips` сбрасывает конкретные температурные защёлки
  только при выполненном условии `reset_safe` с заданным гистерезисом.
  Операторский reset температурную защиту не отменяет.

Флаги владельца защиты находятся в `CollocationThermalState`, а не
подменяют состояние механического интегратора. Импорт физического состояния
с флагами чужого управляющего контура отвергается.

Нагрев и охлаждение термостатов имеют отдельные суммарные ограничения.
При нехватке мощности запросы соответствующего знака уменьшаются
пропорционально. В PID для anti-windup передаётся реально поданная
мощность после распределения. Переход manual → auto использует её же,
обеспечивая безударный переход.

Эти ограничения относятся к управляемым термостатам. `heat_duties_w`
описывает независимые внешние тепловые нагрузки и не расходует указанную
управляемую мощность. Внешняя нагрузка не может одновременно писать
в тот же тепловой исполнительный канал, что и термостат.

## Состояние и отказ

`CollocationThermalState` содержит физическое и тепловое состояния, память
PID и защит, фактически удерживаемые мощности, внешнюю маску приводов,
операторскую защёлку, часы и предложенный следующий физический шаг.

Границы отчёта/контроллера не схлопывают предложение шага до короткого
остатка при достаточно малой оценке ошибки. Если измеренная ошибка
требует уменьшения, следующее предложение сокращается. Все последующие попытки
по-прежнему проверяют ошибку, область свойств и балансы.

`max_samples` ограничивает число управляющих отсчётов, `max_attempts` —
общее число физических попыток **во всём вызове**, а не в каждом сегменте
отдельно. При отказе в середине вызова частичный результат не публикуется;
исходные состояния и память контроллера остаются неизменными.

## API

```python
from surface import CollocationThermalStation, CollocationThermalState

station = CollocationThermalStation(
    heat_model,
    thermostats=thermostats,
    temperature_trips=temperature_trips,
    control_interval_s=0.05,
    max_heating_w=1000.0,
    max_cooling_w=2000.0,
)
initial = station.initialize(initial_hydraulics, initial_heat)
report = station.advance(
    initial,
    1.0,
    motor_torques_nm={"a": 5.0, "b": 7.0},
)
restart = CollocationThermalState.from_dict(report["state"])
continuation = station.advance(restart, 1.0, motor_torques_nm={"a": 5.0, "b": 7.0})
```

Контуры давления/скорости здесь не вычисляются: моменты двигателей
задаются внешним кодом. Температурные PID и защёлки работают независимо
от этих команд. Смена численных настроек допускается через `solver_options`
при создании модели, как у `ThermalLiquidCollocation`.

## CLI и проверенный restart

Пример конфигурации:
`configs/surface_collocation_thermal_control.json`. Он содержит модель,
начальные давления/расходы/скорости, температуры и список периодов.

```bash
python scripts/run_collocation_thermal.py configs/surface_collocation_thermal_control.json --output /tmp/full.json
python scripts/run_collocation_thermal.py configs/surface_collocation_thermal_control.json --output /tmp/partial.json --stop-after 1
python scripts/run_collocation_thermal.py configs/surface_collocation_thermal_control.json --checkpoint /tmp/partial.json --output /tmp/resumed.json
```

Результат записывается атомарно после успешного расчёта. Ошибка не заменяет
существующий файл. Устройство берётся из модели либо явно задаётся
`--device`; SciPy-backend этим путём не поддерживается.

`run_collocation_thermal_schedule` привязывает checkpoint к модели,
начальному состоянию, плану периодов, версиям библиотек и исходникам.
При resume завершённые периоды один раз воспроизводятся физически,
сверяются сохранённые записи и финальная память. Одной пересчитанной
контрольной суммы недостаточно, чтобы подменить температуры или PID.
Изменение кода/конфига/плана делает прежний checkpoint несовместимым.

## Подтверждённые границы

Подтверждены sampled PID, utility allocation, задержка/защёлка/сброс,
выбег после снятия момента, отчётные разбиения, точный повтор расписания,
проверка подменённого checkpoint и сквозное сопоставление с независимой
консервативной ODE. Артефакты:
[проверка управляющего сценария](../benchmarks/reports/surface_collocation_control/README.md).

Физика остаётся однофазной, с постоянными гидравлическими свойствами и cp.
Непрерывная локализация физической остановки вала, многопараметрический
dispatch, движущиеся механизмы и полная PR-сеть пока не подключены к этому
новому контуру. GPU-производительность не квалифицирована: математика
гидравлики/тепла работает на выбранном Torch-устройстве, PID и таймеры —
на CPU на отсчётах. Полные состояния экспортируются после контрольных
окон; внутри нелинейных итераций остаются чтения скалярных статусов.

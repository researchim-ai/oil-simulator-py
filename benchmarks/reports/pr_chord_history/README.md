# Защищённый перенос линейзации между задачами Radau

Переиспользован существующий `PRCollocation`, его PR-остаток, потоки HLLC,
встроенная оценка ошибки и независимый аудит стадий. Новый блок переносит
якобиан и LU между близкими нелинейными задачами; общего BDF-интегратора
установки этот эксперимент не добавляет.

## Изменение решателя

`DenseNewtonHistory` хранит одну матрицу с факторизацией. Принимающая задача
должна иметь тот же явный ключ фаз, активных компонентов и команд, размер,
тип данных и устройство. Отношение временных коэффициентов допускается в
пределах 0,8–1,25, изменение начальной точки ограничено. После трёх переносов
линейзация обязательно обновляется. При недостаточном уменьшении новой
невязки пробная поправка отбрасывается и тот же вектор решается свежим
Ньютоном. Итерационный лимит и исходная конечная проверка сохраняются.

Нижние границы совпадают точно. Малое изменение неактивного верхнего потолка
логарифма запаса допускается только при расположении обеих точек строго
ниже старого и нового потолка. Поправки всегда ограничиваются актуальными
границами новой задачи. Это политика допуска старой матрицы, а не ослабление
физических допусков или ограничений переменных.

История предназначена для плотного CPU-пути без дифференцирования расчёта.
Разреженный и CUDA-пути сохраняют исходную политику. Размер плотной задачи
не увеличен. Внешние материальные сопряжения, не адаптированные в
`PRCollocation`, не используют этот перенос. Отказ физического/временного
теста и фазовый fallback сбрасывают историю. В checkpoint матрицы не входят.

## Связанная установка

Использован прежний рабочий интервал установки из 16 узлов: гравитационный
сепаратор, два насосных соединения, компрессор, регуляторы и исходный газовый
рецикл диаметром 1 мм. Начало 0,706238099587186 с, три отчётных интервала,
суммарно 0,04864483383967377 с. Геометрия, начальные запасы и допуски одинаковы.

Сначала выполнена подготовка, затем отдельный прогрев нового пути. Дальше
чередуются три пары свежих физических моделей на одном нативном контексте.
Время охватывает весь вызов установки с инициализацией, не один линейный
решатель. Независимый аудит и запись сжатых траекторий выполняются за таймером.

* Сборки якобиана быстрой части: **12 → 3** на полное расписание.
* Успешные переносы: **9**, аварийные обновления: **0** в этом сценарии.
* Число нелинейных задач быстрой части: **12 → 12**; у каждой политики
  3 попытки и 6 принятых внешних полушагов. Дробление шага не скрыто.
* Медиана полного тёплого расчёта: **6,5150 → 6,2652 с**, отношение **1,0399**.
  Все времена исходного пути: 6,3521 / 7,4684 / 6,5150 с; нового:
  6,2591 / 6,4012 / 6,2652 с.
* Все **8** траекторий, включая подготовку и прогрев, прошли независимый аудит.
  Максимальное отличие отчётных состояний в исходной норме временной ошибки:
  **2,8914·10⁻⁷**; критерии Ньютона и временные допуски не менялись.

Это небольшое наблюдаемое ускорение на общем хосте, а не доказательство
устойчивого выигрыша 4% на любой машине. Часть расширенных CPU-тестов
пересекалась по времени с подготовкой и началом серии. Более убедительный
результат — сокращение именно сборок якобиана на 75% при прежнем числе
нелинейных задач и независимом аудите. Перенос только быстрой части не
устранил стоимость остальной установки. Реального времени всей сети,
преимущества над конкурентом или ускорения Norne этот замер не подтверждает.

Подготовка текущей серии с готовым дисковым кэшем заняла **163,30 с** и
вынесена отдельно. В предыдущем диагностическом запуске она заняла
**604,15 с**, включая 402,63 с учтённого codegen. Снятый тогда стек показал
перебор слияний операций в `torch._inductor.scheduler`; это была компиляция,
не физические микрошаги. Разница холодных подготовок не приписывается
переносу матриц: состояние дискового кэша различалось.

Первый вариант требовал точного совпадения верхних границ. Он физически
прошёл аудит, но дал **0 переносов**: потолок запаса менялся при течении.
Разница времени около 1% не принята за ускорение. Эта отрицательная проверка
сохранена отдельно в `inactive_exact_bounds/`; её исходники отличаются от
финального снимка и идентифицированы собственным manifest.

## Включение и повторение

По умолчанию метод выключен. Для нового проекта `pr_subcycled_surface_v1`
с `fast_time_scheme: radau3` или `radau3-embedded` есть явная опция
`fast_jacobian_history: true`. Она входит в идентификатор модели; старый
checkpoint нельзя незаметно объявить принадлежащим изменённой конфигурации.
Для прямого API: `PRCollocation(physics, scheme="radau3",
reuse_step_jacobian=True)`. Новая история начинается пустой.

Парный драйвер сам чередует политики, не меняя физический вход:

```bash
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=src:scripts \
  /home/user/miniconda3/bin/python scripts/benchmark_pr_chord_history.py \
  benchmarks/reports/pr_chord_history/validated/request.json \
  --output-dir .scratch/pr-chord-repeat --repeats 3
```

`validated/` содержит запрос, manifest, сводку и все восемь сжатых траекторий.
`validated_sources.tar.gz` хранит проверенные по manifest исходники финальной
серии. Логи проверок: 65 проверок коллокации с включённым переносом, 18
проверок истории/интеграции конфигурации, 46 прежних контрактов Ньютона.
Тесты покрывают откат, фазовый fallback, открытые границы, стенки, независимый
порядок сходимости и отбрасывание испорченных физических журналов.

Не квалифицированы этим экспериментом: полный цикл пуск–изоляция–пуск с
включённой историей, её перенос на гравитационный блок оборудования, GPU и
общий интегратор установки без внешнего сравнения целого шага с половинами.

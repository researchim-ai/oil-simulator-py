# Общая временная схема полной PR-установки

В `request.json` сохранена полная прежняя 16-узловая установка: гравитационный
сепаратор, конечные патрубки, три динамических привода, шесть PI/актуаторов
и тонкий газовый рецикл. Выбран один исходный отчётный интервал
0,016214944613224563 с, начиная с 0,706238099587186 с. Начальные запасы,
геометрия, карты, команды и допуски одинаковы. Начальное установление режима
и полный секундный цикл этим экспериментом не квалифицируются.

`sampled` — прежняя схема контролируемой subcycled-установки с независимым
контролем временного сопряжения. `sdirk2-common` — общие неявные стадии полного
физического графа, PI и идеальных ограничителей скорости. Это другая
временная схема, не оптимизация с требованием побитового совпадения.
Общая схема сохраняет независимое пространственное уточнение профиля/патрубков.

CPU eager, OMP/MKL по одному потоку, три пары в чередующемся порядке;
два подготовительных прогона исключены из медианы. Время включает создание
модели и инициализацию, исключает запись файлов и независимые аудиты.
Native-компиляция и GPU не включены. Среда и SHA-256 исходников находятся
в `summary.json`, точный снимок — `sources.tar.gz`.

Медианы: **sampled 9,716375339 с; common 9,042943770 с**, отношение 1,07447×.
Каждый из восьми прогонов прошёл соответствующий независимый аудит;
в общей ветви на интервале один принятый временной шаг, шесть нелинейных
решений с учётом пространственного уточнения/исправления активной ветви,
без временных отказов или fallback. Остаток энергии не превышает 2,9e-7 Дж.
Расхождение конечных состояний в исходной норме — **0,8214223** при допустимом
значении ≤1. Это не мелкошаговый внешний эталон: оба временных метода имеют
свои локальные оценки ошибки. Независимая экспериментальная валидация
замыканий и глобальная TPD-проверка здесь не выполнялись.

Аудитор общей ветви независимо пересчитывает EOS/химико-гравитационный
профиль и поток HLLC через площадь каждого патрубка, карты и PS/PH машин,
угловой момент, PI, идеальный rate limiter и стадийные N/E-балансы. Он
отклоняет подменённые управляющие скорости и конечные состояния. Стенки,
inventory-level датчики и переходы через legacy fallback в область этого
аудита пока не включены; runtime-проверка баланса стенки есть отдельно.
Ограничения нового runtime перечислены в `docs/PR_SURFACE_CONTROL.md`.

Серия `before_valve_reuse/` сохранена полностью, включая свой снимок кода.
Она также прошла независимые аудиты, но была медленнее: 9,463 → 11,325 с.
В итоговой серии переиспользуется существующий механизм хранения проверенной
активной ветви обратных клапанов; комплементарность проверяется заново на
каждой стадии. Его отсутствие приводило к повторным исправлениям режима
при пространственном уточнении. Более ранний диагностический вариант без
стадийной проверки комплементарности независимый аудит отклонил; он не
включён в квалифицированные измерения.

Это небольшой выигрыш, а не обещание 50× или режима реального времени.
Вся схема пока опциональная; по умолчанию остаётся `sampled`. Для длинных
сценариев, запусков/остановок, независимой проверки стенок и GPU нужны
отдельные проверки. Результаты не относятся к Norne/FIM.

Воспроизведение из корня проекта:

```bash
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=src:scripts python scripts/benchmark_pr_common_surface.py benchmarks/reports/pr_common_surface/request.json --output /tmp/pr-common-surface --repeats 3
```

`prepare-*.json.gz` и `repeat-*.json.gz` содержат полные результаты;
`checksums.json` фиксирует артефакты, `validation.json` — завершённые проверки.

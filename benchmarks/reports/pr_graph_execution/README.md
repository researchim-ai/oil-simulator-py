# Ускорение общего графа PR-установки

## Изменения

Уже существующий обратный AD включён в PRCollocation для малых плотных
CPU-систем. Предыдущий путь строил плотный якобиан через jacfwd; новый
использует jacrev. Уравнения, критерии сходимости, шаги и физические
ограничения сохраняются. CUDA и нативные derivative kernels остаются
прежними; выше dense_limit сохраняются coloring и разреженный решатель.
Плотная ветвь не добавляется как резервный путь для больших систем.

В SDIRK2 состояния физических операторов, уже вычисленные в точном решении
каждой стадии для следующей правой части, используются повторно для отчёта
и потоковых интегралов. Это данные внутри одного шага, не перенос EOS на
другое состояние и не замораживание фаз. Старые ветви доступны через
приватные `_dense_cpu_jacobian_mode` и `_reuse_sdirk_points` для проверки.

## Профиль

`profile-reference.json` и `profile-optimized.json` получены на одном запросе
с инструментированием. Это диагностика с накладными расходами, а не
парные времена производительности. Измеряются обычные вызовы невязки,
преобразования AD, LU, полное время Newton и оставшаяся работа. Вложенные
вызовы невязки внутри AD не складываются повторно с временем AD.

* Исходная ветвь: весь запуск 9.0673 с, Newton 5.8983 с, AD 4.9532 с, обычная невязка 0.9232 с, LU 0.0120 с, вне Newton 3.1690 с.
* Ускоренная ветвь: весь запуск 6.0174 с, Newton 3.0212 с, AD 2.0595 с, обычная невязка 0.9254 с, LU 0.0142 с, вне Newton 2.9963 с.

Здесь основной выигрыш даёт сборка производных, а не линейная факторизация.
В диагностике встречаются системы до 403 неизвестных; конфигурация разрешает
этот плотный размер. Результат не означает плотную сборку для большого графа.

## Парный замер рабочего участка

CPU eager, OMP/MKL по одному потоку. Два чередующихся парных повтора, два
подготовительных запуска исключены. Включены создание/инициализация модели
и решение; аудит и сериализация исключены. Каждый запуск — свежий физический
экземпляр, без продолжения с уже рассчитанной траектории.

Медианы **8.694305 → 5.670637 с**,
ускорение **1.5332×**, сокращение времени **34.78%**.
Все шесть траекторий прошли независимый аудит. По шесть глобальных нелинейных
решений на интервал, без отказов и BE-fallback. Максимальное отличие
отчётных состояний — **1.11e-12**
исходного бюджета ошибки.

Это тот же 16-узловой стенд, рабочий интервал 0,016214944613224563 с из
состояния t=0,706238099587186 с. Он не подтверждает скорость полного пуска,
Norne, GPU или режим реального времени. Снимок исходников, точный запрос,
все результаты и аудиты находятся в `steady/`.

## Непрерывная проверка событий

Новый `audit_pr_controlled_mixed.py` переиспользует независимые аудиторы
common SDIRK2 и действительного BE-fallback по типу принятой записи.
Проверяет часы, стыковку всех состояний/интервалов и глобальные N/E-балансы.
Нормализуется только идентификатор внешнего адаптера к его физически
идентичной reference_surface, без замены физических полей. Требуется явный
начальный checkpoint. Ограничения исходных аудиторов (например, стенки в
common-ветви) не снимаются и экспериментальная калибровка не заявляется.

Тесты создают настоящую смешанную траекторию через принудительный вызов
существующего BE-fallback, затем отклоняют порчу времени, пропущенный шаг,
конечное состояние, общий теплообмен и управляющие скорости. Отдельно
сверены reverse/forward/FD якобианы при изменённых пробных неизвестных и
полные отчёты с включённым/выключенным повторным использованием стадий.

`cycle_driver.py` запускает исходный полный цикл 16-узловой установки:
0–0,2 с пуск, 0,2–0,4 с изоляция, 0,4–1,0 с повторное открытие.
Статус завершения определяется `cycle-optimized/summary.json` и результатом
независимого аудита; файл progress.jsonl сам по себе не подтверждает успех.
Верификационный цикл выполняется параллельно с регрессией и его wall time
не используется как парный замер ускорения.

Воспроизведение рабочего интервала:

```bash
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 CUDA_VISIBLE_DEVICES='' PYTHONPATH=src:scripts \
/home/user/miniconda3/bin/python scripts/benchmark_pr_graph.py \
benchmarks/reports/pr_attraction/qualified-facility/request.json \
/tmp/pr-graph-paired --repeats 2
```

Расширенная регрессия: **314 passed**, пять предупреждений библиотек
(PyTorch beta/deprecation и неконтинуальный searchsorted). Включены реальная
разреженная ветвь и проверки нативных производных/конечного остатка.
Ruff и `git diff --check` прошли. Лог: `regression.log`.

## Итог полного исходного цикла

**Весь интервал 0–1,0 с завершён, независимый аудит принят.** Пуск
0–0,2 с, изоляция 0,2–0,4 с, повторное открытие 0,4–1,0 с. Проверены
139 общих SDIRK2-записей и 10 настоящих BE-записей (пять резервных
макроинтервалов); зарегистрировано 28 отклонённых попыток и 672 решения
коллокационных нелинейных систем, включая работу отклонённых попыток.
Это не счётчик всех внутренних legacy-решений.

Независимый итоговый дисбаланс энергии **2,21844e-7 Дж**, максимальный
компонентный дисбаланс **5,82077e-11 моль**. Все пять патрубков сепаратора
переносят компоненты при пуске и повторном открытии; при изоляции переносы
компонентов и энергии равны точно нулю. Отражение импульса у закрытой
границы сохраняется. `cycle-optimized/operating_checks.json` содержит
интегралы по каждому патрубку и интервальные количества шагов.

Инициализация и интеграция заняли **829.699 с**
(около 13.83 мин) в верификационном прогоне
параллельно с регрессией. Аудит и сериализация в эту величину не входят.
Это не чистый парный замер и не доказательство ускорения полного цикла
относительно старых запусков или работы в реальном времени.

Малые шаги локализованы около резких переключений: минимум принятой
записи 2,83e-6 с; вдали от них шаг возвращается к заданному максимуму
0,02 с. Рабочий интервал ускорен на 34,78%, но стоимость полного
подробного событийного расчёта всё ещё велика. Она требует отдельной
дальнейшей работы над числом стадий/повторных решений и стоимостью
подготовки/проверок; данный результат не закрывает задачу real-time.

`validation.json` связывает парный замер, полный цикл, регрессию и
совпадение текущих исходников с обоими снимками. `checksums.json`
позволяет проверить целостность сохранённых артефактов.

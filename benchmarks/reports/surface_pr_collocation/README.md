# Консервативный PR Gauss4: проверка и парный CPU-замер

15 ноября 2026. CPU, Torch float64, один поток. Проверен новый opt-in
`PRCollocation`, а не вся наземная площадка, пласт или GPU.

## Что реализовано

- Две совместные стадии Gauss4 с неизвестными PR-фаз, P и T.
- Конечная проекция по компонентам, полной энергии и импульсу.
- Общие с прежней моделью HLLC-потоки и силовые/тепловые операторы.
- Проверки EOS/стабильности на стадиях и конце, локальных/глобальных
  балансов и энтропии. Нелинейные допуски не ослаблены.
- Оценка времени полным шагом против двух полушагов, общий бюджет
  попыток и безопасный перенос предложения шага через отчётную границу.
- Явно отмеченный backward-Euler fallback с прежним поиском фаз.
- CLI `--integrator gauss4`; прежний метод остаётся методом по умолчанию.

## Независимая точность

В изохорном теплообмене двух сосудов с чистым метаном Cv и давление PR
выписаны отдельно; правая часть эталонной ODE не вызывает производственные
flash/AD/остатки. DOP853: rtol=1e-13, atol=1e-12.

Для интервала **0,5 с** фиксированные шаги дали:

- dt=0,25 с: ошибка температуры **3,742e-5 К**;
- dt=0,125 с: **2,332e-6 К**;
- dt=0,0625 с: **1,457e-7 К**.

Отношения ошибок **16,046 / 16,004** подтверждают четвёртый порядок на
гладкой ветви. Адаптивный расчёт дал **2,377e-7 К**, 10 принятых полушагов,
без fallback; общий остаток энергии около **1,71e-13 Дж**.
См. `thermal_reference.json`. Это численная точность синтетического
стенда, не экспериментальная точность метана или реального оборудования.

## Двухфазный связанный граф

Существующий `configs/surface_pr_equilibrium_transport.json`: 6 узлов,
два сосуда, две трубы по две ячейки, бинарная PR-смесь с двумя фазами.
Три периода: малое возмущение, перекрытие одной ветви и её открытие.

За **0,0004 с модельного времени** независимо перепроверены **все 14
принятых Gauss-полушагов**, обе стадии и конечные состояния, EOS,
компонентные/энергетические/импульсные балансы, потоки HLLC и закрытые торцы.
Fallback не потребовался. Общие остатки: компоненты порядка 1e-15 моль,
энергия порядка 4e-12 Дж. Это короткая физическая проверка, не результат
ускоренного расчёта длительного промыслового режима.

`closed_graph.json.gz` содержит полный запрос и траекторию;
`closed_graph_audit.json` — результат аудита. Аудитор использует отдельные
скалярные EOS/HLLC-эталоны и не вызывает рабочие flash/потоки/`inspect`.
Подмена стадии, конечной энергии или интеграла потока отвергается тестами.
Сам по себе этот аудит не доказывает глобальный TPD-минимум; стабильность
дополнительно проверяется рабочей моделью.

## Появление и исчезновение фазы

`configs/surface_pr_collocation_phase_cycle.json`: закрытый этановый сосуд,
охлаждение 220 → 200 К с образованием двух фаз и нагрев обратно до 220 К.
Конечная температура двухфазной смеси — 200 К, давление около 0,217836 МПа.
Полная подведённая/отведённая энергия соответствует фазовому запасу.

Оба интервала потребовали явно записанный `backward_euler_fallback`:
**4 принятых полушага**. Весь сериализованный результат прошёл прежний
независимый аудитор; максимальный локальный остаток энергии **3,64e-12 Дж**.
Данные — `phase_cycle.json.gz`, `phase_cycle_audit.json`.
Четвёртый порядок через фазовый переход или непрерывная локализация
момента рождения фазы не заявляются.

## Производительность: узкий гладкий стенд

Три пары, чередующийся порядок запуска. Модель, начальные состояния и
численные настройки методов одинаковы: relative_tolerance=1e-7,
temperature_tolerance_k=1e-5. Модельное время — **0,05 с**. Подготовка
модели и прогрев исключены из измеренного интервала. На каждом принятом
конце независимо проверены T и P против скалярной ODE.

Медианы итоговой серии: **21.859 → 0.569 с**,
отношение **38.39×** в пользу Gauss4.

Заданные бюджеты конечных наблюдаемых: **1e-3 К и 5 Па**. Оба метода
прошли их на всех принятых концах. Это критерии конкретной проверки,
а не экспериментально установленная точность свойств.

Backward Euler: 174 принятых полушага, 94 попытки; максимальные ошибки
около **1,502e-4 К / 0,433 Па**. Gauss4: 2 принятых полушага, 1 попытка;
около **6,26e-10 К / 1,28e-6 Па**. Последние значения — расхождение с
численным эталоном, не независимая абсолютная физическая погрешность.

Ускорение связано с уменьшением числа временных шагов на гладком
теплообмене. В каждой Gauss-попытке остаются **шесть нелинейных решений**
для оценки ошибки против трёх у прежнего метода. Здесь нет сравнения
с Eclipse/OPM или коммерческой наземной динамикой. Коэффициент этого
двухсосудного стенда нельзя переносить на фазовые переходы, большую
сеть, Norne либо CUDA. Исходные парные траектории, времена, версии и
SHA-256 — в `thermal_timing/`.

## Регрессия и границы

**85 тестов прошли, 1 CUDA-тест пропущен**: новые стадии/балансы,
независимый порядок, реальные фазовые переходы, sparse/dense,
атомарный отказ, поддержка прежнего аудитора и старые PR/Newton-пути.
Ruff, форматирование, компиляция и `git diff --check` пройдены.
`validation.json` фиксирует набор проверок и хеши.

Этот адаптер пока не включает стеночные запасы, открытые границы,
роторы/оборудование, гидростатические грани, drift-flux и капельные
популяции. Такие модели отвергаются при выборе Gauss4 и остаются на
прежних специализированных решателях. Чистый GPU-замер не выполнялся.

## Воспроизведение

```bash
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 python scripts/check_pr_collocation.py --output /tmp/pr_order.json
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 python scripts/run_pr_equilibrium_transport.py configs/surface_pr_equilibrium_transport.json --integrator gauss4 --output /tmp/pr_graph.json
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 python scripts/run_pr_equilibrium_transport.py configs/surface_pr_collocation_phase_cycle.json --integrator gauss4 --output /tmp/pr_phases.json
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=src:scripts python scripts/benchmark_pr_collocation.py --output /tmp/pr_timing
```

Для использования аудитора: `audit_pr_collocation.audit_gauss_step(model,
before, record, fluid, commands)`; на fallback-участках используется
прежний `check_pr_equilibrium_transport.audit`. Сырой JSON позволяет
повторить эти проверки без рабочего решателя.

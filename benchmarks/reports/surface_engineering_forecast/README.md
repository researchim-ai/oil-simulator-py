# Инженерная точность и локальный поиск рабочего режима

Цели заданы до подбора настроек: конечное давление и BHP на общих отчётных
датах — 1 кПа; Sw/Sg — 0,0002; Rs — 0,05; компонентные расходы и
накопленная добыча — 0,2%. Это критерии численного сравнения для выбранных
сценариев, не универсальные отраслевые допуски и не экспериментальная
валидация. Независимый аудит массы сохранён: 0,01 кг + 1e-8 от добытого
количества каждого компонента. Допустимость площадки проверяется на
каждом принятом шаге.

## Что изменено

Вместо требования совпадения двух алгоритмов до 0,1 Па рабочие настройки
подбираются по указанным инженерным целям. Выбран умеренный набор:
CNV 1e-6, MB 1e-10, BHP 100 Па, относительный допуск дебита 1e-5,
допуск множителя уставок 1e-7. Сетка и максимальный шаг 90 минут сохранены.

Новый `search_method="continuation_safeguarded"` сначала ищет скобку рядом
с предыдущим режимом: не больше четырёх физических проб в пределах ±20%
предыдущего множителя. Наклоны берутся из уже решённых точек предыдущего
поиска. Оба конца новой скобки должны быть проверены на текущем временном
слое. Если это не удалось, выполняется полный поиск. Численная
несходимость FIM по-прежнему отклоняет временной шаг.

После построения скобки пробная точка немного смещается к недопустимой
стороне: так чаще удаётся сразу ограничить ошибку с двух сторон вместо
повторного улучшения только допустимого конца. Каждая точка решается
физически; границы скобки, допуск ширины и материальный учёт сохраняются.

Полное сканирование выполняется на старте, после смены команд или
запрошенных дебитов, для ранее неограниченного режима и периодически
каждые 16 принятых шагов (`continuation_scan_interval`). При возврате
к полному поиску локальные пробы также участвуют в проверке связности
допустимых выборочных точек. Аудитор проверяет наличие полного набора
проб, сброс истории на событиях и соблюдение периода сканирования.

Это **продолжение локальной рабочей ветви**, а не доказательство глобального
максимума при нескольких раздельных допустимых областях. Для произвольной
немонотонной площадки перенос настроек требует отдельной проверки.
Старый поиск по умолчанию сохранён; новая стратегия включается явно.

## Отвергнутые варианты

- CNV 1e-3 / MB 1e-7 и скобка 1e-6 не прошли суточный аудит массы.
- CNV 1e-4 / MB 1e-8 прошли сутки, но не прошли накопленный аудит массы
  за 30 суток. Суточный GPU-результат этого варианта не является готовым
  ускоренным профилем.
- Умеренный вариант без смещения пробной точки прошёл месяц: 3106 → 2008
  FIM-проб, 10485 → 5975 линейных попыток. Его данные сохранены отдельно
  от окончательного варианта.

Неудачные расчёты сохранены с `failure.json`; они не имеют статуса
успешной квалификации. Допуск аудита массы ради их принятия не менялся.

## Область проверки

Основная модель: синтетический сильно истощающийся пласт, 1024 ячейки,
16 скважин, black-oil и квазистационарная площадка. Месячный график содержит
изменения управления на 10-х и 20-х сутках. Отдельная большая модель:
65 536 ячеек / 64 скважины, слабое истощение, 30 суток. Это не Norne и не
полная переходная многофазная PR-сеть.

CPU — один поток. GPU — RTX 3090 Ti, лимит Torch 8% для малой модели,
12% для большой. Машина и GPU используются совместно с другими задачами;
время означает интегрирование, без построения модели/импортов/итогового
аудита. Отношения времени не являются гарантией ускорения на любой
нагрузке. Числа физических и линейных решений позволяют отдельно видеть
сокращение вычислительной работы.

## Окончательные результаты

- **Малый пласт, CPU, 30 суток:** FIM 3106 → 1686, линейные попытки 10485 → 5013; время 492.921 → 285.115 с.
- **Малый пласт, RTX 3090 Ti, сутки:** FIM 172 → 98, линейные попытки 526 → 242; время 236.245 → 114.826 с.
- **65 536 ячеек / 64 скважины, RTX 3090 Ti, 30 суток:** FIM 57 → 53, линейные попытки 185 → 162; время 93.319 → 152.839 с.

Малый месячный вариант относительно уточнённого строгого эталона с максимумом
45 минут: давление 27.964 Па, BHP 164.787 Па,
компонентные расходы 0.09576%, суммарная
накопленная добыча компонентов 0.11355%.
Все инженерные цели выполнены. Ускоренный месяц содержит 490 принятых
шагов без отказов; управляющие события сохранены.

Свежая малая GPU-пара дала отношение времени
2.057. На большой
модели ускорение времени не подтверждено: число проб снизилось мало,
а замер на общей карте оказался медленнее старого контрольного запуска.
Универсального коэффициента ускорения для любых размеров и режимов нет.
Большой пример сохранил прежние строгие допуски, чтобы не переносить
настройки MB сильно истощающегося пласта на слабое истощение без проверки.

73 теста прошли, один CUDA-тест пропущен в CPU-наборе; реальные GPU-прогоны
выполнены отдельно. Сохранены проверки событий, периодического полного
сканирования, отката и рестарта, отказа при подмене физики/PVT и
некорректных допусков.

## Воспроизведение и артефакты

Готовый профиль — `configs/fim_blackoil_facility_depletion_operational.json`.
Прежние профили и глобальные значения по умолчанию не заменены.

```bash
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
MPLCONFIGDIR=/tmp/pr_forecast_mpl PYTHONPATH=src:scripts \
/home/user/miniconda3/bin/python scripts/run_fim_facility_forecast.py \
  --config configs/fim_blackoil_facility_depletion_operational.json \
  --schedule benchmarks/reports/surface_forecast_profiles/schedule.json \
  --days 30 --report-days 1 --device cpu --output /tmp/operational_month
```

Проверка относительно строгого расчёта на прежнем шаге:

```bash
MPLCONFIGDIR=/tmp/pr_forecast_mpl PYTHONPATH=src:scripts \
/home/user/miniconda3/bin/python scripts/check_facility_tolerance_pair.py \
  benchmarks/reports/surface_reusable_snapshot/month /tmp/operational_month \
  --budgets benchmarks/reports/surface_engineering_forecast/budgets.json \
  --days 30 --output /tmp/operational_comparison.json
```

Для сравнения с `surface_forecast_profiles/depletion_run4` добавить
`--time-refinement`. Это проверка полного численного профиля относительно
уточнённого решения, не чистое уточнение шага при идентичных настройках.

`final_month`, `final_gpu`, `large_gpu` — окончательные прогоны.
`strict_gpu` — свежий строгий GPU-контроль. Месячный CPU-контроль находится
в `../surface_reusable_snapshot/month`; уточнённые эталоны — в
`../surface_forecast_profiles`. `continuation_month` — умеренный вариант
до смещения пробной точки; его изменённые исходники — в `unbiased_source`.
`engineering_month` и `fast` — отвергнутые аудитом массы варианты.
`engineering_gpu` — только суточный опыт отвергнутых для месяца настроек.
`executed_sources.tar.gz` содержит окончательный код, `before_sources.tar.gz`
— код перед этой серией, `change.patch` — изменения. Протоколы каждого
прогона фиксируют исходники, конфиг и PVT; `artifact_sha256.json` —
контрольные суммы опубликованных файлов.

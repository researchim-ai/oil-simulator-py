# Отложенная запись CPR-графа: эксперимент не принят по скорости

Измерены фактические применения предобуславливателя на месяце модели
65 536 ячеек / 64 скважины: из 70 линейных решений 36 использовали CPR
один раз, 28 — два раза, четыре — три раза и два — четыре раза.
Прежняя политика записывала граф уже на втором применении: 34 записи
и 42 повтора графа на 112 применений CPR.

## Экспериментальная политика (не включена по умолчанию)

Только внутри транзакционного поиска ограничений связанной модели
первые три применения CPR выполняются обычным способом; четвёртое
записывает CUDA-граф и последующие используют его. Самостоятельный
пластовый расчёт, включая обычный Norne/SPE9, сохраняет прежний порог:
один прогревочный вызов, запись со второго. Графы глобально не отключаются.

Для каждого нового предобуславливателя счётчики начинают с нуля. В статистику
линейного решения добавлены `cpr_graph_eager_calls`, `cpr_graph_captures`,
`cpr_graph_replays`. Эти счётчики относятся к графовой ветви исполнения.
CPU и аварийный обычный путь не учитываются как прогрев CUDA-графа.

Постоянные буферы и переиспользование графа между разными матрицами
**не реализованы**. AMG обновляет численные коэффициенты Чебышёва,
а также матрицы и плотную матрицу грубого уровня; старый граф не может
просто продолжать работать с новыми Python-объектами. Нужны обновляемые
буферы всех входов и корректная инвалидизация при смене структуры/ветвей.
Эксперимент не выдаёт такое переиспользование за выполненное.

## Проверка

Публичный профиль неизменен:
`configs/fim_blackoil_facility_field64k_continuation.json`.
GPU — RTX 3090 Ti, лимит Torch 12%, 30 суток, два события. Число физических
решений прежнее: 29 FIM-проб, 70 линейных попыток, 9 стадий, без отказов.
Графовых записей стало **34 → 2**, повторов **42 → 2**, обычных
прогревочных вызовов **70 → 110**. Всего 112 применений, распределение
по линейным решениям неизменно. Ошибок записи нет, графы остались включены.

Все принятые состояния, трассы поиска, скважинные/поверхностные результаты
и материальный учёт сравниваются точно через `require_equal`, а не только
по конечным полям. Независимый аудит массы и контроль неизменности
исходников включены. Проверка с уточнённым шагом времени также выполнена.

35 CPU-проверок прошли, одна CUDA-проверка пропущена в CPU-режиме.
На настоящей GPU прошли 11 проверок: семь повторных проверок политики
и четыре GPU-теста, включая SPE9, меняющуюся правую часть, новую матрицу,
остановленные скважины и сравнение графа с обычным исполнением.
Новых замечаний Ruff нет; прежние замечания сохранены в `lint.json`.

## Протокол

`run_counted.py` оборачивает `_matvec_graph` только счётчиками вызовов,
успешных записей, повторов и ошибок; ни уравнения, ни аргументы, ни
возвращаемые значения не меняются. Обе сравниваемые версии запускаются
через одинаковую обёртку. Для воспроизведения эксперимента распакуйте
`after_source.tar.gz` в отдельный каталог. В рабочем коде уже возвращён
прежний порог, поэтому запуск текущего репозитория не воспроизводит
отвергнутую политику. Например, из корня репозитория:

```sh
mkdir -p /tmp/cpr-delay-candidate
tar -xzf benchmarks/reports/surface_cpr_capture_delay/after_source.tar.gz -C /tmp/cpr-delay-candidate
CUDA_VISIBLE_DEVICES=GPU-2f9ce359-f3f4-accc-bf9c-31bc88bb1cb7 CUBLAS_WORKSPACE_CONFIG=:4096:8 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 python benchmarks/reports/surface_cpr_capture_delay/run_counted.py /tmp/cpr-delay-candidate /tmp/cpr-counts.json --config benchmarks/reports/surface_cpr_capture_delay/large.json --schedule benchmarks/reports/surface_cpr_capture_delay/schedule.json --days 30 --report-days 5 --device cuda --cuda-memory-fraction .12 --output /tmp/cpr-delay-run
```

Сохранены точные исходники, `source.patch`, тесты, конфигурации, журналы,
траектории и счётчики. Для архивного runner нужен абсолютный путь PVT
как в `large.json`. Это синтетический black-oil пласт и квазистационарная
площадка; не полный Norne, не подробная PR-динамика, не экспериментальная
валидация. Время означает интегрирование без построения модели, импортов
и итогового аудита. GPU и машина используются совместно с другими задачами.

## Результат и решение

Две свежие GPU-пары, вторая в обратном порядке: 18,565 → 18,438 с
и 18,002 → 18,649 с. Медианы 18,284 → 18,544 с: кандидат примерно
на 1,4% медленнее. **Ускорение не подтверждено; порог три не включён
в рабочий решатель.** Меньшее число записей графов само по себе
не является выигрышем: дополнительные обычные применения CPR тоже стоят
времени. Вывод относится к проверенной политике, не ко всем возможным
оптимизациям графов или AMG.

В рабочем коде остались счётчики и внутренний параметр прогрева с прежним
значением по умолчанию 1. Нет новых пользовательских настроек модели.
`source.patch`/`after_source.tar.gz` описывают отвергнутый эксперимент;
`production.patch`/`production_source.tar.gz` — окончательное состояние.

CPU-месяц экспериментальной версии: все 490 стадий, поля, трассы и
материальный учёт совпали точно с `surface_bhp_cpr/small`. Независимый
аудит массы пройден. Этот запуск проверяет корректность, а не выигрыш
CUDA-политики на CPU. Предварительный CPU-прогон был остановлен при
ограничении области новой политики; квалифицирован отдельный полный
прогон неизменной экспериментальной версии.

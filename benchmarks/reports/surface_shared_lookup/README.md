# Общий поиск интервала давления для столбцов PVT/PVTO

`PressureLookup` ищет интервал давления один раз и использует его для
нескольких столбцов свойств. На общей PVT-оси поиск разделяют Rs, Bo/Bw/Bg
и вязкости. Для двух выбранных PVTO-таблиц один поиск каждой оси используется
и для Bo, и для mu_o. В типичном вызове состояния число поисков давления
сокращено с 11 до 3; выбор Rs-пары и прочие поиски модели сюда не относятся.

Арифметика сохранена в виде `lo + delta * (hi-lo) / span`, без переноса
деления до умножения. Сохраняется правило правой стороны узла и float64.
Объект поиска живёт только в пределах одного вызова свойств. Индексы,
давления и AD-граф не кэшируются между пробами Newton/шагами FIM.
[Метод и ограничения](../../../docs/BATCHED_BLACKOIL_HYDRAULICS.md).

## Полные FIM-прогоны

Один Torch CPU-поток, CUDA отключена, float64. Три последовательные пары
на каждый размер, без одновременных CPU-тестов. Контроль `repeated`
повторно создаёт текущий lookup для каждого столбца; `shared` разделяет
его между столбцами. Это управляемый повтор/переиспользование поиска
в одном текущем ядре, не запуск двух разных бинарных версий проекта.
Геометрия, физика, сетка квадратуры, допуски и уставки совпадают.

- **512 скважин / 1024 ячейки / одни сутки:**
  медианы **1,645 → 1,579 с CPU**, время меньше на **4,0%**.
- **2048 скважин / 4096 ячеек / одни сутки:**
  медианы **4,764 → 4,538 с CPU**, время меньше на **4,8%**.
- **64 скважины / 128 ячеек / 65 PVTO-таблиц:**
  медианы **0,884 → 0,879 с CPU**. Разброс перекрывается;
  ускорение этой расширенной PVT-задачи **не заявляется**.

Все девять пар приняли один суточный шаг. Конечные давление, Sw/Sg,
Rs и накопленные компонентные отборы **совпали побитно**. Обе траектории
каждой пары прошли независимый аудит фактических расходов/приёмника и
запасов пласта. Применены фиксированные бюджеты: 0,1 Па, 1e-8 по
насыщенностям, 1e-5 по Rs и 0,01 кг по компонентным отборам.

В 2048-скважинном прогоне число инструментированных поисков интервала
давления снизилось **9856 → 2688** при том же количестве запросов столбцов
(**9856**). Это счётчик пакетного вычисления состояния/PVTO, не всех
поисков таблиц в решателе. Результаты и времена каждого запуска — в
`comparison_summary.json`, `summary.json` и `lookup_policy.json`.

## Тензоры для производных: отдельная проверка одного вызова свойств

`retained_storage_cpu`: реальный пример PVT из конфигурации проекта,
128 потоков × 256 давлений с обеих сторон точки насыщения. Через
`torch.autograd.graph.saved_tensors_hooks` измерены уникальные хранилища,
сохраняемые при прямом вычислении для последующего backward, включая
заимствованные входы. Затем сопоставлены значения и градиенты обоих путей.

- repeated: **11 053 464 байт**, 51 уникальное хранилище;
- shared: **8 956 312 байт**, 43 хранилища;
- разность: **2 MiB**, около **19%**.

Это измерение данного forward-графа, **не пиковая память всего процесса,
пласта, allocator или GPU**. Прямые значения и градиенты прошли сравнение.
Исходники, входные размеры и точное определение метрики — в protocol и
`check_shared_lookup_memory.py`. Скорость этим отдельным тестом не измеряется.

## Месячная связанная модель и регрессия

`coupled30_cpu`: 3 ячейки / 2 скважины / 30 суток, шесть пятисуточных шагов,
обратная связь ограничений оборудования с добычей. Пройден независимый
аудит массы и ограничений. Строгое сравнение с сохранённым эталоном до
этого блока (`surface_compact_quadrature/final_coupled30_cpu`) дало
побитное совпадение конечных полей и отборов. Разность времени этих
запусков разных версий не используется как контролируемый speedup.

**229 passed, 14 skipped**, точный лог — `regression.txt`.
Проверены скалярное/пакетное давление, разные формы входа, неодинаковые
PVTO-оси, точные узлы, первые/вторые производные, конечные разности,
отсутствие повторного поиска между столбцами и отсутствие устаревшего
lookup при новой пробе давления. Повторно проверены полный FIM/Шур,
совпавшие границы, restart, rollback и независимые учётные аудиторы.

## Границы

Новый путь автоматически действует в существующем `torch_batch`;
новых физических параметров и переключателей конфигурации нет.
Старый интерфейс интерполяции отдельного столбца сохранён.
Количество host-read не увеличено. Общая оркестрация, планировочное
чтение активных интервалов и отчёт остаются существующими.

CPU-выигрыш умеренный. Сокращение числа поисков не выдаётся за такой же
коэффициент ускорения всего решателя. CUDA-скорость, GPU-память и Norne
не квалифицированы: устройствам NVIDIA нет доступа из этого окружения.
Матрица пласта остаётся разреженной; `blackoil_fim.py` и `torch_linear.py`
не изменены. Область физики — существующая homogeneous Rs-only
изотермическая ветвь дерева. Это эквивалентность вычислений, не
экспериментальная калибровка PVT или гидравлических корреляций.

## Воспроизведение

Последовательно, выходные каталоги должны отсутствовать:

```bash
export CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=src:scripts
python scripts/run_shared_lookup_forecast.py --lookup repeated --config benchmarks/reports/surface_pipe_batch/wells2048_torch_batch_input.json --output /tmp/lookup_repeated2048
python scripts/run_shared_lookup_forecast.py --lookup shared --config benchmarks/reports/surface_pipe_batch/wells2048_torch_batch_input.json --output /tmp/lookup_shared2048
python scripts/check_shared_lookup_memory.py --output /tmp/lookup_memory
pytest -q tests/test_blackoil_pressure_lookup.py tests/test_blackoil_pipe_batch.py tests/test_blackoil_pvto_batch.py
```

Hashes, повторные аудиты и сравнения — `validation.json`.

# Направляющая чувствительность связанного ограничителя

Новая опциональная стратегия `control.search_method="sensitivity_safeguarded"`.
Обычный быстрый конфиг остаётся на `facet_safeguarded`: месячная точность
подтверждена, выигрыш полного времени пока не подтверждён.
Область — существующий изотермический black-oil пласт, добывающие скважины,
сборное дерево и квазистационарная площадка с общим множителем дебита.
Это не новая физическая модель ствола/труб и не валидация реального оборудования.

Для текущего сошедшегося состояния решается линейная система

```
[A C; B D] [du/dlambda; dBHP/dlambda] = [0; rate_mask * base_cap / 86400].
```

Используются действующие блоки Якобиана, исключение Шура и FGMRES/CPR.
Полная плотная матрица пласта не собирается. Градиент компонентов учитывает
отклик всех ячеек, скважин и сборной сети, а не только замороженную ячейку.
Дополнительная копия разреженных значений ограничена
`control.sensitivity_sparse_budget_bytes` (по умолчанию 256 МиБ, учитывается
исходный массив и рабочая копия). Это не предел общей памяти CPR/AMG/процесса.

На малой площадке делаются четыре направленные пробы h/-h и h/2/-h/2;
используются только конечные возрастающие чувствительности одной и той же
грани ограничения, согласованные между h и h/2. Это предложение следующей
точки, а не принятие линейно предсказанного состояния. Принятая точка
всегда проходит полный FIM и оборудование. При старте, смене команд/уставок
и застое разрешены вспомогательные линейные решения; на гладких продолжающихся
интервалах сохраняется дешёвая тёплая проба. Сбой вспомогательной СЛАУ,
непригодный остаток или исчерпание бюджета возвращают обычный поиск.

При `reuse_inactive_caps=true` новая стратегия также применяет сертификат
версии 2: оставляет 25% запас до точного неактивного переключателя вместо
2x запаса архивной версии 1. Неравенство неактивности проверяется для всех
скважин. Сошедшаяся недопустимая точка может подтвердить другую недопустимую
точку того же старого состояния/шага; допустимые поля не экстраполируются.
Аудитор понимает обе версии, поэтому предыдущие месячные артефакты сохранены.

## Короткие парные результаты

1024 ячейки, 16 скважин, 0,003 суток, один CPU-поток. Три пары с
чередованием порядка. Медиана **22,191 → 17,396 с** (общий хост).
Полных FIM-решений **165 → 139**, вспомогательных линейных решений 8,
проб малой площадки 32, отказов макрошагов нет. Точность прошла фиксированные
бюджеты: давление/скважинное BHP 0,1 Па, Sw/Sg 1e-8, Rs 1e-5,
относительные накопления/дебиты 1e-7. Например, разность давления 4,33e-6 Па,
накопленного отбора 1,34e-9 относительно. Это численная регрессия,
не доказательство абсолютной физической точности. Полные данные —
`paired_comparison.json`, шесть прогонов `pair*`, точные исходники —
`executed_sources.tar.gz`.

Разложение эффекта: базовый поиск 165 FIM; новая стратегия без вспомогательных
СЛАУ (бюджет 1 байт) — 141 FIM; полная новая стратегия — 139 FIM.
Таким образом, в этом коротком случае основную экономию даёт более полный
доказанный интервал неактивности, ещё два решения исключены направляющими
чувствительностями. Абляция выполнена один раз; её время не является медианой.
Первый безусловный вариант чувствительностей был отвергнут: 183 вместо 165
FIM и нарушение частного бюджета накоплений. `short_comparison.json` хранит
этот предварительный не принятый результат; актуальная стратегия адаптивна.

## GPU и проверки

На RTX 3090 Ti: 65 536 ячеек, 16 скважин, один стартовый интервал
0,00005 суток (4,32 с модельного времени). Полных FIM **20 → 15**,
вспомогательных СЛАУ 8; точность прошла те же строгие бюджеты.
Пик аллокатора Torch: 509 432 832 байт выделено, 757 071 872 зарезервировано;
контекст CUDA и чужие процессы не учитываются. Аллокатор ограничен 8%.
Две последовательные GPU-пробы не устанавливают устойчивый коэффициент
ускорения большого прогноза; это проверка масштабирования и точности.
Данные — `gpu_large_comparison.json` и `gpu_large_*`.

Проверены производные против целых FIM-прогонов с конечными разностями
(обычные/структурированные скважины, смешанные активные режимы), направление
оборудования против полного FIM, смена газового/нефтяного ограничения,
команды, перезапуск, откат и ограничение памяти. Отдельные CUDA-тесты покрывают
обычный и структурированный блок. Логи приложены. Публичный fast-конфиг
не переключён на новую стратегию. Месячный контроль завершён на отдельном
снимке; итог сохранён в `month_comparison.json`.

## Повтор короткой проверки

Из корня проекта (выберите свободные выходные каталоги):

```sh
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=src:scripts \
python scripts/run_fim_facility_forecast.py --config benchmarks/reports/surface_capacity_tangent/reference_config.json --days .003 --report-days .003 --device cpu --output /tmp/capacity_reference
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=src:scripts \
python scripts/run_fim_facility_forecast.py --config benchmarks/reports/surface_capacity_tangent/candidate_config.json --days .003 --report-days .003 --device cpu --output /tmp/capacity_candidate
PYTHONPATH=src:scripts python scripts/check_facility_capacity_search.py /tmp/capacity_reference /tmp/capacity_candidate --days .003 --output /tmp/capacity_check.json
```

Только стратегия поиска и её вспомогательный бюджет могут различаться;
проверяющий запрещает изменение физики, уставок, FIM- и временных допусков.

Месячный контроль: accepted=True. CPU: 1706.572 → 1827.049 с на общем хосте. Строгие бюджеты, скважинные истории и проверка против более строгого архива — month_comparison.json. До accepted=true расширять область приёмки нельзя.

Месячный итог: 11 892 → 11 572 FIM (−2,69%), но время 1706,57 → 1827,05 с
(+7,06%) на общем хосте. Пройдены строгие бюджеты численной регрессии и
бюджеты против уточнённого архива. `accepted=true` в сравнении означает
точность и меньшую работу FIM, а не подтверждённый выигрыш wall time.
Включение по умолчанию отложено до повторного парного замера.

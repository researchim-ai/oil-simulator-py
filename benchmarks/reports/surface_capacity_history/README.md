# История поиска для сокращения FIM-проб

Опция `coupled_facility.control.reuse_capacity_history=true` добавляет к
`facet_safeguarded` два вида предложений, не меняя критерий допустимости:

1. При одинаковых уставках локальные секущие одного и того же ограничения
   предыдущего поиска дают одну пробную поправку. Исключаются точки,
   полученные по сертификату, далёкие насыщенные уставки, слишком узкие
   пары, отрицательные и нечисловые наклоны.
2. На последовательности одинаковых шагов начальная проба учитывает
   тенденцию последних множителей, включая вторую разность при наличии
   истории. Изменение ограничено 10% предыдущего множителя; предложение
   обязано лежать внутри уже проверенной скобки.

Каждая новая точка требует физического решения текущего шага. Сканирование
допустимой области, допустимый/недопустимый концы скобки, её допуск,
лимит проб и обычный защищённый поиск сохранены. При смене управляющих
воздействий или запрошенных дебитов история не используется. При смене
шага отключается экстраполяция во времени; пробный наклон остаётся только
предложением, не сертификатом. После неудачи используется штатный откат.
История не удерживает поля пласта и не добавляет вспомогательных СЛАУ.

По умолчанию опция выключена. `capacity_history_proposals` считает только
предложения по наклону (не более одного на поиск), а `capacity_history_anchor`
хранит несколько скаляров для тенденции во времени. Ветви других методов
поиска этой опцией не ускоряются.

## Проверка точности

`scripts/check_facility_history_pair.py` допускает изменение только этой
опции. Проверяются завершение, контрольные суммы траекторий, материальный
аудит, одинаковые модель/PVT/события/устройство/отчётные даты и сетка
принятых шагов. Отдельно сравниваются BHP, режимы, компонентные расходы
и накопления **каждой принятой стадии**, а не только суточные отчёты.

Заранее заданные бюджеты сравнения: давление и BHP 0,1 Па, насыщенности
1e-8, Rs 1e-5; относительные расходы и накопления 1e-5 (0,001%).
Это допуски сравнения двух способов поиска, а не ослабление допусков
решателя, гарантия физической точности или экспериментальная калибровка.
При нормировании расходов используется нижний масштаб 1e-8 кг/с,
накоплений — 1 кг. Совпадение режимов требуется на каждой стадии.

Исследуемая модель: синтетический истощающийся black-oil пласт,
1024 ячейки / 16 скважин и квазистационарная площадка. Это не Norne и не
квалификация полной переходной PR-сети. GPU — только RTX 3090 Ti,
лимит Torch 8%; карта занята сторонней нагрузкой. Времена не изолированы.

## Уточнение допустимого конца скобки

У первого месячного варианта было 3106 → 2625 FIM-проб и
492,921 → 400,525 с. Проверка всех стадий обнаружила максимальное отличие
BHP 0,115145 Па при заранее заданном пределе 0,1 Па: этот вариант
**не прошёл строгую приёмку**. Допуск не изменён.

Окончательный алгоритм при остаточном нормированном запасе ограничения
ниже -1e-8 делает ещё одну физическую пробу по секущей уже узкой скобки.
При недопустимости этой точки остаётся прежний допустимый конец.
Расходы не масштабируются, скобка не расширяется. Это устраняет часть
систематического недобора при раннем попадании исторического предложения
в интервал допуска, ценой части экономии физических проб.

## Окончательный вариант

- **CPU, 30 суток, два события:** FIM-пробы 3106 → 2794 (на 10.05% меньше); время 492.921 → 429.115 с. Максимальное отличие BHP на всех стадиях 0.0705266 Па, относительных компонентных расходов 9.25371e-07, накоплений 9.63754e-08.
- **RTX 3090 Ti, 1 сутки:** FIM-пробы 172 → 170 (на 1.16% меньше); время 130.934 → 130.466 с. Максимальное отличие BHP на всех стадиях 0.00797184 Па, относительных компонентных расходов 1.85919e-07, накоплений 9.63754e-08.

Обе пары прошли неизменённые строгие бюджеты сравнения; режимы совпадают
на всех принятых стадиях, отклонённых шагов нет. 44 теста прошли, два
CUDA-теста пропущены в CPU-наборе; отдельный реальный GPU-прогон выполнен.
Время на общей машине — наблюдение, не изолированная оценка ускорения.
Основное подтверждение экономии — число физических FIM-проб.

Готовый профиль: `configs/fim_blackoil_facility_depletion_history.json`.
Обычный `depletion_forecast` и глобальное значение по умолчанию сохранены.
Месячный эталон без истории: `../surface_reusable_snapshot/month`.
Не прошедший приёмку вариант хранится в `month` и `month_comparison.json`;
его версия сопряжения — `unpolished.py.txt`. Окончательный — `polished_month`.
GPU-эталон — `gpu_False`, окончательный вариант — `polished_gpu`.

Пример запуска (CPU, один поток):

```bash
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
MPLCONFIGDIR=/tmp/pr_forecast_mpl PYTHONPATH=src:scripts \
/home/user/miniconda3/bin/python scripts/run_fim_facility_forecast.py \
  --config configs/fim_blackoil_facility_depletion_history.json \
  --schedule benchmarks/reports/surface_forecast_profiles/schedule.json \
  --days 30 --report-days 1 --device cpu --output /tmp/history_month
```

Сравнение:

```bash
MPLCONFIGDIR=/tmp/pr_forecast_mpl PYTHONPATH=src:scripts \
/home/user/miniconda3/bin/python scripts/check_facility_history_pair.py \
  benchmarks/reports/surface_reusable_snapshot/month /tmp/history_month \
  --days 30 --output /tmp/history_comparison.json
```

Контрольные суммы файлов отчёта: `artifact_sha256.json`.

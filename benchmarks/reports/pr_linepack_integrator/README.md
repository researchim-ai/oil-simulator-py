# Ускорение PR-linepack с проверкой временной точности

Итоговая серия находится в **`validated/`**. Две чередующиеся пары CPU,
один поток PyTorch, один запрос `surface_pr_linepack.json`:

- прежний Ньютон, нулевые начальные Darcy-скорости, step doubling:
  **35,279864 с**;
- существующий улучшенный Ньютон, ограниченная история линейзации,
  начальные Darcy-скорости из сошедшихся решений, step doubling:
  **17,653708 с**, **1,99844×**;
- тот же расчёт с опциональным `embedded_be`:
  **14,637670 с**, **2,41021×** относительно первого варианта.

Это медианы полного построения, инициализации и решения короткой
синтетической задачи **0,003 с моделируемого времени**. Импорты выполнены
до замера, аудит и запись исключены. Сначала выполнены reference/newton/embedded,
затем порядок обращён. EOS патрубков пакетный во всех трёх вариантах.

Все шесть траекторий прошли независимый NumPy-аудит PR-профилей, геометрии,
Дарси и балансов компонентов/энергии. Число принятых подшагов во всех
вариантах — **14**. Нелинейных решений с учётом отброшенных проб:
**56 → 55 → 46**. Линейные системы оценщика в этот счётчик не входят.
Разница отчётных состояний между реализациями — максимум
**1,383e-8 исходного временного бюджета**.

## Проверка точности

Отдельный расчёт с максимумом макрошага **0,00025 с**, step doubling и теми
же физикой/допусками дал 24 принятых подшага. Его балансовый аудит пройден.
Максимальные расхождения трёх методов с этим сгущением — соответственно
**0,707525 / 0,707525 / 0,707525 бюджета**, все меньше единицы.
См. `validated/refinement.json` и `refined.json.gz`.
Этот запуск выполнялся параллельно регрессии: его время не используется
для сравнения производительности. Сгущение проверяет временную
чувствительность той же модели; экспериментальным эталоном оно не является.

В `single_step_rejected/` сохранён более быстрый отклонённый вариант:
он заменял две принимаемые половины одним полным BE-шагом. Балансы сходились,
но расхождение со сгущением достигло **1,45058 бюджета**. Его ускорение
не входит в итоговые результаты. Текущий `embedded_be` сохраняет обе
консервативные половины и заменяет только дополнительный полный прогон
линейной оценкой ошибки второй половины с учётом всего макроинтервала.

## Как применяется

По умолчанию работают улучшенный Ньютон, начальное приближение Darcy-скорости
и прежний `step_doubling`. Для опционального оценщика задайте в существующем
конфиге `model.integration.temporal_error_control="embedded_be"`.
Ни физические уравнения, ни исходные допуски не ослабляются. Это BE-половины
с другой оценкой ошибки, а не SDIRK2. Холодный запуск, события и фазовые
изменения требуют обычной проверки; недопустимая линейная проба возвращает
расчёт к step doubling. Условия описаны в `docs/SURFACE_MODELING.md`.

Перенос численной линейзации использует существующий `DenseNewtonHistory`
только на CPU, максимум две записи уровней квадратуры, с проверкой
топологии, управлений, шага, близости точки и качества сходимости.
Скорость последнего сошедшегося локального решения — лишь начальное
приближение Ньютона; расход заново определяется полной системой.
Явный предиктор этот перенос не изменяет.

## Воспроизводимость и границы

`validated/summary.json`, `samples.json`, шесть `repeat-*.json.gz`,
`request.json` и `sources.tar.gz` содержат точные входы, зафиксированные
исходники, результаты и аудиты. `validation.json` объединяет итоговые
проверки; `checksums.json` фиксирует файлы. Счётчики якобиана относятся
к принятым физическим подшагам; null у прежнего решателя означает
отсутствие счётчика. Фактическое время охватывает и отброшенные пробы.

`before_velocity_seed/` — промежуточная завершённая серия;
`interrupted/` — прерванный замер. Они не включены в итоговые медианы.
Исходники проверялись на неизменность в течение каждой полной серии.

Это не замер Norne, всей 16-узловой установки или GPU. Не подтверждены
ускорение 50×, работа в реальном времени или общая квалификация всех
многофазных режимов. Существующий лимит плотной сети в 768 неизвестных
сохраняется. Две пары — проверка локального эффекта, не статистическая
квалификация производительности.

```bash
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 CUDA_VISIBLE_DEVICES='' \
PYTHONPATH=src:scripts python scripts/benchmark_pr_linepack_eos.py \
  configs/surface_pr_linepack.json --experiment integrators --repeats 2 \
  --output /tmp/linepack-integrators
```

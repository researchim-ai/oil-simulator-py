# Управляемый жидкостно-тепловой сценарий

15 ноября 2026. Torch CPU float64, один поток. Это проверка sampled-контроля
на синтетической однофазной модели с постоянными свойствами. Она не
подтверждает полную PR-сеть, реальное оборудование или непрерывную защиту.

## Реализовано

`CollocationThermalStation` сопрягает существующие термостаты/PID,
выдержки температурных защит и ограничители нагрева/охлаждения с
`ThermalLiquidCollocation`. Код правил sampled-защит и распределения
мощности общий с прежней `ThermalLiquidStation`.

Сохраняются целочисленные часы, память PID, удерживаемые фактические
мощности, таймеры/защёлки защит, операторский trip и внешняя маска приводов.
Команда остановки снимает момент, но не стирает скорость, массу или энергию.
Проверены выбег, безопасный/запрещённый reset, manual → auto, anti-windup,
разбиение отчётов и общий бюджет вычислительных попыток.

Расписание использует общий механизм физического replay. При resume
завершённые периоды воспроизводятся один раз; сверяются записи и финальная
память. Тесты отвергают подменённые температуры/PID даже с пересчитанным
checksum. CLI пишет результат атомарно и сохраняет прежний файл при ошибке.

## Сквозной сценарий и независимый эталон

`configs/surface_collocation_thermal_control.json`: два насоса, инерционная
труба с четырьмя тепловыми ячейками, экспортная арматура, источник 1000 кг,
тепловая стенка. Моменты 5/7 Н·м; ручной запрос термостата 1000 Вт
ограничивается общей доступной мощностью 100 Вт. Опрос — каждые 0,05 с.
Порог жидкости узла `h` — 300,02 К, выдержка 0,05 с.

Периоды 0,07 + 0,08 + 0,15 с пересекают управляющие отсчёты, не меняя
их фазу. Первый sample с нарушением — 0,05 с; единственное срабатывание
защиты — **0,10 с**. После него оба момента равны нулю, валы продолжают
выбег. Ровно шесть отсчётов, без дубликата на правой границе.

Независимая консервативная ODE (`ConservativeReference`) интегрируется
DOP853 с rtol=1e-12 и atol=1e-9 по сегментам с заранее ожидаемыми
командами: 5/7 Н·м до 0,10 с, затем 0/0; нагрев 100 Вт. Для RHS не
используются производственные гидравлические/тепловые операторы. Этот
эталон проверяет физическую траекторию, а не только согласованность логов.

На всех **78 принятых шагах** выполнены выбранные бюджеты наблюдаемых:
давление 1 Па, расход 1e-8 м³/с, скорости 1e-4 рад/с, температуры 1e-5 К,
запас источника 1e-7 кг. Максимальные расхождения с ODE:

- давление **1,44e-5 Па**, расход **9,90e-13 м³/с**;
- температура **5,31e-11 К**, запас источника **1,81e-10 кг**;
- максимальный общий энергетический остаток **1,41e-8 Дж**.

Это численные расхождения синтетического стенда, не экспериментальная
точность жидкости или датчиков. В частности, значения ниже точности
самого ODE-эталона нельзя трактовать как независимую абсолютную погрешность.
Проверены все гидравлические и тепловые состояния на границах команд:
никакого сброса запасов или скорости там нет.

Длительность диагностического расчёта — около **3,50 с** за 0,30 с модели.
Это одиночный запуск, **не сравнительный бенчмарк производительности**.
GPU не запускался.

## Перенос предложения шага

Короткий остаток отчётного/управляющего окна больше не схлопывает рабочее
предложение следующего шага при достаточно малой оценке ошибки. Если
ошибка близка к допустимой, следующий шаг уменьшается. Проверены остатки порядка 1e-12 с, в том
числе окно, которое целиком короче minimum_dt, при представимом времени.
Фактический остаток всё равно рассчитывается, состояния не экстраполируются.

В статическом probe следующее окно 0,02 с требует **21 шаг** с
восстановленным прежним правилом переноса против **одного шага** с
сохранённым предложением. Физические состояния совпали побитово.
Это проверка числа операций и политики переноса, не утверждение о
21-кратном ускорении всей сети. Данные — `step_carry.json`.

## Проверки и данные

**226 тестов прошли** выбранным регрессионным набором, включая старые
контроллеры, защиты, тепло, рецикл, новые sampled-контуры, разреженную
математику, checkpoint/replay и атомарный отказ CLI. Ruff, проверка
форматирования, компиляция Python и `git diff --check` прошли.

Запуски CLI «целиком» и «частично + resume» дали одинаковый JSON.
В API-проверке полное расписание и возобновлённое также совпали побитово.
`summary.json` содержит бюджеты, расхождения и SHA-256 исходников;
`run.json.gz` — конфигурацию, полное расписание, checkpoint и траекторию;
`validation.json` — перечень пройденных проверок.

Дополнительно тестами явно подтверждено ограничение sampled-защиты:
короткий температурный выброс между отсчётами может быть пропущен при
интервале 0,05 с, но обнаруживается при интервале 0,005 с. Непрерывная
локализация остановки вала или других физических событий не заявляется.

## Воспроизведение

```bash
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 python scripts/check_collocation_thermal_station.py --output /tmp/collocation_control_check
python scripts/run_collocation_thermal.py configs/surface_collocation_thermal_control.json --output /tmp/control_full.json
python scripts/run_collocation_thermal.py configs/surface_collocation_thermal_control.json --output /tmp/control_part.json --stop-after 1
python scripts/run_collocation_thermal.py configs/surface_collocation_thermal_control.json --checkpoint /tmp/control_part.json --output /tmp/control_resumed.json
```

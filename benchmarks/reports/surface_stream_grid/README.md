# Сетка квадратуры по двум выбранным PVTO-таблицам

`PipePressureGrid` исключает из квадратуры узлы таблиц, которые не участвуют
в свойствах данного потока. Сохраняются общая PVT-ось, обе выбранные
Rs-таблицы и дифференцируемая движущаяся точка насыщения. Точность Gauss,
контроль механического баланса, PVT-границы и скалярный повтор не ослаблены.
[Алгоритм и ограничения](../../../docs/BATCHED_BLACKOIL_HYDRAULICS.md).

## Полный FIM, расширенная PVTO

`wells64_pvt65_input.json`: 128 ячеек, 64 добывающие скважины с собственными
отводами к коллектору, одни сутки, один принятый шаг. Все скважины работают
по давлению сети. PVT — синтетический проверочный флюид с 65 Rs-таблицами,
каждая имеет собственный дополнительный узел давления. Функции Bo/mu_o
в них линейны и непрерывны в точке насыщения; это не экспериментальный
датасет. Сохранение настоящего излома свойств проверяется отдельным тестом.

Три последовательные пары на окончательной версии, float64, один Torch
CPU-поток, CUDA отключена. Меняется только политика узлов и связанное с
ней применение компактной сетки к одиночному коллектору; ядро свойств,
пласт, оборудование, уставки и временной интервал одинаковы.

- Глобальные узлы: **2,631 / 2,490 / 2,710 с CPU**.
- Узлы выбранной пары: **1,060 / 1,122 / 1,061 с CPU**.
- Медианы: **2,631 → 1,061 с**, ускорение **2,48×**.
- Фиксированных узлов на поток: **68 → 5**.
- Максимальная разность конечного давления: **4,66e-10 Па**;
  Sw: **5,56e-17**, Sg: **1,60e-16**, Rs: **1,43e-14**.
- Максимальная разность накопленного компонентного отбора: **4,66e-10 кг**.

На принятом шаге новый путь рассчитал пакетно 64 отвода и один коллектор,
без скалярных повторов. Контрольный путь оставил коллектор скалярным.
Счётчики принятого шага не являются профилем всех итераций Newton.
Один только переход от 68 к 5 фиксированным узлам уменьшает ёмкость
сетки сегментов с 70 до 7 на заданном порядке Gauss; это геометрия сетки,
**не измерение пиковой памяти всего процесса/autograd/GPU**.

## Обычная PVTO: контроль отсутствия систематического ухудшения

2048 скважин / 4096 ячеек / одни сутки, исходный PVT с одинаковыми осями.
Оба пути используют те же 3 фиксированных узла; компактный путь возвращает
прежнюю ось напрямую. Три пары:

- global: **8,276 / 8,021 / 7,876 с**, медиана **8,021 с CPU**;
- stream: **7,879 / 7,933 / 8,359 с**, медиана **7,933 с CPU**.

Конечные поля и компонентные отборы совпали побитно. Разброс перекрывается;
устойчивое ускорение для одинаковых осей **не заявляется**. Отдельный
приёмник остаётся на существующей скалярной трубе.

Нельзя переносить коэффициент 2,48× расширенной PVTO на Norne или любой
другой PVT-набор. Эта оптимизация выгодна при лишних узлах других таблиц.

## Протокол и версии

`final_*` — окончательные расчётные исходники. Каждый запуск хранит
protocol/summary, gzip-траекторию, SHA256 и независимый аудит фактических
компонентных расходов/приёмника/запасов пласта. `grid_policy.json` фиксирует
политику, неизменность wrapper и реальные вызовы выбора узлов.
`comparison_summary.json` сравнивает совпадающие физические конфигурации
с заранее заданными бюджетами.

Режим `global` подставляется в память отдельного процесса benchmark-wrapper;
файлы исходников не заменяются. В нём остаётся объединение всех PVT-узлов
и прежний скалярный коллектор. `stream` использует рабочую реализацию.
Число логических элементов фиксированной сетки в метаданных не является
измерением реального выделенного хранилища: глобальная ось может быть view.

Каталоги без `final_` — предварительная версия до включения компактной
сетки у одиночного коллектора. Их исходные hashes сохранены; они не
выдаются за прогоны окончательной версии.

## Проверки и ограничения

**213 passed, 12 skipped**, точный лог — `regression.txt`.
Проверены выбранные узлы, неодинаковые оси, обязательный излом Bo,
давления и неявные производные против глобальной сетки/скалярной трубы,
появление газа, сериализация и независимость кэша нового снимка свойств,
полный FIM/Шур, rollback и независимые учётные аудиторы.

Кэш принадлежит неизменяемому валидированному снимку PVT; новая PVT
задаётся новым `BlackOilMixture`. Узлы собираются на host один раз и
загружаются на устройство одним массивом. Выбор пары по компонентному
составу выполняется на устройстве без чтения индекса на CPU.

Пока сохраняются вырожденные нулевые интервалы после clipping и упаковка
осей/свойств всех Rs-таблиц. Длинные выбранные оси могут требовать большого
числа точек; бюджет пакета не является строгой границей всей памяти.
Скалярный повтор при сложной квадратуре использует существующую глобальную
сетку с рекурсивным делением и прежними допусками.

Сохраняется изотермическая homogeneous Rs-only модель сборного дерева,
без разделения потока, реверса/нулевого расхода и нисходящих труб.
Экспериментальная калибровка и GPU/Norne-ускорение здесь не подтверждены.
Драйвер NVIDIA окружения недоступен. `blackoil_fim.py` и `torch_linear.py`
не изменены; матрица пласта остаётся разреженной.

## Воспроизведение

Последовательно, без конкурирующих CPU-тестов; выходные каталоги должны
отсутствовать:

```bash
export CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=src:scripts
python scripts/run_pipe_grid_forecast.py --grid global --config benchmarks/reports/surface_stream_grid/wells64_pvt65_input.json --output /tmp/grid_global64
python scripts/run_pipe_grid_forecast.py --grid stream --config benchmarks/reports/surface_stream_grid/wells64_pvt65_input.json --output /tmp/grid_stream64
python scripts/check_fim_well_forecast.py /tmp/grid_stream64/trajectory.json.gz
pytest -q tests/test_blackoil_pipe_grid.py tests/test_blackoil_pipe_batch.py
```

Для обычного контроля использовать конфигурацию
`benchmarks/reports/surface_pipe_batch/wells2048_torch_batch_input.json`.
Повторные аудиты, сравнения и hashes — `validation.json`.

# Стоимость гидравлики и размещение небольшой сети

Область: синтетический изотермический black-oil пласт, 16 добывающих
скважин, homogeneous equilibrium сборное дерево из 17 труб,
квазистационарная подготовка и экспорт. Это не Norne и не вся подробная
PR-динамика. CNV/MB, временные допуски, шаги и поиск ограничений не ослаблялись.

## Что изменено

На CPU пакет с Re < 2000 во всех точках использует ту же ламинарную
формулу 64/Re без вычисления неактивной турбулентной ветви. Равенство
Re=2000 остаётся в прежнем пути ради его второй производной перехода.
В полностью насыщенном CPU-пакете опущены две неиспользуемые PVTO-таблицы.
Смешанные режимы сохраняют исходный алгоритм. Дополнительных CUDA scalar
read для этих проверок нет: GPU-пути сохранены.

Для небольшой сети переиспользован существующий `network_backend=cpu_reference`:
пласт, свойства ячеек и линейная система остаются на CUDA, давление/состав
сборной сети считаются на CPU. Массовые расходы скважин уже находились на
host-границе исходного алгоритма; повторного копирования полей пласта нет.
Исчезают мелкие CUDA-вычисления и пересылки внутри трубной гидравлики.
Полная плотная матрица пласта не появляется. Это выбор размещения того же
решателя, а не новая физическая модель или запрет GPU-гидравлики.

## Завершённые измерения

**CPU, три чередующиеся пары:** 1024 ячейки, 16 скважин, 0,003 суток.
Медиана 19,148645 → 17,037342 с: на 11,03% меньше времени.
165 FIM-проб в каждом опыте, 16 принятых стадий. Все сохранённые принятые
состояния/отчёты и конечные поля совпали точно. `pairs.json`, `pair*`.
Профиль до правки — `profile_reference.txt`; его время с накладными
расходами профилирования не использовано как исходное время ускорения.

**RTX 3090 Ti, три чередующиеся пары размещения:** 1024 ячейки,
16 скважин, один стартовый интервал 0,00005 суток = 4,32 с модельного времени.
Пласт и СЛАУ в обоих случаях на GPU. Медиана полностью GPU-сборной сети
28,847815 с; гибридной 13,232263 с: наблюдаемый коэффициент 2,18.
По 20 FIM-проб с учётом отброшенной полной стадии оценки ошибки,
3 связанных решения и 2 принятые половинные стадии, отказов нет.
`release_placement_pairs.json`, `release_placement*`.

**65 536 ячеек, та же RTX 3090 Ti:** одна пара на таком же стартовом
интервале, 29,540242 → 16,440517 с, наблюдаемое отношение 1,80.
По 20 FIM-проб, 2 принятые стадии. Это проверка масштаба и точности;
одна пара не задаёт статистически устойчивого ускорения большой модели.
Пик аллокатора Torch: 505 826 304 → 505 813 504 байт выделено,
761 266 176 → 759 169 024 зарезервировано. Контекст CUDA и чужие
процессы не учитываются. `large_placement_pairs.json`, `large_placement*`.

Во всех GPU-парах фиксированы бюджеты: давление/BHP 0,1 Па, Sw/Sg 1e-8,
Rs 1e-5, относительные дебиты/накопления 1e-7. Фактические различия
конечных полей и проверенных скважинных показателей равны нулю.
Дополнительно точно совпали времена, итерации, компонентные отборы,
скважинные отчёты и отчёты площадки на всех сохранённых принятых стадиях;
`*_accepted_states.json`. Это не история полей каждой ячейки между датами.

Все прогоны завершены, с source guard, checksum и материальным аудитом.
CPU — один поток. GPU — явный UUID RTX 3090 Ti, лимит аллокатора 8%.
Хост/карта общие и не были изолированы; сторонние процессы не останавливались.
Время относится к интегрированию после построения модели, включая ленивые
кэши/CUDA-графы внутри него. Длину месяца/9 лет из этих окон не оцениваем.
Полного месячного замера после этой правки нет. В одном коротком окне
три связанных решения дают 20 полных FIM — эта цена поиска остаётся
следующим существенным кандидатом на оптимизацию.

## Проверки и отвергнутые варианты

54 CPU-теста пройдены, 4 CUDA-теста пропущены в CPU-запуске:
ламинарная формула и две производные, границы 2000/4000, смешанные пакеты,
насыщенная/недонасыщенная нефть, физические трубы/сеть, компонентные и
энергетические балансы, FIM, откат и restart. Лог `release_tests.log`.
GPU-приёмка дополнительно выполнена полными связанными парами выше.

Вариант implicit AD Кольбрука сохранил точность, но не дал выигрыша
в связанном опыте: 29,663011 → 30,244084 с, около 1,96% медленнее на общем
хосте. Он удалён из рабочего кода. `rejected_gpu_ad.json` содержит метрики,
`rejected_gpu_sources.tar.gz` — точный экспериментальный код, а `gpu_short*`
— завершённые прогоны. Этот вариант не входит в `executed_sources.tar.gz`.
Первый более длинный GPU-пилот был остановлен ради ограниченных окон;
он не используется как завершённое сравнение и не подменяет измерения.

## Конфигурация и повторение

Рабочая альтернатива для малой сети и GPU-пласта:
`configs/fim_blackoil_facility_depletion_gpu_hybrid.json`.
От `depletion_fast` отличается только `physical_surface_network.network_backend`.
Автоматического порога по числу скважин нет: большие сети требуют своей
проверки CPU/GPU; старый конфиг и прежние defaults сохранены.

```sh
CUDA_VISIBLE_DEVICES=GPU-2f9ce359-f3f4-accc-bf9c-31bc88bb1cb7 \
CUBLAS_WORKSPACE_CONFIG=:4096:8 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=src:scripts \
python scripts/run_fim_facility_forecast.py \
  --config configs/fim_blackoil_facility_depletion_gpu_hybrid.json \
  --days .00005 --report-days .00005 --device cuda --cuda-memory-fraction .08 \
  --output /tmp/facility-hybrid-check
```

Из корня проекта можно распаковать `reference_sources.tar.gz` и
`executed_sources.tar.gz` в разные временные каталоги и запустить их
`scripts/run_fim_facility_forecast.py` с соответствующим PYTHONPATH.
Для CPU используйте один и тот же `reference_config.json`, 0,003 суток,
`--device cpu`; для GPU-размещения — `reference_config.json` и
`hybrid_config.json`, 0,00005 суток. Для крупной пары — `large_*_config.json`.
PVT-файл приложен. Архивные драйверы содержат оригинальные пути измерения;
команды выше и переносимые конфиги предназначены для нового запуска.
Контрольные суммы всех артефактов — `artifact_sha256.json`.

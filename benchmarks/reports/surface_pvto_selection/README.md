# PVTO: выбор двух таблиц вместо интерполяции всех таблиц

Для каждого потока нужны две соседние Rs-таблицы. Новый `PackedPVTO`
выбирает их до интерполяции по давлению; неодинаковые оси упаковываются
один раз для пакета труб. Убран временный массив точка×все_Rs_таблицы.
Линейная арифметика, правило правого узла и физические уравнения сохранены.
[Метод и границы](../../../docs/BATCHED_BLACKOIL_HYDRAULICS.md).

## Полный FIM, один CPU-поток

Все сравнения используют одинаковые конфигурации, пакетную гидравлику и
новый пакетный входной допуск. Меняется только способ PVTO-интерполяции:
benchmark-only `AllTablesPVTO` воспроизводит прежний массив всех таблиц,
один раз на колонку для двух соседних gather; он не вычисляет его дважды.
Режимы выбираются в отдельном процессе, исходники не перезаписываются.
`lookup_policy.json` хранит фактически исполненный режим, число вызовов
и SHA wrapper/эталона. Обычный driver отдельно проверяет массы и исходники.

На конфигурациях с небольшим стандартным набором PVTO:

- **512 скважин / 1024 ячейки / одни сутки:** три пары, медиана
  **2,505 → 2,333 с CPU**, сокращение времени **6,86%**.
- **2048 скважин / 4096 ячеек / одни сутки:** одна пара,
  **8,476 → 7,771 с**, сокращение **8,32%**.

После исправления только порядка импортов wrapper повторена пара на каждом
размере: **2,556 → 2,381 с** и **8,511 → 7,710 с CPU**. Это окончательные
контрольные замеры; расчётные модули в обеих сериях одни и те же.
Точная копия wrapper до lint сохранена в `run_pvto_selection_before_lint.txt`;
исходные SHA первых измерений не переписаны.

Во всех парах конечные P/Sw/Sg/Rs и компонентные накопленные отборы совпали
побитно. В каждом прогоне принят один шаг; на принятом шаге 512/2048
отводов посчитаны пакетно, скалярных повторов нет, один общий коллектор
остаётся скалярным. Отчёт принятого шага не является профилем всех Newton
итераций. Результаты — `comparison_summary.json` и gzip-траектории.

Это отдельный шаг после ускорения входных проверок:
[предыдущий допуск: 13–14% экономии CPU-времени](../surface_batch_admission/README.md).
Проценты двух разных серий не выдаются за единый контролируемый замер.

## Синтетическое ядро на 64 неодинаковых PVTO-осях

`ragged64_cpu` — отдельная интерполяция и первые производные, **не время
труб/пласта**. 64 потока × 256 точек, 64 синтетические линейные таблицы,
Bo/mu, разные длины осей. Рецепт и источники записаны в protocol.
Пять пар после прогрева, CPU float64, один поток:

- весь набор таблиц: медиана **57,184 мс**;
- выбор двух: **1,498 мс**;
- ускорение этого ядра **38,16×**.

Численные значения и производные прошли сравнение. Прежний реально
выделенный массив всех таблиц занимает **8 MiB**; выходной тензор одного
выбранного запроса — **128 KiB**, упакованные свойства — **11 KiB**.
Это размеры конкретных тензоров, **не общая пиковая память процесса,
autograd или GPU**. В прежнем пути одновременно существуют и другие
массивы; коэффициент экономии всей памяти не заявляется.

Физическая сетка квадратуры пока строится по объединению всех PVT-узлов:
эта оптимизация не устраняет всю зависимость полной задачи от размера PVT.
Синтетические таблицы не являются калибровкой реального флюида.

## Проверки

**207 passed, 11 skipped**, точный лог `regression.txt`.
Сравниваются неодинаковые оси и точные узлы, первая и вторая производные,
отсутствие stack по всем таблицам в рабочем запросе, фазовый переход,
конечные разности, полный FIM/Шур, restart, rollback и учётные аудиторы.
CUDA-тесты предусмотрены; драйвер окружения недоступен, GPU-скорость и
память не квалифицированы. Norne этим блоком не измерялся.

Матрица пласта остаётся разреженной. `blackoil_fim.py` и `torch_linear.py`
не изменены. Область физической ветви остаётся homogeneous Rs-only,
изотермическое дерево без разделения потока, реверса/статического нулевого
расхода и нисходящих труб. Это проверка эквивалентного представления,
не экспериментальная валидация корреляций.

## Воспроизведение

Запускать последовательно, без конкурирующих CPU-тестов. Выходные каталоги
должны отсутствовать:

```bash
export CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=src:scripts
python scripts/run_pvto_selection_forecast.py --lookup all_tables --config benchmarks/reports/surface_pipe_batch/wells2048_torch_batch_input.json --output /tmp/pvto_all2048
python scripts/run_pvto_selection_forecast.py --lookup selected --config benchmarks/reports/surface_pipe_batch/wells2048_torch_batch_input.json --output /tmp/pvto_selected2048
python scripts/benchmark_pvto_selection.py --output /tmp/pvto_ragged64
pytest -q tests/test_blackoil_pvto_batch.py tests/test_blackoil_pipe_batch.py tests/test_blackoil_batch_admission.py
```

Повторные проверки всех траекторий, SHA и точности — в `validation.json`.

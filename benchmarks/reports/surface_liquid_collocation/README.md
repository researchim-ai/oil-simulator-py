# Проверка Torch Gauss4 для жидкостной сети

**Исторический протокол первоначального контроллера ошибки.** Позднее
проверка пассивного теплообмена выявила, что его оценка могла обнуляться
на аффинных задачах. Метод Гаусса и измеренная точность данной траектории
подтверждены, но время 8,93× не квалифицирует исправленный контроллер.
Исходные данные сохранены; новый контроллер использует независимый Kutta3.
[Исправленная серия](../surface_liquid_thermal_collocation/README.md).

15 ноября 2026. Это benchmark однофазной слабосжимаемой жидкостной
сети с двумя насосами, инерционной трубой, экспортной арматурой и
двумя валами. Он не является расчётом полного многофазного PR-стенда
или сравнением с Eclipse/OLGA. Свойства и оборудование синтетические.

## Что сравнивается

Production adaptive-midpoint и новый опциональный `LiquidCollocation`
на PyTorch CPU float64, по одному потоку Torch/OMP/MKL. У обоих:

- одна физическая модель и общие законы труб/насосов/арматуры;
- непрерывный интервал 1 с и постоянные моменты 5/7 Н·м;
- максимальный шаг 0,02 с;
- rtol=1e-8, абсолютные допуски 0,1 Па, 1e-11 м³/с, 1e-6 рад/с;
- проверки массы, механической энергии и оборудования;
- время включает интегрирование и материализацию принятого журнала.

Начальные давления 550/500 кПа, расход трубы 0,002 м³/с,
скорости валов 100/110 рад/с; давления источника/экспорта 400/480 кПа.
Ограничители момента/скорости в сравнительном режиме неактивны.

Перед измерениями оба метода прогреваются. Три пары запускаются
последовательно с обратным порядком во второй паре. Ни один GPU
не используется. Хеши производственных исходников и скрипта проверяются
до/после всей серии и сохранены в `summary.json`.

## Результат окончательной серии

- Пара 1: midpoint 15,342 с, Gauss4 1,712 с.
- Пара 2, обратный порядок: Gauss4 1,691 с, midpoint 15,113 с.
- Пара 3: midpoint 15,070 с, Gauss4 1,651 с.

Медиана **15,113 → 1,691 с** за секунду процесса: **8,93 раза быстрее**
на этом CPU-примере. Принятых шагов **800 → 71**. Gauss выполнил
73 совместных нелинейных решения (две попытки отвергнуты),
444 явных вычисления невязки и 81 построение Якобиана.

Максимальная проверенная ошибка давления: **0,201 → 0,00517 Па**;
расхода: **9,99e-9 → 2,56e-10 м³/с**. Максимальная энергетическая
невязка Gauss — **8,60e-11 Дж**, массовая — **1,02e-15 кг**.
Оба метода уложились во внешний пример бюджета ошибок.
Физические траектории повторов каждого метода совпали побитово;
побитовое совпадение разных методов не ожидается.

Финальный CPU-набор: **191 тест прошёл**. Ruff, проверка форматирования,
компиляция Python и `git diff --check` прошли. Данные проверки —
`validation.json`. Предварительные измерения до объединения аудитов
оборудования не включены в окончательную серию.

## Проверка точности

Независимый эталон — аналитически редуцированная пятисоставная ODE
`check_liquid_transient.coupled_rhs`, DOP853 с rtol=1e-12 и покомпонентными
абсолютными допусками. Производственный Gauss не использует этот RHS:
его производные и алгебраические ограничения вычисляет общий Torch-код.

Внешний пример бюджета ошибки: 1 Па для давления, 1e-8 м³/с для
расхода трубы, 1e-4 рад/с для скоростей. Это требования данного стенда,
не универсальная промышленная норма. Каждый метод должен укладываться
в бюджет на **всех принятых концах шагов**. Ошибка сплошной временной
интерполяции не сертифицирована.

Новый метод не обязан совпадать с midpoint побитово: отличаются порядок,
временная сетка и оценка ошибки. Сравнивается достигнутая физическая
точность относительно независимого решения. Балансы пересчитаны отдельно
из сохранённых стадий в тесте, без использования рабочего `_powers`.

## Численная организация

Gauss решает одну совместную систему двух стадий на попытку, без тройного
пересчёта интервала для временной ошибки. Встроенный метод третьего
порядка использует дополнительные вычисления производных, а не
дополнительные решения временных задач. Алгебраические расходы
восстанавливаются на конце основного и встроенного решения.

Проверены четвёртый порядок на аналитической акустике и согласованность
разреженного/плотного решения на распределённой сети с 258 неизвестными
двух стадий. Проверены повтор из JSON-checkpoint, восстановление после
отказа и неизменность входного состояния при незавершённом интервале.

## Границы результата

Новый путь подключается явно через `LiquidCollocation`. Midpoint остаётся
основным путём существующих станций и расписаний. Полноценная локализация
остановок, движущиеся исполнительные механизмы, PID, согласованный тепловой
адаптер и перенос интегратора на PR-профили ещё не реализованы в этом пути.
Сам по себе данный выигрыш не сокращает время полного PR-стенда в том же
отношении. CUDA-производительность не измерялась.

Gauss сохраняет согласованный баланс квадратичной механической энергии,
но не L-устойчив. Его нельзя объявлять универсально лучшим методом для
жёсткой многофазной динамики. Для полной PR-сети по-прежнему необходимо
сравнение на непрерывных уравнениях всей связанной системы с её событиями.

## Воспроизведение

```bash
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 python scripts/benchmark_liquid_collocation.py --output /tmp/liquid_gauss_recheck --pairs 3
```

`summary.json` содержит все времена, ошибки и счётчики. `pair*_*.json.gz`
содержат исходные отчёты и физические траектории, а не только график
конечных значений. [Описание API](../../../docs/LIQUID_COLLOCATION.md).

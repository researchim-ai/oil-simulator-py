# Контракт сходимости и резервное линейное решение PR-сети

Продолжение аудита наземной сети от 13 ноября 2026 года. Область изменения:
современный `src/surface/torch_nonlinear.py`, используемый равновесным
PR-транспортом. Пластовый `blackoil_fim.py` и физические уравнения не менялись.

## Исправление сходимости

Раньше итоговый `success` возвращался при конечной невязке до `1e-8`, независимо
от переданного `tolerance`. Поэтому остановившийся поиск шага или исчерпанный
бюджет Ньютона могли считаться успехом при недостигнутой запрошенной точности.
Дополнительная проверка PR-транспорта `max(abs(r)) < 1e-9` ограничивала часть
таких случаев, но также не обеспечивала более строгий запрошенный бюджет.

Теперь конечная невязка проверяется по каждой строке. Базовый бюджет —
`tolerance` либо явно разрешённый вызывающим кодом `stagnation_tolerance`.
Построчная оценка округления может расширить только свою строку. Недопустимые
оценки не разрешают успех. Нулевой, отрицательный, NaN или бесконечный целевой
допуск отклоняется до вычисления остатка.

Конечная проверка выполняется на том же устройстве. Нового чтения CUDA-статуса
на CPU нет. Сам факт исчерпания итераций не запрещает действительно сошедшийся
последний результат: решает соответствие конечной невязки явному бюджету.

Регрессионные проверки включают недостижимый корень на границе с невязкой
`2e-10`, исчерпание одной итерации при недостигнутой точности, разрешённое
округление только в правильной строке и недопустимые целевые допуски.

## Устранение лишней CPU-работы

Раньше для каждого нового плотного Якобиана вычислялись LU-факторы как `J`,
так и регуляризованной матрицы `J^T J + 1e-12 I`, затем решались обе системы.
Резервный результат отбрасывался даже при полностью успешном обычном LU.

На CPU резервная матрица теперь строится и факторизуется только при ошибке
обычного LU либо нечисловой прямой поправке. Если она потребовалась, её
факторы используются до следующего обновления Якобиана. Проверки включают
невырожденную систему с одной факторизацией на один Якобиан и вырожденную
систему с сохранённым регуляризованным решением.

На CUDA сохранён выбор результата на устройстве с резервной системой:
это изменение не добавляет синхронизацию ради проверки LU на CPU.

Отдельный синтетический CPU-тест на 128 неизвестных: шесть пар замеров
с обратным порядком исполнения, по 15 решений в каждом замере. Медиана
пакета уменьшилась с 0,03670 до 0,02876 с, то есть примерно на 21,6%.
Количество факторизаций на решение уменьшилось с шести до трёх;
конечные решения совпали побитово. Этот результат относится только к
данному плотному ядру и не переносится на разреженную сеть.

## Отвергнутые изменения начального приближения

Проверен перенос фазовых профилей логарифма давления и координат состава
между квадратурами, включая раздельные односторонние значения интерфейсов.
Он менял только старт Ньютона, сохраняя физические проверки. Однако это
не дало устойчивого выигрыша на тяжёлом трёхфазном старте.

- Контрольная версия: 73,07 с; 718 вычислений невязки, 45 Якобианов.
- Полный перенос, включая начало физического шага: 109,02 с; 1574 вычисления
  невязки, 74 Якобиана. Первая проба дошла до 40 итераций с невязкой около
  `1,29e-11`. Это также выявило проблему итогового флага сходимости.
- Перенос только внутри уточнения квадратуры: 77,07 с; 786 вычислений
  невязки, 53 Якобиана.

Это одиночные инструментированные CPU-измерения, а не статистические оценки.
Оба экспериментальных варианта удалены из производственного кода. Не добавлены
новые параметры конфигурации или скрытые кэши профилей. Их измерения сохранены
для объяснения решения; они не означают квалификацию новой физики.

## Проверки

Расширенный CPU-набор: 111 прошли, один CUDA-тест пропущен. Он включает
Ньютон, гравитационный транспорт, управление, открытые границы, теплообмен,
равновесные трубы и насосные соединения. После добавления проверки входного
допуска отдельный окончательный набор Ньютона: 24 прошли, один CUDA-тест
пропущен. Эти числа перекрываются, складывать их нельзя.

Окончательный старт исходного трёхфазного стенда: 69,08 с за 1 мкс,
шесть глобальных решений, 718 вычислений невязки, 45 Якобианов.
Конечное состояние побитово совпало с контрольной версией; независимый
аудитор подтвердил оба физических полушага, максимальная локальная
энергетическая невязка — 6,04e-8 Дж. Исходники во время прогона не менялись.
Стенд использует разреженный путь (`dense_limit=128` при 292/400 неизвестных),
поэтому устранение резервного плотного LU его не ускоряет. Разницу
73,07 → 69,08 с по одиночным запускам выигрышем алгоритма не объявляем.

Продолжение из этого checkpoint на 1,5 мкс завершилось за 69,21 с без
отказов, с нормированной временной ошибкой 0,05709. Конечное время —
2,5 мкс, предлагаемый следующий шаг — 2,25 мкс. Независимый аудит
продолжения прошёл: максимальная локальная энергетическая невязка
1,16e-7 Дж. Это проверяет рост шага и повторный запуск со строгим
контрактом, но также не квалифицирует полное расписание.

Сырые исторические сравнения находятся рядом в сжатых JSON. Полный перенос
сохранился только как инструментирование; его полный физический отчёт не
прилагается. Финальный контрольный прогон и независимый аудит зафиксированы
в `validation.json`. `instrument_final.py` воспроизводит диагностический
старт из корня репозитория с тем же CPU-окружением, что и адаптер исходного
аудита; он сохраняет результаты в `/tmp` и считает факторизации LU.
Подтверждение микросекундного старта
не является подтверждением полного секундного расписания или всей сети.

Плотный микробенчмарк воспроизводится из корня репозитория:

```bash
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=src python benchmarks/reports/surface_nonlinear_contract/benchmark_dense.py
```

Он использует сохранённый `baseline_torch_nonlinear.py.gz`, поэтому
последующий коммит не заменит контрольную реализацию текущим `HEAD`.

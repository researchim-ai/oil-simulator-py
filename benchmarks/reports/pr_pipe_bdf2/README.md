# Консервативный Torch BDF2 для PR-труб

Реализованы непрерывный пространственный оператор и отдельный адаптивный
BDF2-интегратор `surface.pr_momentum_bdf.PRMomentumBDF`. Это **opt-in путь
горизонтальной однофазной трубы**, а не перевод всей связанной многофазной
установки на новый метод. Default backward Euler сохранён.

Сводные результаты: [summary.json](summary.json). Все шесть `release_*` серий
проверены на совпадение текущих хешей исходников, включая независимые аудиторы.
Уравнения, PR-константы и поток Rusanov совпадают с native Modelica-стендом.
Горизонт каждого сравнения — **0,01 с физического времени**, не 1 с и не год.
Время — CPU, медиана трёх прогретых запусков после отдельно сохранённого
холодного. Компиляция native-эталона и независимые аудиты исключены из таймера.

## Измеренный результат

На 8 ячейках:

* BE, относительный допуск 1e-4: **1,45774 с**, 42 нелинейных решения.
* BDF2 при исходных допусках: **0,56346 с**, 15 решений. Этот самый быстрый
  режим имеет большую ошибку скорости и не объявляется равным по точности.
* BDF2 при допусках, ужесточённых в 10 раз: **0,80047 с**, 21 решение,
  наблюдаемое ускорение относительно BE **1,82×**.
* При ужесточении в 100 раз: **1,03588 с**, 33 решения.

Для сравнения 1,82× максимальные отличия от tight IDA на сохранённых точках
траектории уменьшаются: давление **47,60 → 5,12 Па**, температура
**0,000581 → 0,0000863 K**, скорость **0,001608 → 0,000706 м/с**.

На 16 ячейках BE требует **2,04517 с**, BDF2 с допусками, ужесточёнными в
100 раз, — **1,47347 с**, ускорение **1,39×**. Нелинейных решений 45 → 33.
Максимальные отличия на сохранённых точках: давление **77,45 → 3,84 Па**,
температура **0,001114 → 0,0000590 K**, скорость **0,002717 → 0,000348 м/с**.

Номинальные допуски разных методов не объявляются эквивалентными. В драйвере
температурный и скоростной абсолютные допуски масштабируются вместе с заданным
относительным. Параметры каждого запуска сохранены. В самом BDF-адаптере нет
подгонки под число ячеек или этот стенд.

Native-эталон — IDA 1e-10. Для сравнения сохранённых временных точек используется
четырёхточечная кубическая интерполяция его dense-output CSV; это не точный
супремум ошибки между точками. Конечные ошибки также сохранены отдельно.
В частности, у BE на 16 ячейках малая ошибка конечной скорости частично
обусловлена фазой акустической волны: сравнивать только последнюю точку было
бы недостаточно. Native-код всё ещё значительно быстрее: этот блок не
устраняет оставшийся разрыв стоимости вычислительного ядра.

## Что изменилось в алгоритме

`PRMomentumPipe.continuous_problem()` возвращает консервативные запасы `U(y)`,
пространственные потоки, источники и остаток `F(y, Udot)`, независимо от шага.
Прежний BE использует тот же оператор и прежний порядок вычисления своего
целевого запаса. BDF не оборачивает прежний `advance()` другим интегратором.

При отношении шагов `r = h/h_prev` выполняется переменношаговый BDF2:
`a0=(1+2r)/(1+r)`, `a1=-(1+r)`, `a2=r²/(1+r)`.
Ограничение роста — 1,5; оно не является утверждением об устойчивости любых
нелинейных EOS-состояний. Допустимость и сходимость проверяются отдельно.

Начало или смена граничного условия запускает BE с полным шагом и двумя
полушагами. После получения трёх точек истории каждый BDF trial требует
**одного** нелинейного решения. Оценка временной ошибки использует дефект
квадратичного предиктора истории, консервативные запасы, давление, температуру
и скорость. Дополнительного решения для оценки ошибки нет. Отказ уменьшает
шаг; история публикуется только после принятия.

Сохраняются фазовая допустимость, положительность активных запасов,
акустические ограничения, EOS-проверки и строгий допуск Newton. Это не
отключение flash и не ослабление критериев. Исполнение использует Torch
на CPU/CUDA; внешние решатели служат только независимому сравнению.

## Балансы, история и контрольные точки

Для BDF нельзя считать перенос как `h * endpoint_flux`, как в BE. Для
`beta=r²/(1+2r)` и `gamma=(1+r)/(1+2r)` приращение граничного переноса
согласовано с методом: `Q_new=beta*Q_previous+gamma*h*flux_new`. Тот же принцип
используется для импульса трения и граничной энтропии. Потоки компонентов и
полной энергии не исправляются искусственно после решения.

В отчёте `left_exchange` / `right_exchange` — **интегрированные численные
переносы за шаг с учётом истории**, а не мгновенные расходы. Знаки сохраняются.
В checkpoint входят три состояния, времена, переносы, порядок и fingerprint
границ/модели. При продолжении проверяются согласованность запасов с EOS,
балансы соседних точек, последнее BDF-уравнение и граничная квадратура.
Смена границ сбрасывает историю и повторяет контролируемый старт.

Отдельный NumPy-аудитор восстанавливает PR-свойства, Rusanov-потоки, Darcy,
уравнение BDF и исторические интегралы. Runtime `decode`, `inspect` и `step`
для этого не используются. Каждая измеренная траектория принята аудитором.

Энтропийный баланс BDF записан как **диагностика**. Не утверждается локальное
неравенство энтропии, проверяемое для BE: у многошагового метода другой
временной оператор. Это одна из причин сохранения opt-in статуса.

## Проверки и CLI

Прошли 53 CPU-регрессии труб, тепловых и сосудных связей, а также 30 целевых
CPU/CUDA-проверок. Проверены второй порядок на аналитическом вязком затухании,
неравномерные шаги, отклонение trial без изменения checkpoint, сериализация,
продолжение истории, смена давления, отрицательный граничный перенос и отказ
на повреждённой истории. После усиления проверки знака повторно прошли шесть
CPU-тестов BDF. В отдельном `viscous_refinement.json` наблюдаемые порядки
уточнения составляют 2,46 и 2,27 относительно точного экспоненциального решения.

```bash
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=src:scripts \
python scripts/run_pr_momentum_pipe.py configs/surface_pr_momentum_pipe.json \
  --integrator bdf2 --device cpu --output /tmp/pr-bdf.json
PYTHONPATH=src:scripts python scripts/check_pr_momentum_bdf.py /tmp/pr-bdf.json
```

Для CUDA используйте `--device cuda` и выбранную через `CUDA_VISIBLE_DEVICES`
карту. Измеренное ускорение выше относится к CPU; оно не выдаётся за замер GPU.
Для продолжения в `initial` задаётся `{"state": <BDF checkpoint>}`. Старые
BE-состояния не являются BDF-checkpoint: историю нельзя восстановить из одной
последней точки без контролируемого запуска.

В `cli_schedule.json` сохранён полный запуск двух интервалов; `cli_restart.json`
продолжает его из JSON-checkpoint. Независимые аудиты приняты, первая новая
точка restart использует порядок 2 без повторного старта. Обычный BE CLI и его
аудитор также проверены: `cli_be_schedule*.json`.

Воспроизведение парного сравнения:

```bash
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=src:scripts \
python scripts/benchmark_pr_pipe_bdf.py --omc-runtime <extracted-omc-prefix> \
  --integrator bdf2 --relative-tolerance 1e-5 --output-dir /tmp/bdf-pair
```

## Границы и следующий перенос

Сохраняется существующий предел отдельного pipe-пути в 768 неизвестных;
плотная матрица для произвольно большой сети не создаётся. Адаптер отвергает
наследников с гравитационной реконструкцией или дополнительными запасами.
Он **не** подключён к `PREquilibriumTransportNetwork` / `PRSubcycledSurface`,
переходам числа фаз, сепараторам, стенкам и роторам. Новое ускорение полного
связанного стенда этим отчётом не заявляется.

Для переноса туда нужна общая история всех дифференциальных запасов и их
межблочных переносов. Например, температура стенки, исключённая по BE-формуле,
не станет BDF-температурой простой заменой `dt`. Аналогично нужно согласовать
компоненты/энергию колонн, фазовые события и оборудование. Этот перенос должен
использовать уже выделенный оператор и проверенные балансы, а не отключать
проверки или заменять подробную физику другой моделью.

Обоснование класса методов: [IDA, непрерывный остаток и BDF](https://sundials.readthedocs.io/en/latest/ida/Mathematics_link.html),
[исследование BDF2 для сжимаемого two-fluid течения](https://ir.cwi.nl/pub/25827).

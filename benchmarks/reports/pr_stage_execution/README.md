# Ускорение связанной PR-установки: стадии и переключения

В рабочий путь добавлены локальная история линейзации SDIRK2 и корректный
старт шага после известных смен команд. Исходный 16-узловой цикл
**пуск → изоляция → повторное открытие, 0–1 с**, завершён обеими версиями
и прошёл независимые аудиты. Модель, геометрия, команды и допуски одинаковы.

## Полный парный прогон

Последовательно, после регрессии, CPU eager, OMP/MKL по одному потоку,
без наших параллельных тестов. Инициализация и журнал/checkpoint включены;
сериализация итоговой траектории и независимый аудит исключены. Это **одна
полная пара**, а не статистика многих повторов или гарантированная скорость.

* Время: **808.382 → 652.673 с**,
  **1.2386×**, сокращение **19.26%**.
* Отклонённые попытки: **28 → 15**.
* Коллокационные нелинейные системы, включая отклонённую работу: **672 → 624**.
* Построения якобиана в этой части: **1549 → 1167**.
* Защищённые межстадийные применения: 281; обновления после недостаточной
  фактической контракции: 17. Это не счётчик всех legacy-решений.
* В обеих траекториях 149 принятых записей: 139 common SDIRK2 и 10 BE-записей
  (по пять резервных макроинтервалов). Метод каждой записи сохранён явно.

До первого принятого шага после закрытия связей: **31,977 → 13,509 с**;
после повторного открытия: **128,816 → 17,228 с**. Это задержки перехода,
не время целого интервала. Первая допустимая длительность после повторного
открытия остаётся микросекундной: примерно 5,88e-6 → 6,25e-6 с.
Ускорение получено сокращением бесполезной работы, не пропуском перехода.

## Реализация

В SDIRK2 обе диагонали таблицы Бутчера равны gamma: на одном подготовленном
операторе две стадии различаются известной правой частью. Используется
существующий DenseNewtonHistory с проверкой размеров, границ, близости точки
и коэффициента времени. Старая матрица должна уменьшить **фактическую новую
невязку**; иначе та же итерация повторяется со свежим якобианом.

История живёт только внутри одной подготовленной задачи. Она не переносится
через шаги, уточнение квадратуры, смену ветви клапана и повторные попытки.
Крупная разреженная ветвь и CUDA не импортируют плотную CPU-историю.

На известной смене команд в последовательных advance() начальная подсказка
ограничивается initial_step_s. Дальше работает прежний адаптивный контроллер.
На одинаковых командах накопленный шаг сохраняется; первый вызов из
произвольного checkpoint не считается известным событием. Контекст
обновляется только после успешного интервала; перемотка его не наследует.
Пустые команды, normal, числовые типы и знаковые нули нормализованы.

Reference отключает обе новые оптимизации, optimized включает их.
Reverse AD и повторное использование физических данных стадий включены
в обеих версиях. Экстраполяция начального приближения **выключена**.
Публичная конфигурация и идентификаторы физических checkpoint не менялись.

## Проверка точности и событий

Все принятые записи независимо проверены существующими NumPy/SciPy
аудиторами физических операторов, контроллеров, часов и глобальных N/E.
Максимальный компонентный дисбаланс новой траектории — 7,28e-11 моль;
энергетический — 1,52e-6 Дж, в прежних бюджетах аудитора. У исходной версии
энергетический дисбаланс 2,22e-7 Дж. Эти балансы не заменяют проверку времени.

Разница на концах режимов: 2,75e-8 / 0,154324 / 0,152570 исходного бюджета
(допустимо ≤1). Все пять патрубков переносят компоненты при пуске и повторном
открытии; при изоляции N/E-переносы равны точно нулю. Отражение импульса
закрытой границы сохранено. Данные есть в comparison.json.

Первичная линейная интерполяция разных временных сеток дала ложные пики
до 470 бюджетов. Исходные данные сохранены в linear-observer-diagnostic.json
как **отвергнутый способ сравнения**, не как ошибочная траектория решателя.
Линейная прямая не описывает быструю начальную релаксацию после скачка
команд и излом остановки идеального привода.

Проверены два дополнительных интегрирования **в точно совпадающие моменты**
первых послесобытийных точек: ошибки 3,92e-8 и 0,154324 бюджета; отдельные
аудиты приняты. На всех 261 принятых точках изолированного участка положения
трёх идеальных приводов совпали с независимым аналитическим законом.

Диагностика между разными сетками использует этот точный закон для ручных
целей, не интерполирует через начальный слой и закрывает обе исключённые
точки прямыми пересчётами. Остальные поля интерполируются только для
сравнения наблюдений: максимум **0.847307 бюджета**. Такие реконструкции
не являются принятыми термодинамическими состояниями или внешним эталоном.
Для точных инженерных выборок на иных временах нужны явные отчётные моменты,
а не произвольная прямая между сохранёнными кадрами.

Регрессия: **338 passed**, три предупреждения PyTorch; Ruff и
`git diff --check` прошли. Проверены испорченная касательная с возвратом к
свежей, отсутствие переноса между шагами, FD/AD, изоляция/пуск, sparse и
нативные производные, одинаковые команды, normal, числовые типы, откат и
неудачный интервал. Лог: release-regression.log.

## Локальный рабочий замер и отвергнутые варианты

release-steady/: три чередующихся пары после двух подготовительных запусков,
на старом рабочем интервале 0,016214944613224563 с из t=0,706238099587186 с.
**5,339364 → 4,886944 с**, 1,09258× (8,47% меньше времени), якобианы
14 → 11, межстадийные применения 0 → 3. Все восемь траекторий проверены;
отклонение состояний 1,08e-8 бюджета. Это изолированный эффект истории:
в одном интервале нет смены команд. Коэффициенты серий не перемножаются.

В stages/ проверена ограниченная экстраполяция стартовой точки с реальной
проверкой невязки. Все три пробы рабочего интервала отвергнуты, дополнительного
выигрыша нет. Поэтому _predict_sdirk_stage выключен по умолчанию.
`tangent/`, `qualified/`, `final-steady/` — промежуточные снимки; итоговая
серия текущего исходника — release-steady/.

Старая попытка cycle-reference/ прервалась SIGSEGV во время таймерного
снятия стека после 0,4 с, при выключенной оптимизации. Она исключена из
физической/временной квалификации. Таймер удалён; оба release-прогона без
него завершены. Лог, failure.json и исходники сохранены; первопричина
нативного сбоя не объявляется доказанной по одному дампу.

## Воспроизведение и предел результата

В release-cycle-* лежат точный запрос, исходники, три интервальных
checkpoint, полная траектория, прогресс и аудит. comparison.json содержит
парное сравнение, event-replay-validation.json — прямые событийные проверки.
validation.json и checksums.json связывают все артефакты с исходниками.

```bash
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 CUDA_VISIBLE_DEVICES='' PYTHONPATH=src:scripts \
/home/user/miniconda3/bin/python scripts/benchmark_pr_graph.py \
benchmarks/reports/pr_graph_execution/steady/request.json \
/tmp/pr-stage-repeat --experiment tangent --repeats 3
```

Полные прогоны: cycle_driver.py --reference NEW_REFERENCE_DIR и
cycle_driver.py NEW_OPTIMIZED_DIR с теми же переменными окружения.
event_replay_driver.py NEW_OUTPUT_DIR воспроизводит прямые проверки событий.

Подробный холодный секундный цикл всё ещё занимает около 10,9 мин CPU.
Это **не real-time**, не Norne/GPU, не промышленная экспериментальная
калибровка, не универсальные 19% и не ускорение 50×. Ускорен конкретный
полный связанный сценарий при прежних допусках. Дальнейшая работа нужна
над стоимостью остальных операторов и подготовок.

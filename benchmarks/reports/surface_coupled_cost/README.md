# Стоимость связанных решений: сохранение выбранной пробы и трение

Проверен изотермический black-oil пласт → добывающие скважины ↔ сборное
дерево → квазистационарная площадка. Опыт с временным уточнением охватывает
переходный интервал 0,02 суток, 1024 ячейки / 16 скважин. Отдельно проверен
месяц на 65 536 ячейках / 64 скважинах. Это не длинная временная
квалификация сильного истощения и не подробная тепловая PR-сеть.

## Исключение повторного решения выбранной пробы

`coupled_facility.control.commit_method="state_restore"` сохраняет
физическое состояние лучшей уже рассчитанной допустимой пробы текущего
шага. После сужения скобки принимается именно это состояние. Все пробы
решаются из того же начала интервала, с прежними уставками, уравнениями
и критериями. Сохраняются пластовые поля, фазовые флаги, BHP, скважинные
накопления, отчёты и метрики принятого Ньютона. Учёт площадки и энергии
выполняется после выбора. Никакого пересчёта добычи множителем нет.

По умолчанию остаётся `replay`, который повторно решает выбранную пробу.
Новый способ исключает один нелинейный расчёт на каждый ограниченный
связанный шаг. В полной временной оценке это также относится к
отбрасываемому грубому решению. Для множителя 1 повтор отсутствовал и
раньше; дополнительный снимок для него не создаётся.

Цена — один дополнительный снимок физического состояния и его обновление
при улучшении допустимой границы. Плотная пластовая матрица не копируется,
полная память устройства здесь не квалифицирована. Снимок не переносится
в другой интервал и не сохраняется в checkpoint; в отчёте остаются только
метод и индекс допустимой пробы `capacity_commit.solved_trace_index`.
Независимый аудит проверяет этот индекс, его множитель и допустимость,
скобку, фактические расходы, балансы и операторские события.

В паре `replay_current` / `state_restore` совпали все 130 принятых стадий:
время, длительность, расходы, BHP, итерации Ньютона, отборы, материальный
учёт и итоговые поля. Исходники Python пары одинаковы, оба прогона
завершены с source guard. Проб площадки стало **1414 вместо 1609**
(−12,12%), включая отброшенные грубые оценки. Остались 65 макроинтервалов
и 195 вызовов внешнего контура поиска ограничения; внутри них выполнялись
указанные полные FIM-пробы. Наблюдаемое время **309,07 вместо 336,74 с**.
Переключения ограничений, исключение после выбора, откат, перезапуск и
CUDA-состояния проверены отдельными тестами.

## Сокращение лишних итераций Коулбрука

Профиль короткого опыта показывает значительную стоимость гидравлики,
в том числе аффинного стартового предиктора. В `profile.json` времена
вложенные и не суммируются. Копирование транзакционного состояния не
является главным узким местом этого опыта.

В общей функции трения скалярных и пакетных black-oil труб число фиксированных
итераций Ньютона сокращено с 10 до 6. Сохранены уравнение Коулбрука,
начальное значение, ламинарная ветвь и переходное сглаживание. Проверены
float64 Re от 1e-10 до 1e100, относительная шероховатость 0…1, окрестности
Re=2000/4000, значения и первые/вторые логарифмические чувствительности
с допусками 1e-12/1e-16. Независимая проверка подстановкой в уравнение
и его неявных производных также проходит. CPU/CUDA проверены отдельно.
Дополнительного скалярного опроса с GPU не добавлено.

## Совместный результат

В `combined` две оптимизации вместе дали **270,73 с** против **336,74 с**
исходного повторного решения с 10 итерациями трения: наблюдаемое
сокращение **19,60%**. Все 130 принятых стадий, конечные поля и накопления
совпали точно. С более строгим временным эталоном сохранились разности:
давление 9,69 Па, Sw 1,88e-6, Sg 7,05e-6, Rs 1,46e-4,
накопленные отборы 0,0139%. Прежние бюджеты не менялись.

На месячной модели 65 536 ячеек / 64 скважин сохранились шесть принятых
шагов; конечные поля, отчётные BHP, дебиты и накопления совпали точно.
Проб стало 65 вместо 71. Наблюдаемое время `scale64k_combined` 109,10 с;
его нельзя напрямую выдавать за ускорение относительно прежних замеров
этой модели на другом фоне нагрузки.

Все времена получены одним потоком Torch на общем хосте; часть прогонов
перекрывалась, GPU были заняты сторонней работой. Это наблюдения данной
серии, не изолированный аппаратный коэффициент ускорения. На 3090 Ti
проверена корректность, а не чистая скорость. Для больших моделей выбор
`state_restore` требует учёта дополнительного снимка памяти.

## Воспроизведение текущей пары

Текущий код использует шесть итераций трения. Сравнить способы приёмки:

```bash
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=src:scripts python scripts/run_fim_facility_forecast.py --config benchmarks/reports/surface_time_accuracy/depletion_defect_control_fine.json --days .02 --report-days .01 --device cpu --output /tmp/facility_replay
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=src:scripts python scripts/run_fim_facility_forecast.py --config benchmarks/reports/surface_time_accuracy/depletion_fine_state_restore.json --days .02 --report-days .01 --device cpu --output /tmp/facility_restore
PYTHONPATH=src:scripts python scripts/compare_fim_facility_forecast.py /tmp/facility_replay/trajectory.json.gz /tmp/facility_restore/trajectory.json.gz --allow-numerical-policy --budgets benchmarks/reports/surface_time_accuracy/field_budgets.json --output /tmp/facility_commit_comparison.json
```

Для аудита исходных замеров сохранены gzip-траектории, протоколы,
контрольные суммы, балансы и прежняя 10-итерационная версия функции
в `executed_sources/blackoil_pipe.py`. Устанавливать её в рабочую копию
для обычного расчёта не требуется. Границы приёмки — в `qualification.json`.

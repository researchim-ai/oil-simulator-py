# Уплотнение квадратуры труб с сохранением граничных производных

Gauss-точки строятся для ненулевых интервалов. Нулевые интервалы больше
не требуют 16–256 одинаковых вычислений свойств: остаётся одна оценка
в совпавшей точке с символическим нулевым half-width в AD-графе.
[Алгоритм и область](../../../docs/BATCHED_BLACKOIL_HYDRAULICS.md).

## Полный FIM: одинаковая физика и разные планы квадратуры

Итоговые измерения — каталоги `final_*`, после проверки производных
смешанных строк с разным числом активных интервалов. Более ранние
каталоги и логи сохранены как предварительные; их версии не выдаются
за окончательную реализацию.

В обоих режимах работают текущие PVT/PVTO, потоковая сетка, пакетное
ядро труб, оператор скважин и тот же FIM. `dense` — контрольная квадратура
на каждом интервале, включая нулевые; `compact` — новый план точек.
План разбиения в обеих ветвях используется всеми Gauss-порядками пробного
давления. Замена выполняется benchmark-wrapper только в памяти процесса.
Файлы расчётных исходников не заменяются.

CPU float64, один Torch-поток, CUDA отключена. Последовательные пары;
CPU-тесты не запускались во время замеров. Все суточные задачи приняли
один шаг и прошли независимые компонентные аудиты. Времена включают
полный `solve_wall_s`, а не отдельную интерполяцию свойств.

### 512 скважин / 1024 ячейки / одни сутки

Три пары:

- dense: **2,386 / 2,371 / 2,324 с CPU**;
- compact: **1,673 / 1,719 / 1,598 с CPU**;
- медианы: **2,371 → 1,673 с**, ускорение **1,42×**, время меньше на 29,4%.

Точные исходные измерения хранятся в summary каждого запуска;
округлённые числа здесь предназначены для чтения.

### 2048 скважин / 4096 ячеек / одни сутки

Три пары, медианы **7,856 → 4,809 с CPU**, ускорение **1,63×**,
время меньше на 38,8%. Все 2048 скважин работают по давлению сети.
На принятом шаге отводы посчитаны пакетно без скалярных повторов;
общий одиночный коллектор сохранил скалярный путь.

Число реально вычисленных точек свойств за весь FIM-прогон:
**11 796 480 → 2 850 816**, сокращение в **4,14 раза**.
Максимум за один вызов свойств: **20 480 → 4 736 точек**.
Это счётчики вызовов ядра, не пиковая память всего процесса/autograd/GPU.

### 64 скважины / 128 ячеек / 65 PVTO-таблиц

Синтетическая расширенная PVT из предыдущей квалификации, одна пара:
**1,022 → 0,905 с CPU**. Вычисленные точки свойств:
**524 160 → 96 720**. Это дополнительный контроль другой сетки,
не серия для устойчивой оценки ускорения на любых больших PVT-наборах.

В каждой из семи пар конечные давление, Sw/Sg, Rs и накопленные
компонентные отборы **совпали побитно**. Оба результата каждой пары
прошли аудит расходов скважин, приёмника и запасов пласта. Применены
фиксированные бюджеты сравнения: давление 0,1 Па, насыщенности 1e-8,
Rs 1e-5 и компонентные отборы 0,01 кг; наблюдаемые разности нулевые.

## Месячное сопряжение с оборудованием

`final_coupled30_cpu`: 3 ячейки / 2 скважины / 30 суток / шесть пятисуточных
интервалов. Существующая обратная связь ограничений оборудования с
добычей. Новый запуск прошёл независимый аудит массы/ограничений и
строгое сравнение с сохранённым до уплотнения эталоном
`surface_pipe_batch/coupled_torch_batch_final_cpu`.

Конечные поля и отборы совпали побитно. Разница времени между этими

Протокол сравнения — `final_coupled30_comparison.json`.

## Почему нельзя просто удалить нулевые интервалы

У интервала может быть нулевая длина, но разные символические производные
концов — при совпадении фазовой границы или PVT-узла с портом. Полное
удаление теряет соответствующую часть Jacobian. Новый план сохраняет
half-width в графе и использует значение в совпавшей средней точке,
умноженное на сумму Gauss-весов. Проверено совпадение первых и вторых
производных с исходным полным правилом; производные третьего порядка
и выше не входят в подтверждённую область этого внутреннего оператора.

Активность определяется строго `half > 0`, без epsilon-отсечения.
Интервалы с различным числом ненулевых частей упакованы до максимума
внутри пакета; padding между строками остаётся. Символические ширины
пустых padding-слотов обнуляются: их производные учитываются ровно один
раз, через исходную совпавшую точку, без двойного вклада. Активные Gauss-точки и
совпавшие точки проходят одним общим вызовом свойств. PVT-покрытие,
изломы выбранных таблиц, bubble point, choking, механический баланс,
проверки конечности и допуски квадратуры не ослаблены.

## Проверки, ресурсы и GPU

**222 passed, 13 skipped**, точный лог — `regression.txt`.
Проверены нулевой полный интервал с ненулевой производной, разные
числа активных интервалов, первые/вторые производные, совпадение bubble
point и PVT-узла с портом, сохранение очень коротких интервалов, один
план на адаптивные порядки и один planning-read на весь пакет. Повторно
проверены конечные разности труб, весь FIM/Шур, restart, rollback и
учётные аудиторы.

Для выбора размера тензоров добавляется **одно чтение максимального
числа активных интервалов на пакет и пробное давление**. Оно не растёт
с числом труб или порядков Gauss; план используется повторно. Это
компромисс между размером буферов и синхронизацией. GPU-ускорение,
пиковая GPU-память и CUDA Graph capture этой серией не подтверждены.

Read-only диагностика текущего окружения: в `/proc` есть версия
NVIDIA-модуля и две записи GPU, но отсутствуют `/dev/nvidiactl`,
`/dev/nvidia-uvm`, `/dev/nvidia0`, `/dev/nvidia1`; `nvidia-smi -L` завершается
кодом 9. Это отсутствие необходимого доступа к устройствам в данном
окружении; драйверы, права и чужие расчёты не изменялись. Наблюдения
сохранены в `cuda_access.json`.

Модель остаётся изотермическим homogeneous Rs-only сборным деревом.
Это эквивалентность численного представления, не экспериментальная
калибровка PVT/корреляций. Norne не запускался. `blackoil_fim.py` и
`torch_linear.py` не изменены; матрица пласта остаётся разреженной.

## Воспроизведение

Запускать последовательно, без конкурирующих CPU-тестов. Выходные
каталоги должны отсутствовать:

```bash
export CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=src:scripts
python scripts/run_compact_quadrature_forecast.py --quadrature dense --config benchmarks/reports/surface_pipe_batch/wells2048_torch_batch_input.json --output /tmp/quad_dense2048
python scripts/run_compact_quadrature_forecast.py --quadrature compact --config benchmarks/reports/surface_pipe_batch/wells2048_torch_batch_input.json --output /tmp/quad_compact2048
python scripts/check_fim_well_forecast.py /tmp/quad_compact2048/trajectory.json.gz
pytest -q tests/test_blackoil_quadrature_plan.py tests/test_blackoil_pipe_batch.py tests/test_blackoil_pipe_grid.py
```

Исходные hashes, счётчики, аудит всех траекторий и результаты пар —
`validation.json`, `comparison_summary.json` и каталоги отдельных запусков.

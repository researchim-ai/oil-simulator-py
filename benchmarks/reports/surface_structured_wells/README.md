# Структурированное исключение скважин сборного дерева

Новый opt-in `well_block_backend=tree_structured` хранит B/D как действия
по дереву и перфорациям. Он не строит `B_full`, `D_full` или скважинную
единичную матрицу. Стандартный `dense` сохранён с прежними границами.
[Алгоритм, настройки и ограничения](../../../docs/STRUCTURED_WELL_COUPLING.md).

## Реальные FIM-прогоны

Один Torch CPU-поток, float64, CUDA отключена. Времена `solve_wall_s`
взяты из summary соответствующего завершённого запуска; это одиночные
измерения, не медианы и не сравнение ускорения с другим моделёром.
Все скважины в этих сценариях фактически работают в режиме `surface`,
поэтому проверка не сводится к несвязанным дебитным диагоналям.

- `wells512_cpu`: 512 скважин, 1024 ячейки, одни модельные сутки,
  один принятый шаг, **22,944 с**. Максимальный модуль остатка компонентной
  массы — **3,53e-5 кг**.
- `wells2048_cpu`: 2048 скважин, 4096 ячеек, одни сутки,
  один принятый шаг, **90,067 с**. Максимальный остаток — **1,54e-5 кг**.
- `wells129_cpu`: предварительный запуск 129 скважин / 256 ячеек,
  одни сутки за **6,275 с**. После него усилена относительная проверка
  диагонали локального предобуславливателя и отформатирован аудитор.
  Его исходные hashes сохранены; он не выдаётся за запуск окончательной версии.

Каждая скважина имеет собственный отвод к общему коллектору и одну
перфорацию. Вводятся большие верхние дебитные уставки, чтобы активировать
ограничение давлением сети. Число ячеек и диаметр общего коллектора
меняются между задачами (2048: 1 м вместо 0,5 м). Это серия квалификации
размеров, **не чистый тест сильного масштабирования**.

`trajectory.json.gz` хранит принятые состояния, фактические расходы и
режимы. Отдельный `check_fim_well_forecast.py` сверяет реестр скважин,
временной горизонт, backend/отсутствие плотных блоков, верхние дебитные
уставки, совпадение BHP с опорой сети в режиме surface, сумму скважинных
компонентов с приёмником и интеграл добычи с запасами пласта. Допуск
интегральной массы — 0,01 кг + 1e-8 от добычи. Это учётный аудит,
не независимая валидация PVT/гидравлических корреляций; отдельную проверку
нижней границы BHP для `bhp_limit` этот аудитор не реализует.

## Одинаковая модель пласта и площадки, 30 суток

`coupled_dense_input.json` и `coupled_structured_input.json` отличаются
только способом скважинного исключения. Модель малая: 3 ячейки, 2 скважины,
6 принятых пятисуточных шагов. Обе включают существующую обратную связь
ограничений оборудования с фактической добычей и прошли независимый
учётный аудит площадки.

- Dense: **11,332 с CPU**; structured: **11,998 с CPU**.
- Максимальная разность конечного давления: **1,77e-8 Па**.
- Sw: **1,39e-15**; Sg: **5,77e-15**; Rs: **2,63e-13**.
- Относительная разность накопленных компонентных отборов: **4,24e-14**.

Бюджеты сравнения записаны до запусков в `coupled_comparison_budgets.json`;
результат — `coupled_comparison.json`. Физическая конфигурация, расписание,
горизонт и допуски Ньютона одинаковы. Новое представление не ускорило эту
маленькую модель; его подтверждённый результат — устранение плотного
барьера памяти и сохранение действия полной системы уравнений.

## Большая алгебра без плотного эталона

`algebra4096_cpu`: **4096 скважин, 65536 перфораций, 4098 узлов**.
Тестовая D представляет диагональ плюс ранговое возмущение;
решение проверяется аналитически по формуле Шермана—Моррисона.
Bx сверяется с отдельной формулой локальных и общего потоков.

- Построение и допуск: **29,05 мс CPU**.
- D-solve + Bx: **6,40 мс**, медиана 10 повторений.
- Тензорные хранилища оператора вместе с заимствованными входами:
  **13 083 187 байт (12,48 MiB)**; общая память процесса не измерялась.
- Расчётный объём плотных B/D тех же размеров: **6 576 668 672 байт
  (6,125 GiB)**. Эти матрицы **не выделялись**.

Этот замер не включает пласт, PVT, нелинейные трубы, отчётность или
компонентный баланс реальной модели. Он не заменяет перечисленные выше
FIM-прогоны и не доказывает общую GPU-производительность.

## Границы и происхождение

Прежние ограничения физического адаптера сохранены: активные добывающие
скважины, дерево, совпадающие PVT/плотности и отметки перфораций с опорой
BHP; активный регулятор давления не поддержан tree_operator. Не добавлены
MSW, реверс, нулевой поток, кольца, группы или нагнетание. Для dense остаются
пределы 128 скважин / 10000 соединений. Structured использует оценку памяти
допуска, которая не ограничивает весь процесс/AMG.

Каждый запуск хранит protocol/progress/summary с исходными SHA256 и
проверкой неизменности исходников во время расчёта. Ошибка локального
pivot требует сертификата невырожденности до ограниченного matrix-free
GMRES; никакого плотного fallback. Каждое обращение D проверяет
собственную невязку по строкам. Регрессия сравнивает полный Шур с плотным
эталоном, смешанные режимы, повторные узлы/ячейки, сериализацию и
отклонение нечисловой поправки с восстановлением состояния.

Драйвер NVIDIA окружения недоступен. CPU-результаты не выдаются за RTX3090,
полностью автономный GPU-промысел, квалификацию Norne или промышленную
экспериментальную валидацию.

## Воспроизведение

Запускать последовательно, без конкурирующих CPU-задач. Выходные каталоги
должны отсутствовать:

```bash
export CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=src:scripts
python scripts/run_structured_well_forecast.py --config benchmarks/reports/surface_structured_wells/wells2048_input.json --days 1 --report-days 1 --output /tmp/wells2048
python scripts/check_fim_well_forecast.py /tmp/wells2048/trajectory.json.gz
python scripts/benchmark_structured_well_blocks.py --wells 4096 --perforations-per-well 16 --repeats 10 --output /tmp/well_algebra4096
python scripts/run_fim_facility_forecast.py --config benchmarks/reports/surface_structured_wells/coupled_structured_input.json --days 30 --report-days 5 --output /tmp/coupled_structured
python scripts/run_fim_facility_forecast.py --config benchmarks/reports/surface_structured_wells/coupled_dense_input.json --days 30 --report-days 5 --output /tmp/coupled_dense
python scripts/compare_fim_facility_forecast.py /tmp/coupled_structured/trajectory.json.gz /tmp/coupled_dense/trajectory.json.gz --budgets benchmarks/reports/surface_structured_wells/coupled_comparison_budgets.json --allow-numerical-policy --output /tmp/well_comparison.json
```

## Профиль следующего узкого места

Отдельный повтор `wells512_profile_cpu` выполнен под cProfile с теми же
исходниками и аудитом. Его **31,064 с** нельзя сравнивать с чистыми временами
как изменение скорости: инструментирование добавляет нагрузку. Компактная
выгрузка — `cpu_profile512.json`, исходные SHA сохранены в summary.

Вложенное накопленное время `BlackOilProductionNetwork.solve` — 29,319 с,
примерно **94%** инструментированного FIM solve. Четыре сборки сети вызвали
2052 решения труб, 14364 проверяемых интеграла и 28728 интегральных
квадратур. Основные работы — PVT-интерполяция, Colebrook и autograd
производных импульсного интеграла. Вложенные времена нельзя складывать.
Это указывает следующую цель: пакетная обработка независимых труб одного
уровня в PyTorch с сохранением разбиения по PVT/давлению насыщения,
контроля квадратуры и физических ограничений. Она ещё не реализована.
Снятие плотного скважинного барьера само по себе не делает этот host-путь
сети автономным GPU-расчётом.

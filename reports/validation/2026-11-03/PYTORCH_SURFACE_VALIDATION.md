# PyTorch/CUDA: динамическая жидкостная станция и тепловые поля

Дата: 2026-11-03. Это протокол переноса существующей модели, не заявление
о готовности всего промышленного наземного комплекса. Руководство:
[PyTorch CPU/CUDA](../../../docs/PYTORCH_SURFACE.md).

## Что изменено

В новой жидкостной динамике backend по умолчанию — Torch float64.
Перенесены совместная система давления/расхода/валов, карты, ограничения
мощности, датчики и стационарные preview диспетчера, механический баланс,
тепловой перенос, конечные массы и стенки. CPU/SciPy сохранён явным
`scipy_reference`, а не скрытым fallback. Запрошенная недоступная CUDA
вызывает ошибку. Файл blackoil_fim.py не редактировался.

Точные производные, ограниченный Ньютон и линейные решения остаются на
выбранном устройстве. Для больших структур — раскраска и разреженный GMRES,
без автоматической плотной матрицы. На CUDA line search считается батчем;
группы из двух итераций требуют невязки <=2e-11. Исправлено владение
выходами CUDA Graph: последующий replay не меняет предыдущий результат.

Для тепла реализованы заранее собранные обе ориентации потоков и локальные
редукции строк по степени на CUDA. Большая матрица не уплотняется;
неудачный итерационный solve отклоняется по балансу. TorchHeatInterval
держит все температурные поля и аудиты подшагов на устройстве и читает
один итоговый статус. Это интервал с заданными расходами, а не весь
связанный гидравлический расчёт без CPU.

## Полный связанный сценарий

Конфиг: configs/surface_thermal_liquid.json, восемь периодов, 23.1 с
физического времени: нагрев рециркуляции, trip, отказ раннего сброса,
охлаждение, безопасный сброс, повторный пуск и останов. Финальный CUDA
прогон прошёл на RTX 3090, UUID GPU-9ade3f1f-7ead-7504-f762-07be60234d31.
Другие процессы и RTX 3090 Ti не останавливались.

На финальном GPU-коде:

- wall time: 165.268 с;
- гидравлических подшагов: 7212;
- восстановленных дроблений: 996;
- все времена температурных событий и состояния блокировок совпали с CPU;
- максимальная разница давления: 4.65661287e-09 Па;
- скорости вала: 1.84741111e-13 рад/с;
- температуры жидкости: 1.13686838e-13 K;
- максимальная совместная энергетическая невязка: 4.25227176e-10 Дж.

CPU-прогон сопоставлен с сохранённой контрольной реализацией на SciPy: до 2.72 Па
и 3.17e-8 K на концах отчётных периодов, при одинаковых событиях. Шаги
адаптивные; равенство внутренних сеток по времени не требуется. До
оптимизаций CUDA полный CPU full/resumed прошёл побайтно (restart_check.json).
На окончательных исходниках дополнительно прошёл короткий restart
на CPU и CUDA. Старые checkpoint закономерно отклоняются после изменения
отпечатка источников, backend или device; их нельзя выдавать за переносимые.

Сохранённый исторический SciPy-прогон малой станции был быстрее текущего
Torch-пути. Перенос не объявляется ускорением относительно SciPy на этой
задаче. Старые протоколы и числа не переписаны. В этой серии оптимизируется
сам Torch/CUDA-путь и работа с большими полями.

## Измеренная производительность

Парный замер на одной RTX 3090, три раунда по 30 повторов с чередованием
порядка: последовательный line search и четыре итерации —
22.09–23.19 мс; батчевый и две итерации —
8.46–8.53 мс. Корни совпали точно.
Это сравнение способов исполнения одних уравнений; исходники обеих
вариаций сохранены в paired_sources/ с хешами в paired_cuda.json.

Ниже — заданные консервативные расходы и аналитическая цепочка объёмов,
не большой гидравлический/пластовый бенчмарк. 64 подшага при фиксированном
числе Куранта; физическая длительность 16/N с меняется с N. Время
интервала включает захват графа и синхронизацию, начальная сборка и первая
загрузка указаны отдельно; для длительного расчёта они оплачиваются один раз.

- 32768 ячеек: CPU 0.472593 с,
  CUDA 0.186710 с;
  setup CPU 0.107485 с,
  CUDA 0.233531 с.
  Ошибка аналитической температуры 0.00517507692 K,
  энергетическая невязка -1.12410081e-15 Дж.

- 262144 ячеек: CPU 4.511301 с,
  CUDA 0.473346 с;
  setup CPU 1.032664 с,
  CUDA 2.288679 с.
  Ошибка аналитической температуры 0.00517507692 K,
  энергетическая невязка -1.40512602e-16 Дж.

Без обмена полями CPU–GPU внутри этих интервалов: один скаляр статуса,
64 replay, никакой плотной большой матрицы. Первые замеры выполнялись
параллельно с CPU-тестами и непригодны для чистого сравнения устройств;
итоговое сравнение использует последовательные запуски benchmark_*_grouped.
Это измерения одной машины, не статистическая гарантия производительности.

## Проверки и ограничения

- Общая наземная регрессия до локальных CUDA-оптимизаций: 849 passed.
- После финальных CUDA-изменений — tests/test_surface_torch.py на CPU/CUDA:
  Torch/SciPy, новые команды при replay, разреженная физическая акустическая
  мода на 161 неизвестной, дубликаты/пустые/батчевые строки, отклонение
  плохого solve, автоматическая станция с запрещёнными SciPy-решателями,
  тепловые балансы и restart: 19 passed, один описанный ниже warning.
  Журнал — torch_tests_gpu.log.
- Интеграционная проверка FIM/surface: 38 passed, 17 skipped; пропущенные
  CUDA-тесты FIM не объявляются пройденными.
- Ruff, git diff --check и строгая сборка MkDocs проверяются отдельно.

Один известный warning Torch — временная device-копия не contiguous
входа searchsorted при vmap; это не CPU-fallback. Новые физические
модели этим переносом не добавлены: горизонтальная слабосжимаемая
однофазная жидкость с постоянными свойствами и калорическим переносом.
Кавитация, температурная EOS, фазовые переходы, многокомпонентная энергия,
единое динамическое сопряжение с FIM и калибровка реального оборудования
не закрыты. Старые PR/газовые и иные наземные реализации не объявляются
перенесёнными этим блоком.

Полный API по-прежнему координирует расписание, PID, переключения и
JSON на CPU и передаёт пакеты на физических подшагах. Следующий этап
ускорения — согласованное хранение связанного состояния и регуляторов
между подшагами; большой тепловой тест не доказывает его готовность.

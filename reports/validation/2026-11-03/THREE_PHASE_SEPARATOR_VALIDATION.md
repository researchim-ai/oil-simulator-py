# Динамическая трёхфазная сепарация — 3 ноября 2026

Область результата: [модель и ограничения](../../../docs/THREE_PHASE_SEPARATOR.md).
Несмешивающиеся нефть/вода и идеальный газ, общая температура,
гидростатика, фазовые запасы, энергия, стенки, двусторонние соединения,
ограниченные P-регуляторы. Torch CPU/CUDA float64. Это не flash и не
сопряжённый расчёт с FIM. Реальная калибровка не заявляется.

## Полный сценарий

`configs/surface_three_phase_separator.json`: два аппарата со стенками,
трёхфазный отбор, газовая связь, импульс воды, остановка, нагрев и запуск.
Пять периодов, суммарно 1 с. CPU и CUDA дали **40 принятых подшагов,
0 отказов**; конечные массивы фазовых масс и температур совпали точно.
Промежуточные невязки различаются на уровне округления; побитовая
эквивалентность CPU/CUDA-журналов не заявляется.

CUDA: максимальная массовая невязка сети `6.60e-15 кг`, энергетическая
`1.06e-8 Дж`; локальная энергия `8.80e-9 Дж`, стенка `1.34e-10 Дж`.
Минимальное производство энтропии `9.59e-3 Дж/К` на принятом подшаге.
Независимое суммирование внешних фазовых переносов за весь сценарий
совпало с изменением запасов до `8.3e-15 кг`. Эти значения характеризуют
дискретный баланс, а не точность свойств или временной аппроксимации.

CLI сохранил первые два периода CUDA; отдельный процесс воспроизвёл
префикс и продолжил расчёт. JSON побайтово совпал с непрерывным запуском.
SHA256: `958dcad02615b71a7ae937c4f9cf68562a8200237237c353e2c7b21673060135`.
Тепловая нагрузка без температуры утилиты отклонена с кодом 2;
существовавший выходной файл остался неизменным. Есть тесты подмены
checkpoint, несовместимых потоков и отказа без частичной публикации.

полный сценарий — `python scripts/run_three_phase_separator.py configs/surface_three_phase_separator.json --device cpu --output /tmp/separator.json`.

сопряжение с FIM, промышленная валидация и замер масштабирования крупных
связанных многофазных моделей. Модель не имеет паспортных данных установки.

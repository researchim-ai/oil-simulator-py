# Резидентное тепловое состояние в связанном расчёте станции

Дата: 2026-11-03. Это завершённый блок исполнения существующей жидкостно-
тепловой модели на PyTorch, без изменения физических свойств и уравнений.
Руководство: [PyTorch CPU/CUDA](../../../docs/PYTORCH_SURFACE.md).

## Реализация

По умолчанию ThermalLiquidStation использует thermal_state_transfer=report.
Температуры жидкости/стенок и массы удерживаются на устройстве до конца
отчёта. Между окнами управления экспортируются только объявленные датчики
из принятого состояния. Дискретный такт PID/защит, выдержки, reset, бюджеты
работы и температурные/энергетические критерии приёмки сохранены.

Добавлены TorchHeatSession, наблюдения датчиков, advance_records и отдельные
режимы window/record для проверки и измерений. Явный snapshot делает полный
экспорт без закрытия. close возвращает публичный LiquidHeatState и закрывает
сессию. Отказавшее окно не меняет курсор; его можно повторить. Изменение
модели в сессии и использование закрытой сессии отклоняются. Привязка времени
разрешает только округление конца уже пройденного интервала.

Обычный CPU/SciPy reference остаётся отдельным явно выбранным backend.
Новых физических EOS, температурной вязкости или фазовых переходов нет.
Файл blackoil_fim.py не редактировался.

## Размерный тест API

Здесь заданы консервативные расходы, а не решается большая гидравлическая
сеть. 16 записей, окна по 4 записи, шаг 0.25/N с; физическая длительность
4/N с уменьшается при росте сетки. Температурные кадры выключены явно.
Тепловое ядро прогрето одинаково; setup и прогрев приведены в JSON отдельно.
Время включает создание публичного LiquidHeatState и проверки, исключает
последующий расчёт хеша и запись итогового JSON. Сравниваются все значения

## Restart, совместимость и проверки

Checkpoint выбран из полного source-bound расписания на границе третьего
периода (prefix_extracted.json). Это извлечение реально рассчитанного
префикса, не заявление об аварийном прерывании процесса. CLI при продолжении
повторно проверил префикс расчётом и завершил оставшиеся периоды.
Полные JSON исходного и продолженного report совпали побайтно:
4c71413bc72bf7c9e67b26c64bb872a5fd88eff0eb9d1081e2ee0b9cc4e74dc5.

- Релевантная CPU-регрессия: 186 passed.
- Заключительный CPU/CUDA-набор на RTX 3090: 38 passed, один ранее известный
  warning searchsorted о contiguous-копии на устройстве.
- Проверены обе ориентации расхода, совпадение каждого баланса, ограниченные
  порции журнала, датчики жидкости и стенки, времена trip и PID, повтор
  отказавшего окна, владение состоянием/счётчиками при чередовании сессий,
  запрет мутации модели, use-after-close и прежние позиционные аргументы.
- Сохранён обычный формат результатов. Добавленный thermal_state_transfer
  расположен после прежних позиционных бюджетов. CLI может переопределять
  режим для всех периодов; scheduler fingerprint включает этот параметр
  и новый модуль сессии.
- Ruff, git diff --check и строгая сборка MkDocs проверяются отдельно.

Журнал температур при включении сохраняется полностью, с порциями около
16 MiB плюс один кадр и временная копия при сборке. Аудиты ограничены
заданным бюджетом числа подшагов. Убрано также квадратичное создание
словарей температур/масс при упаковке обычного record-пути.

с пластом не объявляются выполненными.

# Общая PR-термодинамика — проверка 3–4 ноября 2026

Область результата: [модель, интерфейсы и ограничения](../../../docs/EQUILIBRIUM_THERMODYNAMICS.md).
Реализованы компонентная PR EOS, до трёх равновесных фаз, PT/PH/PS/UV,
неявные производные, потоки полной энергии и компоненты, тепловые границы
stock-продукции, смешение/разделение и ячейки N/U/V на Torch CPU/CUDA.
Параметры примера не являются калибровкой Norne, реальной нефти или рассола.

поиск/синхронизации; эффективный пакетный GPU flash ещё не квалифицирован.

## Независимые основания и трудные случаи

Двенадцать сохранённых случаев CoolProp 7.2 PR для метан/этан, включая
несколько давлений, фазовых долей и явных `kij`. Данные:
`tests/data/surface/pr_mixture_coolprop.json`; [описание кубического
backend CoolProp](https://coolprop.org/coolprop/Cubics.html).
Константы production PR не подгонялись к округлённым константам fixture;
допуски сравнения фазовых долей `2e-4`, плотности `6e-4` относительных.
Собственный компонентный баланс flash проверяется до `1e-10`, равенство
логарифмов фугитивностей — до `1e-8`.

Три жидкие фазы в симметричной смеси сравнены с независимым скалярным
решением по прежней NumPy PR-модели. Симметричные фазы сопоставляются
по доминирующему компоненту, а не по порядку почти равных следовых долей.
Иллюстративная метан/гексан/вода даёт водную, углеводородную и газовую фазы,
с конечным испарением воды и растворением метана; также проверены 25 °C.
Этот тест подтверждает разрешение уравнений выбранной EOS, не точность
модели воды относительно эксперимента.

Проверены конечные разности неявного Якобиана, тождества Максвелла,
теплоёмкости, нулевые компоненты и поток, появление фазы с долей `1e-6`,
скрытая теплота чистого компонента, PH/PS и UV, передача энтальпии в
прежний PR API, механические составляющие энергии, явная характеризация
stock-масс и второй закон при нагреве/подъёме давления. В runtime-тесте
вызовы SciPy solve/root/minimize и NumPy linear solve запрещены.

## Полный CPU/CUDA-сценарий

`configs/surface_equilibrium_process.json`: две скважины с явной
stock-характеризацией и тепловыми условиями, подъём, смешение и
трёхфазное разделение при 3 МПа. Суммарный массовый расход `24.7 кг/с`,
температура разделения `367.536246135575 K`.

Оба финальных JSON прошли независимый `check_equilibrium_process.py`:
checksum, актуальные хеши 11 исходников, масса stock→компоненты,
глобальный компонентный/энергетический баланс, фазовые количества,
энергия каждого продукта, равенство фугитивностей и `u=h−Pv`.

CPU: энергетическая невязка `−3.73e-9 Вт`; CUDA: `1.12e-8 Вт`.
Максимальная компонентная невязка CUDA `5.69e-14 моль/с`;
логарифмическая невязка фугитивностей `1.55e-12`.
Производство энтропии около `899.514167483 Вт/К`, положительно.
Максимальная разность CPU/CUDA расходов отдельных компонентов продуктов
`1.71e-13 моль/с`, температуры — `5.69e-14 K`.
Это точность согласования дискретных расчётов, не экспериментальная
точность EOS. Побайтового равенства CPU/CUDA-журналов не требуется.

Отдельно подменены энергии двух продуктов на `+1/−1 Вт` с пересчитанной
checksum. Общий баланс сохранился, но независимый проверяющий скрипт
отклонил несогласованность энергии отдельной фазы.
Результаты: `verification.json`, `independent_audit_negative.log`.
Полный GPU-сценарий существенно медленнее CPU на этой малой задаче;
ускорение и готовность многократного flash для большой динамической
модели не заявляются.

## Что не подтверждается этим протоколом

Изотермический `blackoil_fim.py` не изменён и не решает энергию пласта.
Адаптер отчётов скважин требует явный assay и температуру либо энергию
границы; в результате `reservoir_energy_equation_solved=false` и
`pvt_eos_characterization_calibrated=false`. Из BO PVT не реконструируется
несуществующий известный молекулярный состав. Прямое неявное сопряжение
нового flash с FIM и патрубками прежнего динамического сепаратора не выполнено.

Мультистартовый TPD не доказывает абсолютный глобальный минимум.
Соли, ассоциация, твёрдые фазы, реальные теплоёмкости во всём диапазоне и
лабораторная калибровка отсутствуют. Физическая точность PR для реальной
воды/рассола не заявляется. Norne с этой новой EOS не пересчитывался;
результаты Norne и превосходство над Eclipse/OPM здесь не подтверждаются.

## Артефакты и воспроизведение

Каталог начат 3 ноября: `results/equilibrium_thermodynamics_20261103/`.
Он содержит CPU/CUDA-логи, полный сценарий, проверку атомарного отказа
и исходные данные. Локальные `results` могут не входить в Git.

```bash
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 python -m pytest tests/test_surface_equilibrium_thermodynamics.py tests/test_surface_thermal_boundary.py tests/test_surface_equilibrium_cli.py -q
python scripts/run_equilibrium_process.py configs/surface_equilibrium_process.json --device cpu --output /tmp/process-cpu.json
CUDA_VISIBLE_DEVICES=GPU-9ade3f1f-7ead-7504-f762-07be60234d31 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 python scripts/run_equilibrium_process.py configs/surface_equilibrium_process.json --device cuda --output /tmp/process-cuda.json
python scripts/check_equilibrium_process.py /tmp/process-cpu.json /tmp/process-cuda.json --output /tmp/process-verification.json
```

CLI сохраняет конфигурацию, версии и хеши физических исходников;
исходники фиксируются до импорта моделей и проверяются перед публикацией.
Проверяющий скрипт независимо пересчитывает сохранённые массовые,
энергетические, компонентные и фазовые соотношения, проверяет checksum
и соответствие исходникам, затем сравнивает CPU/CUDA продукты.

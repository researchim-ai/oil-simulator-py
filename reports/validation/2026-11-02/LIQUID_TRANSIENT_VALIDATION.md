# Жидкостные запасы, инерционные трубы и динамические насосы

Дата: 2026-11-02. Горизонтальная однофазная слабосжимаемая жидкость,
локальные запасы давления, инерция трубы, алгебраические клапаны и
насосные карты, независимые валы. CPU, синтетические данные.

## Реализованный физический блок

`LiquidTransientNetwork` решает давления конечных объёмов, трубные расходы,
насосные/клапанные расходы и скорости валов в одной неявной системе.
Повторно используются геометрия/трение Pipe, характеристики Pump,
ThrottleValve, RotatingDrive и распределение общей электрической мощности
DynamicPumpStation. Стационарная гидравлика не подменяет динамические
запасы и трубную инерцию. Двухфазная труба не используется с фиктивным газом.

Реализованы локальные и глобальный массовые балансы, механическая/
акустическая энергия, потери, торможение, остановки валов, выбег,
недоступность и trip с защёлкой. Питание отключается без удаления
вращения или движения жидкости. Клапан закрывается как отдельная
безмассовая ветвь, а соседняя труба сохраняет инерционное состояние.

Поправлены два края решения:

- При закрытом обратном клапане пробное ненулевое значение алгебраического
  расхода больше не создаёт сингулярную нагрузку P/omega на почти
  неподвижном валу. Уравнение закрытой ветви отдельно требует Q=0.
- Остановка на границе подшага учитывает временную точность события,
  а не обнуляет все малые положительные скорости. Независимые остановки,
  слабое ускорение и удержание при нулевой мощности покрыты тестами.

## Независимые численные эталоны

`scripts/check_liquid_transient.py` содержит три проверки:

1. Закрытые два объёма с одной ламинарной инерционной трубой: независимая
   формула затухающего осциллятора. Горизонт 0.02 s, начальные давления
   601000/599000 Pa, rho=1000 kg/m³, K=1e8 Pa. Ошибки давления для
   dt=0.0005/0.00025/0.000125 s: 2.3673421 / 0.5931592 / 0.1483749 Pa.
   Отношения около 3.9911 и 3.9977 подтверждают второй порядок по времени.
2. Стоячая волна в линии длиной 10 m: независимая непрерывная формула
   с ламинарным затуханием, горизонт 0.01 s. Ошибки давления при
   8/16/32 ячейках: 5.2267595 / 1.3312170 / 0.3356173 Pa.
   Отношения 3.9263 / 3.9665, время фиксировано на dt=0.00005 s.
3. Два разных вала, два объёма, инерционная труба и экспортный клапан:
   самостоятельно записанная ОДУ с формулой Пуазейля и квадратичными
   насосными кривыми, DOP853 с rtol=atol=1e-12. На горизонте 0.2 s ошибки
   давления при dt=0.004/0.002/0.001 s: примерно
   1.596682 / 0.399178 / 0.099794 Pa; отношения около 4.
   Ошибка скорости на самом мелком шаге около 7.986e-7 rad/s.

Нагрузки/аналитические решения не вызывают гидравлический решатель проекта.
Для проверки порядка включён фиксированный шаг, адаптивная оценка ошибки
отключена явно. Это проверка дискретизации и формул, не промысловая точность.
Результат с SHA исходников: `results/liquid_transient_20261102/reference_final.json`.

Структура уравнений сопоставлена с первичными описаниями
[WANDA, теория напорной трубы](https://deltares-wanda-core.readthedocs-hosted.com/en/latest/theoretical_and_mathematical_background.html)
и [MathWorks Pipe (IL)](https://www.mathworks.com/help/hydro/ref/pipeil.html).
Численных результатов WANDA/Simscape для этого примера нет;
сравнение с ними не заявляется.

## Обнаруженная фазовая ошибка и её исправление

Первый вариант сохранял массу/энергию, но CFL по длине трубы и
ограничение изменения давления недостаточно разрешали быстрые колебания
присоединённого малого выходного объёма. После закрытия клапана на
0.08 s изменение maximum_dt от 0.005 до 0.000625 s меняло конечное
выходное давление от 764045 до 1074966 Pa. Малый остаток энергии
не был основанием объявлять такую траекторию точной.
Исторический диагностический файл:
`closure_time_refinement_before_error_control.json` в каталоге результатов.

Добавлена включённая по умолчанию оценка локальной ошибки: полный подшаг
сравнивается с двумя половинными, принимаются только консервативные
половинные состояния. Экстраполяция не применяется. Управление шагом
использует давление, трубный расход и скорость каждого вала;
причины отказов отделены от нелинейной сходимости.

На том же закрытии клапана:

- штатные допуски: конечное p_outlet=1153648.0373 Pa,
  максимум по узлам/времени 1164384.9109 Pa, минимум 163082.3523 Pa;
- допуски в 16 раз строже: p_outlet=1153908.8024 Pa,
  максимум 1164386.7786 Pa, минимум 163075.9290 Pa.

Расхождение конечного выходного давления 260.77 Pa вместо примерно
389864 Pa у исходного грубого варианта относительно уточнённого расчёта.
Это **сравнение численных разрешений одной модели**, не независимый
эталон реального гидроудара. Глобальная ошибка произвольной траектории
не равна локальному допуску и не гарантируется им.
На штатных допусках принято 1470 половинных подшагов, на строгих — 3686;
максимальные принятые оценки ошибки 0.99723 и 0.97116, предел 1.
Файл: `results/liquid_transient_20261102/closure_accuracy_refinement.json`.
Разовые CPU-времена 25.02/60.21 s сняты параллельно с другими проверками;
это оценка стоимости точности, не изолированный performance-бенчмарк.

## Полный сценарий 5.28 s

`configs/surface_liquid_transient.json`: два насоса, линия 20 m,
четыре распределённых объёма трубы, коллектор и малый выходной объём.

1. Равновесие 0.05 s: скорости 100/100 rad/s, воспроизводятся давление
   и расход старой стационарной модели. Принято 26 половинных подшагов.
2. Закрытие экспортного клапана на 0.08 s: запасы и давление меняются,
   обратные клапаны насосов блокируют подачу, валы не исчезают.
   В t=0.13 s скорости около 100.116686 rad/s. Принято 1470 подшагов.
3. Trip и открытие экспорта на 0.8 на 0.15 s: питание снято,
   валы и жидкость продолжают движение; конечные скорости около
   99.567592 rad/s. Принято 696 подшагов.
4. Явный reset и торможение на 5 s: оба вала приходят к нулю,
   трубные запасы и расходы продолжают рассчитываться. Принято 10323 подшага.

Итого 12515 принятых физических подшагов и 576 отклонённых макропроб:
7 по изменению давления, 569 по оценке временной ошибки.

Import ограничен 1800 W (фактически пик около 787.37 W), export — 1000 W

Максимальный локальный массовый остаток ≤9.85e-14 kg,

## Воспроизведение

```bash
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 MPLCONFIGDIR=/tmp/norne-mpl \
python -m pytest -q tests/test_surface_liquid_transient.py
python scripts/check_liquid_transient.py --output results/liquid/reference.json
python scripts/run_liquid_transient.py configs/surface_liquid_transient.json \
  --output results/liquid/full.json
python scripts/run_liquid_transient.py configs/surface_liquid_transient.json \
  --stop-after 2 --output results/liquid/partial.json
python scripts/run_liquid_transient.py configs/surface_liquid_transient.json \
  --checkpoint results/liquid/partial.json --output results/liquid/resumed.json
cmp results/liquid/full.json results/liquid/resumed.json
```

## Границы готовности

26 целевых тестов покрывают независимые эталоны, закрытую сеть без
опорного давления, разворот потока, равновесие станции, закрытие клапана,
trip, недоступность, бюджет мощности, независимые остановки, слабый разгон,
нулевую мощность, диссипативное торможение, запрет выхода за карту,
адаптивную точность, JSON/restart и атомарность выхода при ошибке CLI.

Нет автоматической диспетчеризации/PID с этой динамической сетью,
высот/гравитации, кавитации, разрыва столба, многофазности, теплового
уравнения, PR/FIM-сопряжения и GPU. K, карты и коэффициенты не калиброваны
по реальным данным. Текущий код — проверяемый физический блок, не заявление
о завершении всего промышленного наземного моделера.

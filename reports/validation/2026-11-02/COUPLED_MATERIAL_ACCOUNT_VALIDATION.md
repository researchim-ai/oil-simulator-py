# Сквозной учёт компонентов FIM–площадка, 2026-11-02

## Изменение

В `FacilityCoupledFIM` добавлены интегральный покомпонентный учёт на принятом
подшаге и накопленный учёт продуктов. Перед принятием шага продукты подготовки
независимо сверяются с фактической подачей. Повреждённый результат отклоняется
через существующий механизм отказа и rollback. Пластовые CNV/MB не менялись.

Это учёт закрытого producer-only пласта и стационарной площадки без запаса,
а не сопряжение динамической PR-сети с black-oil. Формулировка и ограничения
гидравлической модели сохраняются. Новых GPU-ядер нет: для учёта передаются
лишь два вектора из трёх компонентных сумм на принятый подшаг.

## Воспроизводимый пример

```bash
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 python scripts/run_fim_blackoil_surface.py configs/fim_blackoil_facility_coupled.json --outlet-mpa 1 --days 2 --output results/coupled_material_account_20261102/full_chain.json
```

Два принятых подшага, 172800 s. Накопленная добыча компонентов:
нефть 5156.129518150633 kg, вода 2494.527406553151 kg,
газ 383.3420915925766 kg. Остаток «начальный запас − текущий запас − продукты»:
3.1916261e-7, 1.4556463e-8, 3.3445417e-8 kg соответственно.
Финальная доля верхних пределов дебита: 0.021367416381835938.
Это малый демонстрационный пример, не Norne и не сравнение с Eclipse.

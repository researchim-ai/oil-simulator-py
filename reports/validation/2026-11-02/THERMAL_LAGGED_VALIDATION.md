# Тепловая труба: фиксированный на подшаге датчик диссипации

Дата: 2026-11-02. Снимок уточняет результаты постоянного потока из
`THERMAL_SHOCK_FIX_VALIDATION.md`, не переписывая исторические измерения.
Область: отдельная горизонтальная однородная замороженная двухфазная труба,
несжимаемая жидкость и идеальный газ, постоянные Cv, CPU.

## Изменение реализации

Добавлен локальный датчик кривизны переменных энтропии и alpha.
Его значение theta в [0,1] вычисляется из **принятого состояния** один раз
перед попыткой подшага и фиксируется во время нелинейного решения.
Неявными остаются сами потоки, EOS, температура и скорость волны.
Датчик умножает консервативную и дополнительную тепловую диссипацию.
В гладких участках уменьшается размазывание волн.

Это устраняет необходимость дифференцировать негладкий датчик внутри
Ньютона. Трёхъячеечный шаблон нелинейной матрицы теперь соответствует
фактической зависимости остатка от новых неизвестных. Прежний полностью
неявный эксперимент с датчиком даже при расширенном шаблоне не проходил
проверки сходимости; он не используется.

Поскольку коэффициенты неотрицательны, знак энтропийной диссипации
сохраняется. Проверки физических границ, нелинейной сходимости, полной
энергии и дискретной энтропии не ослаблены. Критерий локальной температуры
по-прежнему <0.02 K; глобальные критерии — L1 T <0.1 K, L1 P <0.5%.

Параметры по умолчанию: `adaptive_entropy_dissipation=true`,
`thermal_entropy_dissipation=1.4`. Старый постоянный энтропийный поток
воспроизводится сочетанием false и 0.75, Rusanov — отдельным режимом.
Параметры входят в model_id/checkpoint; журнал содержит минимум/максимум
датчика. Дополнительной скрытой памяти датчика между шагами нет.

## Как выбирался коэффициент и что считается независимым

Коэффициент — численный параметр диссипации, а не подгонка EOS или PVT.
В исходной задаче и первых четырёх дополнительных состояниях испытывались
коэффициенты 1.0 и 1.5. Первый давал локальный перегрев до 0.05110 K,
второй проходил эти случаи. Первая зарезервированная матрица выявила
пограничную ошибку 0.0207804 K при alpha=0.99, ±30 m/s.
Она **не объявлялась пройденной**, и её состояния после дальнейшего выбора
коэффициента переведены в численную калибровку.

Окончательно выбран один коэффициент 1.4 для всех состояний, без изменения
эталона и порогов. После его фиксации зарезервированы новые четыре случая:
(alpha, |v|) = (0.972,45), (0.982,40), (0.988,50), (0.978,55).
Они не использовались при выборе 1.4. В скрипте раздельно доступны
`--matrix regression`, `calibration`, `validation`, `all`.
Это разделение не позволяет называть использованные при выборе задачи
независимой валидацией. Набор конечен, гарантии для всех состояний нет.

## Другие диагностические эксперименты

- Перенос точного усреднённого состояния после t=0.001 s на 128 ячейках
  постоянным потоком тоже создавал локальное отклонение около −0.15251 K.
  Дефект не сводится к единственному начальному столкновению.
- Постоянное усиление тепловой диссипации на всех гранях ухудшало локальную
  температуру; варианты с отдельным контактным датчиком не вошли в код.
- Уменьшение dt в четыре раза для лагированного варианта chi=1.0 снижало
  ошибку сильного режима с 0.05110 до 0.03895 K, не достигая 0.02 K.
  Одно временное уточнение не решало задачу.
- Масштабированные малые прогоны использовались для предварительного
  отбора вариантов; итоговые критерии проверены заново на исходных сетках
  и времени, без замены N=512 или t=0.005 s.
- Явный SSPRK2 оказался быстрым в прототипе, но не вошёл в рабочий солвер:
  источники, CFL, положительность и общие режимы для него не проверены.

Сходные локальные ошибки при взаимодействии размазанных ударных волн
рассматриваются в [Rider, 1994, Errors When Shock Waves Interact Due to Numerical Shock Width](https://epubs.siam.org/doi/10.1137/0915075).
Это контекст численного явления, не доказательство для нашей EOS.

## Итоговые численные результаты

Исходная задача, N=512: ошибка центра 0.003624274 K (постоянный поток
0.007072325 K, старый Rusanov около 0.18063 K). Глобальная L1-ошибка T
уменьшилась с 0.09433324 до 0.03422211 K. Уточнение 32/128/512 проходит
глобальные критерии, локальный критерий проверяется на самой мелкой сетке.

Дополнительно проверена более мелкая сетка N=1000 для alpha=0.98, ±60 m/s:
локальная ошибка 0.019644607 K, L1 T=0.022713686 K, L1 P=1158.606 Pa.
Принято 1251 подшагов, отказов 0, максимальная невязка энергии 2.885e-10 J.
Критерий выполнен с небольшим запасом: локальная ошибка не обязана монотонно
убывать при уточнении. Максимум T по всей трубе тоже записан отдельно;
критерий центра не объявляется нормой L-infinity по всем ячейкам.

Расширенный набор на N=512 прошёл все 12 состояний. Максимальная ошибка
центра 0.017705260 K; максимум в четырёх зарезервированных случаях
0.011230050 K. Во всех 12 случаях отказов подшага 0 и выполнены оба
глобальных критерия. При выборе коэффициента эти четыре зарезервированных
результата не использовались.

## Проверка скорости

`scripts/benchmark_thermal_fluxes.py` выполняет три чередующихся измерения
трёх методов на 64 ячейках, два подшага, начальная инициализация исключена.
В этом опыте старый постоянный энтропийный поток требовал 23 нелинейных
вычисления, новый — 11. Фон не изолирован, замер не является промысловым
или GPU-бенчмарком. Медианы: Rusanov 0.312858 s, постоянный энтропийный поток 0.435697 s,
новый 0.198978 s. Отношение стоимости старого постоянного к новому около
2.19. Все образцы и отпечатки исходников: `final_paired_timing.json`.
Нельзя переносить это ускорение на Norne или весь наземный контур.

## Воспроизведение и артефакты

Каталог: `results/thermal_lagged_20261102/` (не включается в git).
Все проверки выполняются с CUDA_VISIBLE_DEVICES пустой,
OMP_NUM_THREADS=1, MKL_NUM_THREADS=1.

```bash
python scripts/check_surface_reference_suite.py --require-local-temperature --include-shock-matrix --shock-workers 4 --output-dir results/thermal_lagged_20261102/final_14_suite
python scripts/check_pipe_shock_matrix.py --matrix validation --cells 512 --workers 4 --output results/reserved_shocks.json
python scripts/benchmark_thermal_fluxes.py --output results/thermal_lagged_20261102/final_paired_timing.json
python scripts/run_transient_pipe.py configs/surface_thermal_pipe.json --output results/thermal_lagged_20261102/final_full.json
python scripts/run_transient_pipe.py configs/surface_thermal_pipe.json --stop-after 1 --output results/thermal_lagged_20261102/final_partial.json
python scripts/run_transient_pipe.py configs/surface_thermal_pipe.json --checkpoint results/thermal_lagged_20261102/final_partial.json --output results/thermal_lagged_20261102/final_resumed.json
cmp results/thermal_lagged_20261102/final_full.json results/thermal_lagged_20261102/final_resumed.json
```

Полный запуск и restart дали побайтно одинаковые JSON. Целевые проверки
датчика, знака энтропии, потока, трубы и защиты эталонного gate: 36 passed.
Расширенный gate требует прохождения всех 12 дополнительных состояний;
при отказе матрицы он не объявляет успех по исходной задаче.

Ограничения: нет промысловой калибровки, теплового проскальзывания,
нефтяной и водной фаз отдельно, реальной калорики/фазового обмена,
сопряжения этой трубы с FIM или GPU-реализации. Результаты этой проверки
не являются объявлением готовности всего промышленного моделера.

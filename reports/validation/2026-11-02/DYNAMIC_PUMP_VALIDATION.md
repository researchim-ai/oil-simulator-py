# Связанный насос, привод, сеть и PID

Дата: 2026-11-02. Реализованный блок: один управляемый центробежный насос
в квазистационарной однофазной жидкостной сети, инерция вала, цифровой
PI/PID и расписание. Расчёт CPU; новых запусков Norne/GPU этот протокол
не описывает.

## Реализация

- Нагрузка насоса, расходы и давления пересчитываются внутри поиска новой
  средней скорости вала; нагрузка предыдущего шага не удерживается.
- Схема средней точки даёт дискретный баланс кинетической энергии без
  добавления неучтённой численной потери. Отдельно учитываются электрическая
  энергия, двигатель, насос, сопротивление вала, трубы, арматура и работа
  давления/высоты на границах.
- Используются существующие квадратичные/табличные напорные характеристики,
  КПД, NPSH и ограничения насоса. Дополнительная задаваемая мощность
  нулевого расхода масштабируется по кубу скорости и входит в нагрузку/тепло.
- PID: производная по измерению с фильтром, насыщение, anti-windup по
  внутреннему пределу и фактически приложенному моменту, manual/auto/off,
  переключение без скачка первой автоматической команды.
- Ограничения момента, потребления/экспорта электрической мощности и
  максимальной скорости учитывают фактическую работу. Жёсткие нарушения
  насосной карты/NPSH/области свойств возвращают ошибку.
- Операторский trip защёлкивается до явного reset; off моделирует выбег,
  а не мгновенное удаление кинетической энергии.
- Адаптивные подшаги не повторяют интегрирование PID. Отчётное время
  проходится полностью. Сохранённые скорость, память регулятора, момент
  и защёлка восстанавливаются на границе периода.
- Checkpoint проверяет параметры, команды, исходники, версии NumPy/SciPy,
  часы, механические работы и общий баланс. История PID воспроизводится
  без повторного решения всех прежних гидравлических состояний.

Исходники: `pid.py`, `pump_drive.py`, `pump_drive_schedule.py`;
CLI `scripts/run_pump_drive.py`; пример `configs/surface_dynamic_pump.json`.
Руководство: [насос, сеть и PID](../../../docs/DYNAMIC_PUMP.md).

## Независимый эталон

`scripts/check_dynamic_pump.py` использует отдельные формулы Пуазейля,
аналитическое решение квадратичной насосной характеристики и DOP853
для ОДУ вала (rtol/atol 1e-12). Он не вызывает насосную/гидравлическую
функцию симулятора для построения эталонной нагрузки.

Постоянная команда 6 N m, начальная скорость 60 rad/s, время 4 s;
включены вязкое сопротивление и дополнительная мощность насоса 20 W
на номинальной скорости. Эталонная конечная скорость 71.1211252376 rad/s.

При dt=0.2/0.1/0.05 s ошибки скорости:
7.32611346e-5, 1.83117017e-5, 4.57766008e-6 rad/s.
Отношения ошибок 4.00078 и 4.00023 подтверждают второй порядок
вала с сетью при постоянной команде. Максимальная ошибка расхода
против независимой формулы около 4.14e-12 m³/s.
Максимальный Re<260, то есть эталон действительно остаётся ламинарным.
Ни один из трёх прогонов не дробил шаг из-за отказа.

Это не калибровка реального насоса и не оценка порядка непрерывного PID:
цифровой регулятор имеет собственный такт и отдельно проверяется тестами.

## Полный сценарий

Пример содержит 120 s и шесть периодов:

1. 60 s: запуск с нуля, уставка давления 260000 Pa; конечное давление
   259980.676 Pa, ошибка 19.324 Pa, скорость 77.8364 rad/s.
2. 5 s: ручная команда 4 N m, переход без сброса механической энергии.
3. 30 s: автоматический режим, новая уставка 262000 Pa и противодавление
   255000 Pa; конечное давление 262132.727 Pa. Оставшаяся переходная
   ошибка −132.727 Pa записана явно, не объявляется нулевой.
4. 5 s: trip, двигатель обесточен, вал продолжает выбег.
5. 5 s: запрос auto без reset оставляет двигатель отключённым;
   защёлка сохранена, расход к концу равен нулю.
6. 15 s: явный reset и торможение до покоя, без фиктивного экспорта
   энергии после остановки.

Всего принято 1200 подшагов, отказов 0. Максимальные остатки:
общий энергетический баланс 7.40e-8 J, механический баланс 3.34e-9 J.
Контрольный интервал заканчивается ровно на 120 s. Непрерывный запуск
и продолжение после третьего периода дают побайтно одинаковые JSON.

Дополнительно тестируются внешние пределы мощности/скорости, нулевая
доступная электрическая мощность, табличная напорная кривая, внешнее
изменение давления, неподвижный/вращающийся насос без расхода, удержание
покоя и точное число тактов PID при повторных попытках физического шага.
Подмена сохранённых работ, фактического момента и памяти PID отвергается
даже после пересчёта checksum.

в `feedback_modes.json`; они не означают прохождения любых других
уставок с этими же коэффициентами.

## Воспроизведение

```bash
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 python -m pytest -q tests/test_surface_pid.py tests/test_surface_dynamic_pump.py
python scripts/check_dynamic_pump.py --output results/pump_drive_20261102/final_reference.json
python scripts/run_pump_drive.py configs/surface_dynamic_pump.json --output results/pump_drive_20261102/final_full.json
python scripts/run_pump_drive.py configs/surface_dynamic_pump.json --stop-after 3 --output results/pump_drive_20261102/final_partial.json
python scripts/run_pump_drive.py configs/surface_dynamic_pump.json --checkpoint results/pump_drive_20261102/final_partial.json --output results/pump_drive_20261102/final_resumed.json
cmp results/pump_drive_20261102/final_full.json results/pump_drive_20261102/final_resumed.json
```

## Границы результата

Закрыт связанный блок **одного насоса с квазистационарной жидкостной сетью**.
Это не завершение всех задач наземного моделирования. Нет динамических
запасов/сжимаемости труб, гидроудара, тепловой неизвестной жидкости,
многоквадрантной машины, группы динамических насосов, электрической
динамики мотора, компрессорной карты/помпажа или связи этого блока с FIM/GPU.
В изолированных объёмах без опорного давления требуется модель запасов;
неопределимое давление не подменяется произвольным числом.

Параметры и настройки примера синтетические. Паспортных данных нет,
поэтому численная верификация не называется промысловой калибровкой.

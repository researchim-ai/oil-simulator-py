# Конечная пропускная способность газового экспорта

Реализация 31 октября 2026. Добавлен `GasExportValve` и функция
`ideal_gas_nozzle_flow`: эквивалент сухого газового регулирующего элемента
через Cd и площадь горловины. Элемент включён в экспорт после смешения
и, если задана, экспортной трубы. Обратное влияние на пласт здесь не решается:
площадка получает заданные компонентные потоки и может ограничить их подачу.

## Физическое приближение

Используется калорически совершенный идеальный газ с постоянными R и gamma.
Входные давление и температура — параметры торможения в низкоскоростном
объёме перед соплом. Давление после элемента — противодавление принимающего
объёма. Открытие линейно масштабирует эффективную площадь: A_eff = Cd A opening.
Это **эквивалент сопла**, а не полный IEC sizing реального клапана.
Cd, площадь и характеристику открытия нужно задавать по оборудованию.

Для r = p_back / p_in критическое отношение равно

```
r_critical = (2 / (gamma + 1)) ** (gamma / (gamma - 1))
```

При r > r_critical массовый расход:

```
m = Cd A opening p_in / sqrt(R T_in)
    * sqrt(2 gamma/(gamma-1) * (r**(2/gamma) - r**((gamma+1)/gamma)))
```

Ниже критического отношения вместо r используется r_critical. Расход
перестаёт зависеть от противодавления; в горловине M=1. Основа:
[NASA, Isentropic Flow Equations](https://www.grc.nasa.gov/www/k-12/airplane/isentrop.html)
и [NASA, Mass Flow Choking](https://www.grc.nasa.gov/www/k-12/airplane/mflchk.html).
Реализованы устойчивые log1p/expm1-формы при малом перепаде и gamma, близком к 1.

Горловина охлаждается при ускорении. После адиабатического смешения струи
в низкоскоростном принимающем объёме идеальный газ восстанавливает температуру
торможения. Поэтому **температура горловины и выходного объёма различаются**.
Выходная температура не является прогнозом Джоуля–Томсона для реального газа.
Проверяются расход через rho A v в горловине и h0 = h + v²/2.
Для выходного объёма нет работы/теплообмена; отчёт содержит также рост энтропии.

## Расход, регулятор и обратные задачи

`ideal_gas_nozzle_flow` возвращает расход, режим, параметры горловины,
остатки массы/энергии и аналитические производные по входному/выходному
давлению, температуре, площади, Cd и открытию. На критической полке
производная по противодавлению равна нулю. При нулевом перепаде производные
по давлениям не определены: возвращаются null и явный признак. Никаких NaN/Inf
вместо этого в JSON нет. При закрытии фактическое состояние горловины не выдумывается.
Обратный поток не поддерживается.

`GasExportValve.run(inlet, gas)` для заданных массового расхода, давления и
температуры перед элементом вычисляет **требуемое открытие** под заданное
противодавление. `max_opening` — предел регулятора, а не фактическое фиксированное
открытие. Если сечения не хватает, поднимается ошибка оборудования.
Площадка не пропускает лишнюю массу через ограниченное сечение.

`required_supply_pressure` решает единственное входное давление при заданных
расходе, противодавлении и открытии. `required_back_pressure` решает обратную
задачу ниже критической пропускной способности. На критическом расходе
противодавление не единственно: возвращается `critical_plateau`, null вместо
произвольного давления и верхняя граница p_critical. Выше пропускной способности
запрос отклоняется. Производные обратных задач получены неявным дифференцированием.
Слишком малый расход, неразрешимый при точности давления float64, даёт численный
отказ, а не фиктивное давление. Нулевой расход/закрытие отмечаются отдельно.

## Площадка, ограничения и расписание

В `gas_export` необязательный блок:

```json
{
  "export_valve": {
    "name": "export_trim",
    "outlet_pressure_pa": 2000000,
    "throat_area_m2": 0.00002,
    "discharge_coefficient": 0.8,
    "max_opening": 1.0
  }
}
```

Положительны площадь, давление и Cd; Cd <= 1, 0 <= max_opening <= 1.
При положительном расходе закрытый элемент отклоняется.
Старые конфиги без `export_valve` сохраняют прежнюю модель экспорта.

`SurfaceFacility.run` принимает `gas_valve_max_opening` и
`gas_valve_outlet_pressure_pa`. В расписании действуют одноимённые поля периода;
значения сохраняются до следующей команды. Вода использует прежний независимый
`valve_openings`. У неизвестного газового элемента команды отклоняются даже
во время остановки. Изменения не мутируют базовую конфигурацию.

Предел сечения входит в существующий `FacilityCapacityControl`: физический
отказ может ограничить долю подаваемой продукции. Численные отказы не считаются
признаком отсутствия мощности. В отчёт добавлены открытие, пропускная способность,
её использование, Mach и давление/температура горловины. Энергия компрессии,
охлаждение, массы всех компонентов и накопления остаются в общем аудите.
Конфигурация элемента и исходный код входят в отпечаток checkpoint.

```bash
python scripts/run_surface_facility.py configs/surface_gas_valve_facility.json --output /tmp/gas_trim.json
python scripts/run_surface_schedule.py configs/surface_gas_valve_facility.json configs/surface_gas_valve_schedule.json --output /tmp/gas_schedule.json
python scripts/run_surface_schedule.py configs/surface_gas_valve_facility.json configs/surface_gas_valve_schedule.json --stop-after 3 --output /tmp/gas_partial.json
python scripts/run_surface_schedule.py configs/surface_gas_valve_facility.json configs/surface_gas_valve_schedule.json --checkpoint /tmp/gas_partial.json --output /tmp/gas_resumed.json
```

## Область проверки

`tests/test_surface_gas_valve.py`: независимая формула через Mach, докритический
и критический расход, полка и переход, производные против конечных разностей,
обратные задачи, очень малый перепад, калорический предел, сечение/ограничение
площадки, компонентный/энергетический баланс, остановка и JSON-продолжение.
В `results/gas_export_valve_20261031/nozzle_reference.json` сохранены 84 точки
сравнения с независимой параметризацией через Mach: максимальная относительная
разница массового расхода 2.25e-12. Это проверка формул, не экспериментальная
калибровка оборудования и не коммерческий бенчмарк.

Расписание демонстрирует заданную подачу 0.144 кг/с сухого газа и ограничение
проходного сечения. При max_opening=0.1 пропускная способность около 0.02219 кг/с;
при повышении противодавления до 5 МПа — около 0.01727 кг/с, режим докритический.
После возврата сечения полная подача восстанавливается. Остановка не создаёт
фиктивных давлений/температур/потоков; на запуске режим рассчитывается заново.

## Что ещё требуется

Не реализованы real-gas EOS, конденсация/газожидкостный критический штуцер,
расчёт состава, реальные карты характеристик, динамика привода, прогноз шума/
эрозии, нестационарная газовая сеть и совместный пласт–подготовка–экспорт.
Газовый блок и дискретное управление работают на CPU; резервуар/Шур CUDA
не изменялись. CUDA-регрессия проверяет существующую связь FIM, не ускорение
этого малого газового расчёта.

Итоговая проверка: **485 passed, 97 skipped, 12 slow deselected** в общем
быстром наборе; 18 профильных газовых проверок входят в этот набор.
Дополнительно 14 проверок существующей FIM-связи с CUDA прошли на RTX 3090 Ti.
Это регрессия общего импорта/связи, а не выполнение нового газового элемента на GPU.
В расписании энергетический остаток газового блока не превышает 4.55e-13 Вт;
остаток энергии сопла в проверке 84 точек — 2.19e-11 Дж/кг.
JSON-перезапуск точно воспроизвёл конечный checkpoint и накопления.
Артефакты, контрольные суммы исходников и команды запуска:
`results/gas_export_valve_20261031/validation.json` и `reproduce.sh`.

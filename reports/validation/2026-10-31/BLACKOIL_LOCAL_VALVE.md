# Локальный жидкостный клапан в black-oil сети

31 октября 2026. Добавлен отдельный `ProductionValve` / `BlackOilLiquidValve`.
Это локальная потеря давления, а не распределённое сопротивление трубы.
Поддерживается жидкая нефть/вода с растворённым газом; свободный газ не поддерживается.

## Замыкание и входные данные

Для одинаковых сечений и отметок входного/выходного портов:

```
G = (m_o + m_w + m_g) / A
K_eff = K / opening²
p_in - p_out = K_eff G² v(p_in, m) / 2
p_vena = p_in - (p_in - p_out) / F_L²
```

`v` — удельный объём жидкой смеси по общему PVT. Коэффициенты K и F_L,
а также давление пара задаёт пользователь. Они не подбираются по пластовым
результатам. Закон местной потери через коэффициент K описан в
[DOE Fundamentals Handbook, Fluid Flow](https://www.energy.gov/documents/doe-hdbk-1012-92vol3).
Применение плотности на входе, закона открытия K/a² и оценки давления
в сжатом сечении — явно принятые замыкания этой реализации.
Это не полная реализация IEC sizing и не универсальная корреляция штуцера.

Проверяется положительный запас `p_vena - vapor_pressure_pa`.
Через PVT-flash проверяются вход, выход и сжатое сечение: газ может выделиться
внутри клапана, даже если на обоих портах жидкость. Такие режимы отклоняются.
Также отклоняется относительное изменение плотности более 1% относительно входа
на выходе или в сжатом сечении. Это ограничитель применимости приближения,
а не оценка полной ошибки реального клапана.

Номинальная диссипация равна `m_total * (p_in-p_out) * v_in`.
Выводимый механический остаток проверяет это жидкостное замыкание;
он не является энтальпийным или полным термодинамическим балансом.
Реальные коэффициенты, диапазон расходов и давление пара должны соответствовать
оборудованию и температуре. Примеры содержат демонстрационные значения.
Поправка K по Reynolds, вязкости и геометрии затвора не реализована.

## Производные и связь

Для прямого и обратного расчёта дифференцируется локальное уравнение потери
по обоим давлениям, трём компонентным массам и K. Для открытия применяется
цепное правило d(K/a²)/da. Дерево переносит производные всех ветвей,
включая смешение компонентов перед локальным элементом.

Существующий `BlackOilPressureControl` может регулировать открытие локального
клапана. При достижении уставки его неявная производная входит в B/D и полный
Шур FIM; на пределе открытия используется фактическое давление.
Неподдерживаемый фазовый режим и нарушение ограничения оборудования явно
отклоняются, состояние неуспешного шага откатывается.

`pipes` остаётся списком труб; `valves` — отдельный список локальных клапанов.
В API `network.edges` объединяет ветви. Отчёт сети разделяет `pipes` и `valves`.
Сериализация, изменение открытий и граничного давления сохраняют оба типа ветвей.
Сеть может состоять только из локальных клапанов, если соблюдены требования дерева.

## Конфигурация

В `homogeneous_blackoil_tree` добавлен необязательный список `valves`:

```json
{
  "name": "collector_trim",
  "start": "header",
  "end": "trim_out",
  "diameter_m": 0.04,
  "loss_coefficient": 15,
  "valve_opening": 0.8,
  "vapor_pressure_pa": 3000,
  "pressure_recovery_factor": 0.8
}
```

K, диаметр и давление пара положительны; 0 < opening <= 1, 0 < F_L <= 1.
Нулевое открытие отклоняется до реализации статического удержания фаз.
Порты локального клапана должны иметь одинаковые отметки.
Управление через `valve_openings` / `pressure_control` и команды расписания
`gathering_valve_openings` / `gathering_target_pressure_pa` общие с распределёнными
сопротивлениями. Конфликт ручной команды и регулятора отклоняется.

## Воспроизведение

```bash
python scripts/run_fim_blackoil_surface.py configs/fim_blackoil_surface_local_valve.json --initial-rs 25 --days 5 --outlet-mpa 1.2 1.4 1.6 --device cpu --output /tmp/local_cpu.json
python scripts/run_fim_blackoil_surface.py configs/fim_blackoil_surface_local_valve.json --initial-rs 25 --days 5 --outlet-mpa 1.2 1.4 1.6 --device cuda --network-backend torch_device --output /tmp/local_cuda.json
python scripts/run_surface_schedule.py configs/surface_gathering_local_valve.json configs/surface_gathering_local_valve_schedule.json --gathering --output /tmp/local_plant.json
```

`--initial-rs` — явная начальная концентрация растворённого газа (м³/м³)
в диагностическом runner. Требует нулевой начальной газонасыщенности и не должна
превышать насыщенный Rs при начальном давлении. Это использует существующее
состояние `Fluid.rs`, а не изменяет PVT. Без этого параметра прежняя инициализация
runner сохранена. Сам JSON-пример предполагает запуск указанной командой.

В локальном примере более строгие CNV=1e-9 и MB=1e-10 заданы только в конфиге;
общие допуски решателя не изменялись. Пласт и Шур могут работать на CUDA,
локальная PVT/AD-модель следует `network_backend`; дерево и регулятор
по-прежнему координируются CPU.

## Проверка и область результата

Артефакты: `results/blackoil_local_valve_20261031/`.
Общий быстрый набор: 467 passed, 97 skipped, 12 slow deselected.
Профильный CPU-набор: 13 passed, 4 CUDA skipped; набор с CUDA: 22 passed
(включает CPU-проверки FIM, это не 22 независимых GPU-сценария).

Проверены аналитический водяной предел, прямое/обратное восстановление давления,
производные по компонентам, давлению и открытию, полные межскважинные блоки FIM,
регулятор, фазовый flash только внутри сжатого сечения, нарушение запаса давления
пара, контроль изменения плотности и откат состояния.

В пятисуточных случаях используются три ячейки, две скважины и давления
приёмника 1.2/1.4/1.6 МПа. Это контрольный пример, а не промысловая калибровка.
Дополнительно при 0.8 и 1.0 МПа зафиксирован выход пробного состояния Ньютона
из жидкостной области. Отказ сам по себе не доказывает фазовое состояние
окончательного стационарного решения; эти режимы текущей моделью не завершены.
Результаты отказов сохранены в `domain_rejections.json`, без ослабления проверок.

Остаются газожидкостный локальный штуцер с критическим истечением,
многофазный насос, расширение термодинамики и температурного расчёта,
динамика привода/аппаратов, распределённый ствол и статическое удержание фаз.

В допустимых пятисуточных режимах максимальная разница CPU/CUDA по давлению
1.607e-8 Па, водонасыщенности 2.23e-16; CUDA-графы сохранены.
Максимальная абсолютная ошибка баланса компонента 0.000841 кг,
относительно отобранной массы компонента — 2.155e-7.
При стандартных допусках исходного примера (CNV=1e-7, MB=1e-8) максимальная
ошибка составляла 0.023818 кг. Ужесточение допусков в локальном примере
не увеличило число итераций Ньютона в этих случаях; это не утверждение
о неизменной стоимости линейных решений или ускорении других моделей.
Оба варианта сохранены (`standard_tolerance_*.json` и `five_day_*.json`).

Площадка с локальным клапаном, сменой уставки и остановкой/запуском
точно воспроизвела checkpoint и накопления после JSON-продолжения.
Итоговая сводка и SHA256 исходников/конфигов находятся в `validation.json`,
команды воспроизведения — в `reproduce.sh`.

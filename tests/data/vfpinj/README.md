# VFPINJ: условия сравнения

Deck `VFPINJ_WCONINJE-01.DATA` задаёт `TUNING 1.0 1.0`: начальный и максимальный шаг — 1 сутки.
Симулятор применяет эти временные настройки по умолчанию.

Локальный журнал OPM для имеющегося эталона сообщает, что TUNING игнорируется из-за
`--enable-tuning=false`. Фактические шаги эталона: 1, 3, 5, 10, 5, 5 суток;
отчётные даты — 0, 9, 19, 29 суток. SHA-256 его UNSMRY совпадает с файлом в этом каталоге:
`d92024797345ab470f096ef68b4d8e9223c4782fe6787b4e16a9191d62b98b32`.

Диагностика 29 октября 2026 с неизменёнными строгими CNV/MB:

- При соблюдении TUNING средняя нормированная ошибка `WWIR:INJ2` — 1.280%.
- При повторении фактических шагов эталона — 0.263%; остальные проверенные векторы имеют
  ошибку менее 0.087%. Это диагностический расчёт, не смена настроек по умолчанию.
- При одинаковых давлениях и насыщенностях из UNRST отклонение предсказанных расходов
  отдельных водонагнетательных перфораций от XCON не превышает 0.082% на 19-е и 29-е сутки.
- Поровые объёмы и обычные проводимости возле INJ2 совпадают с INIT в пределах округления
  (для проводимостей проверен относительный порог 0.1%).

Дополнительный независимый расчёт OPM Flow 2026.04 с `--enable-tuning=true` сохранён в
`opm_tuning/`: SMSPEC, UNSMRY, полный PRT и manifest.json с командой и SHA-256 входов/выходов.
При сравнении с ним ошибка `WWIR:INJ2` — 0.124%, максимальная по векторам — 0.400% (`WGIR:INJ1`).
Эталонный тест использует этот расчёт и прежние допуски; исходный эталон `opm/` сохранён.
Повторный запуск: смонтировать этот каталог в `/case` и пустой выходной каталог в `/out`,
затем выполнить команду из manifest.json в указанном образе OPM, без доступа к GPU.
Совпадение векторов при конечном шаге не заменяет исследование сходимости по времени.
